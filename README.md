# Sheet Studio

**[Windows·Mac 다운로드](https://github.com/beaur8-prog/sheet-studio/releases/latest)** · [설치·사용자 가이드](docs/USER-GUIDE.md) · [버전별 수정 내역](docs/CHANGELOG.md)

현재 공개 버전은 **0.7.29**이며 Windows x64 설치 파일과 Mac Apple Silicon ZIP을 제공합니다. **개발 버전 0.7.35는 아직 배포하지 않았습니다.** 파일 선택창 대기 표시·중복 열기 방지와 Mac 폴더 위치 기록 처리를 보강했습니다. [파일 열기 수정](docs/releases/v0.7.35.md)을 확인하세요. 일반 실행은 빈 통합 문서로 시작하며 이전 작업은 **파일 → 이전 문서 복구**로 불러옵니다. [시작 동작 변경](docs/releases/v0.7.34.md)을 확인하세요. 도움말의 업데이트 메뉴·수동 방식 선택·실시간 진행 창을 추가했습니다. [업데이트 사용법과 검증](docs/releases/v0.7.33.md)을 확인하세요. 실행 중인 앱의 버전 표시와 오래된 화면 빌드 재사용 방지를 추가했습니다. [버전 표시 수정](docs/releases/v0.7.32.md)을 확인하세요. 동적 배열과 스필·XLSX 메타데이터, 외부 통합 문서 연결 보존, 피벗 계산, 페이지 설정·머리글/바닥글·시트 위치 인쇄를 보강했습니다. [개선 내용과 남은 제한](docs/releases/v0.7.31.md), [추가 계획과 검증](docs/CORE-FIVE-HOUR-20261031.md)을 확인하세요. Linux는 소스 빌드를 지원하며 현재 공개 0.7.29에는 DEB가 없습니다.

문서 전체 100만 셀을 지원하며 선택 편집·붙여넣기·채우기는 한 번에 10만 셀까지입니다. 큰 문서의 첫 전달과 XLSX 열기·저장에는 시간이 걸릴 수 있습니다. [대용량 문서의 범위와 사용법](docs/CAPACITY.md)을 확인하세요.

설치된 Microsoft Excel의 네이티브 실행 파일과 한국어 UI를 분석하고, 익숙한 작업 흐름을 독립적으로 구현한 Windows·macOS 스프레드시트 앱입니다. Microsoft Excel의 원본 코드 복원이나 전체 기능의 동일성을 주장하지 않습니다.

## 앱 업데이트

개발 버전 0.7.33부터 앱의 **도움말 리본**과 운영체제 **도움말 메뉴**에 **업데이트 확인**, **수동 업데이트**, **업데이트 진행 상황**을 제공합니다. 현재 버전·새 버전·마지막 확인 시간과 확인 → 다운로드(퍼센트·받은 용량) → 무결성 검사 → 설치 준비 단계를 볼 수 있습니다. 창을 닫아도 다운로드는 계속되고 하단 상태 표시줄에서 다시 열 수 있습니다.

**수동으로만 확인**을 선택하면 자동 확인·다운로드를 끕니다. 직접 **업데이트 확인 → 새 버전 다운로드 → 설치 화면 열기** 순서로 진행할 수 있고, **설치 파일 직접 받기**는 공개 릴리스 페이지를 엽니다. 확인 버튼만으로 파일을 다운로드하거나 앱을 종료하지 않습니다. 설정은 재실행 후에도 유지됩니다.

자동 방식을 선택한 설치 앱은 실행 15초 뒤와 이후 6시간마다 정식 릴리스를 확인하며, 기기별 파일의 크기·SHA-256을 검증합니다. Windows는 문서 복구 저장·정상 종료 후 **설치 화면과 진행률**을 표시하고, 설치를 마치면 앱을 다시 실행합니다. 종료가 취소되면 설치하지 않습니다. Mac은 ZIP을 풀어 기존 앱을 직접 교체하며, Linux는 공개 설치 파일을 직접 받습니다. 개발 실행·브라우저에서는 자동 업데이트를 지원하지 않습니다.

공개 0.7.29은 이전 네이티브 메뉴 방식의 업데이트 기능을 포함합니다. 새 업데이트 창은 0.7.33 개발본에 있으며 별도 배포 전에는 공개 설치 파일에 포함되지 않습니다. `npm run test:updates`와 `node tests/ui-updates.mjs`로 로직·화면을 검사할 수 있습니다.

## 실행

Windows·macOS·Linux와 Node.js 22.12 이상이 필요합니다.

```powershell
git clone https://github.com/beaur8-prog/sheet-studio.git
cd sheet-studio
npm ci
npm run runtime:install
npm run desktop
```

Windows 실행 파일은 `npm run package:win`으로 만듭니다. 결과는 `release/<version>/win-x64/Sheet-Studio-<version>-Windows-x64-Setup.exe`입니다. `npm run package:dir`은 같은 폴더 아래 `win-unpacked/`을 생성하며 이 폴더 전체가 필요합니다.

**Mac 빌드:** Mac에서 `SHEET_STUDIO_ADHOC=1 npm run package:mac -- --arch=arm64`(Apple Silicon)를 사용합니다. DMG/ZIP 경로, 기본 메뉴, 서명 및 GitHub Actions 사용법은 [macOS 빌드 안내](docs/MACOS.md)를 참조하세요. macOS arm64의 실제 실행과 시트 수명주기 회귀 테스트를 확인했습니다. 빌드 결과와 설치된 의존성은 Git 저장소에 포함하지 않습니다.

로컬 브라우저에서는 `npm run dev` 후 `http://127.0.0.1:5192`로 접속하세요.

앱은 오프라인에서 동작합니다. 작업 내용은 기기에 자동 저장됩니다. **파일 → XLSX 저장**으로 다른 앱에서 열 수 있는 파일을 만들고, **앱 문서 저장 (.sheet.json)**으로 앱의 차트·메모를 포함한 편집 상태를 보존할 수 있습니다.

**도움말 → 예제 통합 문서**에서 수식과 서식을 적용한 예제를 열 수 있습니다. 예제의 데이터는 이 작업에서 만든 가상 데이터입니다.

## 기존 VBA 매크로 사용

**Windows 데스크톱 Microsoft Excel이 설치되어 있어야 합니다.** XLSM을 연 다음 **개발 도구 → Excel에서 매크로 실행 → Excel 연결**을 누르세요. 열린 Excel 작업 사본에서 매크로를 실행하거나 앱에서 `Module1.MacroName`을 입력합니다. **결과 가져오기**로 셀 변경을 반영하고 **XLSM 저장**으로 저장합니다.

실행에는 Excel의 보안 정책이 그대로 적용됩니다. 차단된 매크로는 실행되지 않으며 앱은 Trust Center 설정이나 VBA 프로젝트 접근 권한을 변경하지 않습니다. 작업 사본의 폴더는 원본과 달라서 상대 경로를 쓰는 매크로에는 조정이 필요할 수 있습니다. 지원 범위와 검증 한계는 [VBA 안내](docs/VBA.md)를 참조하세요.

계산 엔진은 JavaScript `eval`을 사용하지 않습니다. 산술, 비교, 문자열, 절대·상대 참조, 범위, 오류 전파, 순환 참조 감지와 다음 함수 등을 지원합니다.

**380개 함수 이름**(이전 버전 별칭 30개 포함)을 지원합니다. `LET`, `SUMIFS/COUNTIFS/AVERAGEIFS`, `INDEX/MATCH/XMATCH`, `INDIRECT/OFFSET`, `PMT/IRR/XIRR`, `STDEV/VAR`와 확률 분포, 공학·텍스트·날짜 함수가 포함됩니다. **수식 → 함수 삽입**에서 이름·한국어 설명·범주로 검색하고 구문과 예시를 확인하세요. 수식 입력 중에는 ↑↓로 함수를 선택하고 Tab으로 완성하며, 현재 인수 안내가 표시됩니다. [전체 함수 목록과 호환 범위](docs/FUNCTIONS.md)를 참조하세요.

## 범위와 차이

독립 VBA 런타임, Power Query 편집기, 공동 편집, 외부 연결 새로 고침, Excel 전체 함수 및 모든 계산 규칙은 구현하지 않았습니다. VBA는 설치된 Excel에서 실행합니다. 큰 문서의 호환성이나 Excel과의 모든 경계 조건 일치는 보장하지 않습니다. 기록된 셀과 일반 수식 범위는 최대 1,000,000셀, 선택 편집·붙여넣기·채우기를 한 번에 최대 100,000셀로 제한합니다. XLSM 원본과 실행 결과는 각각 최대 15 MB이며 Excel 연결의 셀 변경 계획은 200,000개 이하입니다. [기능별 제한](docs/CAPACITY.md)을 참조하세요.

차트 테두리의 조절점을 끌면 크기가 바뀝니다. 조절점에 키보드 포커스를 두고 방향키로 10px, Shift+방향키로 1px씩 조절할 수 있습니다. Esc로 드래그를 취소합니다.

차트는 자료의 형태로 계열 방향과 머리글을 추론하며 숫자로 된 첫 행/열을 임의로 제외하지 않습니다. 설정에서 방향과 제목/항목 선택을 바꿀 수 있습니다. 분산형은 첫 열이 X값이며 거품형은 X·Y·크기 열이 필요합니다. 새 차트는 XLSX·JSON에 저장됩니다. 기존 차트는 원본 XML과 연결 파트를 보존하며, 3D는 2D 미리 보기, 주식형·표면형·최신 ChartEx 유형은 원본 보존 안내로 표시합니다. 원본 차트의 전체 Excel 렌더링이나 모든 외부 연결을 지원하지는 않습니다. 조건부 서식은 지원하는 비교·텍스트·중복·상위/평균·수식 규칙을 다시 계산하며 XLSX/XLSM에 저장합니다. 색조·데이터 막대·아이콘 집합은 원래 XML을 보존하지만 동일한 미리 보기/편집은 제공하지 않습니다. 머리글 선택은 사용 영역을 기준으로 한 제한된 범위를 선택합니다. 자동 필터는 선택 범위 또는 현재 데이터 영역의 첫 행을 머리글로 사용합니다. 복사/채우기, 정렬, 잘라내기 및 인쇄의 모든 Excel 세부 동작을 재현하지는 않습니다.

지원하지 않는 XLSX 개체·서식은 다시 저장할 때 유지되지 않을 수 있습니다. 자세한 파일 형식 지원 범위는 [IO-NOTES.md](IO-NOTES.md)를 참조하세요.

## 분석과 검증

- [분석 요약](docs/ANALYSIS.md): 네이티브 분석과 화면 관찰의 범위 및 구현과의 구분
- [검증 기록](VALIDATION.md): 테스트 실행과 실행 파일 확인
- `node tests/ui-cell-editing.mjs --packaged`: 화면 갱신 중 더블클릭, 셀 안 커서·서식·입력·취소·병합·확대 상태 검사
- `node tests/ui-dimensions.mjs --packaged`: 열·행 경계 드래그, 안내선, 실행 취소, 자동 맞춤과 확대/고정 상태 검사
- `node tests/ui-worksheet.mjs --packaged`: 틀 고정·붙여넣기·범위 입력·숨기기·조건부 서식 UI 검사
- `node scripts/worksheet-native-smoke.mjs`: 설치된 Excel과 새 워크시트 기능 및 XLSM 저장 비교
- `node tests/ui-functions.mjs --packaged`: 함수 검색·범주·삽입·자동 완성·인수 안내·수식 저장 검사
- `node scripts/functions-native-smoke.mjs`: 설치된 Windows Excel과 계산 결과 및 XLSX 실제 열기 대조
- `npm test`: 계산, 파일 왕복, 차트 유형·참조·원본 보존·크기 및 플랫폼 설정 테스트
- `node tests/ui-excel-charts.mjs --packaged`: 10종 차트의 생성·설정·XLSX 저장/열기·변환 검사
- `node scripts/chart-native-smoke.mjs`: 설치된 Windows Excel에서 18개 새 차트 조합과 기존 차트 왕복 검사
- `node tests/ui-charts.mjs --desktop`: 실제 Electron에서 차트 조절·저장·복원 검사 (`--packaged`로 배포 앱 검사)
- `node tests/ui-smoke.mjs`: 로컬 개발 서버에 대한 실제 브라우저 상호작용 테스트 (설치된 Microsoft Edge 사용)

원본 Microsoft 실행 파일, 리소스, 아이콘 또는 디컴파일 코드는 앱과 이 저장소에 포함하지 않았습니다. 상세 원본 분석 산출물은 로컬에 보관하며 공개 저장소에는 독립 앱 코드와 분석 요약만 포함합니다.

수학·통계·공학 함수의 일부는 MIT 라이선스의 [Formula.js](https://github.com/formulajs/formulajs) 4.6.1을 사용하며, 셀 참조·공백·오류·날짜·조건 집계는 앱의 호환 계층에서 처리합니다. 배포 앱에 [오픈 소스 고지](public/THIRD-PARTY-NOTICES.txt)를 포함합니다.

Linux x64 DEB는 Linux에서 `npm run package:linux`로 빌드합니다. 설치·실행 방법은 [사용자 가이드](docs/USER-GUIDE.md)를 참고하세요.
