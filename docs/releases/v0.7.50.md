# Sheet Studio 0.7.50 · 터치패드 핀치 / Ctrl+휠

개발 수정이며 공개 배포가 아니다. 리토스와 기존 공유 링크는 변경하지 않는다.

## 사용 방법

- Windows·macOS·Linux·Android 공통 화면에서 터치패드의 두 손가락을 벌리면 확대, 모으면 축소한다. **Ctrl+마우스 휠 위/아래**도 같은 시트 배율을 바꾼다. 마우스만 움직이거나 일반 휠/두 손가락 스크롤을 쓰면 기존 스크롤 동작을 유지한다.
- 기존 배율 범위 **50~180%**를 사용하며 1% 단위로 표시한다. 상태 표시줄의 배율과 맞추고, 배율 숫자/100% 복원 메뉴로 초기화한다. 읽기 전용·Android 전체화면 뷰어·태블릿 편집·차트 전용 시트도 지원한다.
- 포인터가 가리키는 내용을 기준으로 확대한다. 포인터가 앱 메뉴 위에 있으면 시트 중앙을 기준으로 한다. 선택 셀이 화면 밖에 있어도 그 셀로 갑자기 돌아가지 않는다. 문서 끝·틀 고정으로 이동할 수 없는 경우는 스크롤 범위 안에 맞춘다.
- 시트 배율은 보기 상태다. 셀 값·수식·차트의 저장 크기·틀 고정 정의·선택·실행 취소·dirty를 바꾸지 않는다. 편집 입력·커서·초점은 유지하며 한글 조합 중에는 확대를 적용하지 않는다. 대화상자/메뉴, 드래그 또는 파일 작업 중에도 확대를 보류한다.

## 구현과 검증 범위

Chromium은 터치패드 핀치를 Ctrl이 눌린 wheel 이벤트로도 전달한다([MDN wheel](https://developer.mozilla.org/en-US/docs/Web/API/Element/wheel_event)). 비수동 이벤트 리스너로 브라우저 페이지 확대를 취소하고 시트 배율만 바꾼다. WebKit의 누적 `GestureEvent.scale`도 별도 경로로 받는다([MDN GestureEvent](https://developer.mozilla.org/en-US/docs/Web/API/GestureEvent)). 두 경로를 중복 적용하지 않는다.

빠른 입력을 프레임당 한 번으로 합치고 작은 핀치 변화도 누적한다. 큰 휠 단계는 한 번에 10% 변화로 제한하고, 작은 핀치는 본래 감도로 처리한다. 연속 입력 동안 처음 가리킨 논리 셀 좌표를 유지하여 정수 스크롤 반올림으로 기준점이 밀리지 않게 한다. 일반 스크롤 후 다시 확대할 때는 현재 화면에서 기준점을 새로 잡는다. 배율 변경 때 저장된 행·열 축 좌표를 비례 조정해 백만 행의 숨김/필터/크기를 다시 조사하지 않는다. 새 문서/시트, 직접 배율 조절, 포인터 드래그 시작, 창 초점 상실·페이지 비활성화·창 크기 변경은 이전에 대기하던 확대를 취소한다.

Android WebView에서는 네이티브 Ctrl+`ACTION_SCROLL`을 정규화해 `sheet-studio-android-wheel`로 전달한다. Android 14(API 34) 이상의 `CLASSIFICATION_PINCH` 터치패드는 별도로 받아, `AXIS_GESTURE_PINCH_SCALE_FACTOR`의 현재·배치 이력 값을 모두 곱한 누적 배율을 공통 제스처 처리로 보낸다([Android MotionEvent 명세](https://developer.android.com/reference/android/view/MotionEvent#AXIS_GESTURE_PINCH_SCALE_FACTOR)). 이 연결은 Sheet Android 호스트에서만 동작하며, 일반 스크롤·터치스크린과 Word/Slide 호스트 입력은 기존 경로를 사용한다. Android 설치본은 웹 자산과 새 호스트를 함께 갱신해야 한다.

- 단위 검사 556개 중 **555 통과**, Windows 전용 1개 제외. 확대 수학·숨김/가변 크기·동결 경계·범위·프레임 병합·작은 변화 누적·문맥 취소·WebKit 누적 배율을 포함한다.
- `tests/zoom-gestures.mjs` 11개 시나리오 그룹 통과: Mac/Windows/Linux UA의 공통 런타임, 실제 Chromium 핀치 입력, Ctrl+휠/일반 휠 구분, 포인터 기준점·틀 고정·차트 시트·백만 번째 행, 입력 초안/커서/조합, Android 휴대폰·태블릿의 읽기 전용/뷰어.
- `tests/ui-zoom-gestures.mjs`: 격리한 실제 macOS Electron 소스 실행과 최종 0.7.50 패키지에서 신뢰된 Ctrl+휠·터치패드 핀치 입력 통과. `webContents` 배율과 `visualViewport.scale`은 1, 리본 높이와 원본/선택/이력은 동일했다. Apple Silicon 로컬 앱은 ad-hoc 서명 검증까지 통과했다.
- 기존 `tests/viewer-modes.mjs` 8개 모드·입력·마우스 시나리오 그룹 통과.
- 기존 실제 Electron `tests/ui-virtual-scroll.mjs`: 50/180% 백만 번째 행, 차트 위치·범위 선택·편집/실행 취소·방향키·틀 고정·일반 휠 이동 거리 통과.
- Android API 35 에뮬레이터의 실제 설치본: **10개 네이티브 검사 전부 통과**(204.327초). 네이티브 Ctrl+휠 위/아래, 분류된 터치패드 핀치의 시작·변화·종료와 배치 이력의 `1.02×1.03×1.1` 배율을 확인했다. 페이지 배율은 1이고 원본·선택·실행 취소·dirty·읽기 전용 권한을 유지한다. 기존 IME·전체화면·Esc/Back·복구·숫자 표시·마우스 크기 조절·평균·인쇄 검사도 통과했다. [최종 CI](https://github.com/beaur8-prog/office-studio/actions/runs/42791651239), [네이티브 검증 기록](https://github.com/beaur8-prog/office-studio/blob/codex/android-sheet-gesture-zoom-20261110/android/qa/results/sheet-gesture-zoom-20261110.md).

검증한 렌더러 소스는 `4c113931f7b404e1b6147720096f9b50fdcfb255`, Android 호스트는 `f8ff0be164810379c4acc5fde65b1d5d9bdf1411`이다. 초기 Android 설치본에서는 공통 DOM Ctrl+휠만으로 배율이 바뀌지 않는 것을 재현하여 호스트 전달 경로를 추가했다. 최종 시험 APK는 별도 패키지 `io.officestudio.sheet.qa`, **1.0.9-qa / code 10**, SHA-256 `ac1ea6d3e2b02e39dfedbaaeffa470d7b4d5a22b50c079f1ea69aac62d690f2c`다. 시험용 debug 서명이며 기존 공개 설치본을 교체하지 않는다. 로컬 Mac 앱은 **0.7.50**이며 화면이 잠겨 사용자용 실행은 보류했다. 검증은 격리된 프로필에서 수행하여 사용자 파일·복구 자료·클립보드를 보존했다.

Windows/Linux는 이 환경의 Chromium에서 해당 UA와 공통 코드 경로를 검증했으며 해당 OS 설치본의 실물 실행은 별도다. 물리 터치패드·마우스는 연결하지 않고 Chromium의 신뢰된 입력과 실제 앱 이벤트로 검증한다. 플랫폼/드라이버가 앱에 전달하는 확대 이벤트를 사용한다.
