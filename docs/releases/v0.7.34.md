# 0.7.34 · 빈 문서로 시작

개발 버전이며 GitHub 공개 릴리스와 리토스 공유본은 별도 배포 요청 전까지 갱신하지 않는다.

앱을 일반 실행하면 이전 문서를 자동 표시하지 않고 새 빈 **통합 문서1**로 시작한다. 파일을 더블클릭하거나 파일 경로와 함께 실행하면 해당 파일을 여는 동작은 유지한다. 이전 작업은 **파일 → 이전 문서 복구 → 복구**에서 명시적으로 불러올 수 있다. 복구한 문서의 저장 폴더 연결을 유지한다.

시작할 때는 이전 문서의 셀 전체를 읽지 않고 복구 메타데이터만 확인한다. 빈 화면을 편집하지 않고 닫거나 다시 열어도 이전 복구 자료를 덮어쓰지 않는다. 새 편집을 저장할 때 현재 문서와 직전 작업의 저장 세대를 보관하고, 더 오래된 세대는 정리한다. 같은 실행 중의 새로 고침은 현재 편집을 유지한다. 복구 자료는 무제한 이력이나 파일 백업을 대신하지 않는다.

Mac 소스에서 10만 셀 이전 문서의 반복 빈 시작/종료, 원본 복구 자료 유지, 새 편집 이후 수동 복구·실행 취소, 현재/직전 두 세대의 정리를 검증했다. 레거시 복구 자료 이전, 즉시 새로 고침·종료 후 명시적 복구, 파일 연결 실행, 문서 폴더 유지, 업데이트 설정 보존도 확인했다. 단위 검사 417개 중 416개 통과·Windows 전용 1개 제외·실패 0개, 업데이트 엔진 24개가 통과했다. 완성 패키지와 세 OS 결과는 아래에 기록했다.

재현: `node tests/ui-startup.mjs`, `node tests/ui-recovery.mjs`, `node tests/ui-file-associations.mjs`, `node tests/ui-file-dialogs.mjs`. 완성 패키지에는 `--packaged`를 붙인다. GitHub Actions `Worksheet editing regression`의 `scope=startup`은 시작·복구·파일 연결·폴더·업데이트·사용자 편집 시나리오를 검사한다. 테스트는 격리 프로필을 사용하며 실제 사용자 문서·OS 클립보드를 테스트 데이터로 사용하지 않는다.

## 최종 Mac 앱 검증

Mac arm64 완성 패키지에서 시작·복구·파일 연결·파일 대화상자·기본 편집 검사를 통과했다. 기존 앱과 전체 사용자 프로필을 백업한 뒤 0.7.34로 교체·실행했으며, 실제 사용자 프로필이 있는 상태에서도 한 시트의 빈 통합 문서로 시작하고 파일 메뉴에 이전 문서 복구가 표시되는 것을 확인했다. 실제 사용자 문서를 수동 복구 테스트에 사용하지 않았다.

실제 100만 셀의 편집·정렬·필터·즉시 종료 후 빈 시작→명시적 복구, XLSX 저장·재열기까지 확인했다. 별도로 SEQUENCE의 100만 파생 결과도 빈 시작 후 복구했고 원본 기록은 한 셀로 유지됐다. 10만 셀 보존 검사에서는 빈 실행·닫기·새로 고침 시 저장된 복구 자료가 동일하고, 새 편집 이후에도 이전 세대가 유지되며, 다음 세션으로 넘어가면 더 오래된 세대의 셀 조각이 정리되는 것을 확인했다.

검증·설치한 Mac arm64 ASAR SHA-256: `933828ba17870a323ef3b8fea5aee7b8dc17feb81da40b075d34ab59be9b61f0`.
