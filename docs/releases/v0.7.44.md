# Sheet Studio 0.7.44 · Android 편집과 전체화면 뷰어

개발 변경이며 공개 APK·GitHub 릴리스·리토스 페이지는 갱신하지 않았다. 여기서 데스크톱 편집은 Android 태블릿·DeX의 넓은 화면만 뜻한다. Windows/macOS/Linux의 기존 화면은 유지한다.

## 사용 흐름

- 편집 화면 위의 눈 아이콘을 누르면 전체화면 뷰어로 전환한다. 제목·입력줄·도구·하단 메뉴 행을 모두 숨겨 격자가 화면 전체를 사용한다.
- 뷰어 위의 연필 아이콘이나 외부 키보드 Esc로 편집에 돌아간다. 오버레이 메뉴는 2.8초 후 숨겨지며 화면 탭·포인터 이동·키 입력으로 다시 나타난다. 메뉴에서는 파일 열기·찾기·시트 이동·확대·주소 이동·차트·공유를 사용할 수 있다.
- Android Back은 열린 패널부터 닫으며, 뷰어에서는 편집으로 돌아간다. 편집에서의 종료 확인·초안/복구 저장·취소 보호는 유지한다. XLSM은 읽기 전용이다.
- 스마트폰 편집은 범위 선택·합계·평균·함수·굵게·정렬·색·테두리를 큰 버튼으로 제공한다. 셀 단일 탭 입력, Enter 다음 셀 이동 중 키보드 유지와 셀 초안 미리보기를 유지한다.
- 840×600 CSS px 이상의 Android 창에서는 마우스/외부 키보드가 있으면 리본·수식줄·시트 탭·상태줄을 사용한다. 더보기 → 편집 화면에서 자동/터치/데스크톱을 지정할 수 있다. 분할 창이나 휴대폰 가로처럼 작은 화면은 터치 편집으로 돌아간다.
- 입력 중 모드 전환은 초안 확인/취소를 먼저 묻고, 한글 조합 중에는 전환하지 않는다. 읽기와 모드 전환이 확정 값·dirty·실행 취소를 바꾸지 않도록 기존 명령·문서 보호를 사용한다.

## 네이티브 패키지

[Sheet 전용 Android 호스트 브랜치](https://github.com/beaur8-prog/office-studio/tree/codex/android-sheet-viewer-20261108)도 함께 필요하다. Sheet에서만 하드웨어 Esc가 앱 종료로 전달되지 않게 처리하고, 키보드 연결/분리 정보를 웹에 보낸다. 시험 빌드는 Android 1.0.3-qa, 별도 ID `io.officestudio.sheet.qa`이며 정식 설치본의 업데이트가 아니다. Word/Slide 배포 파일은 교체하지 않는다.

## 검사와 제한

- 전체 단위 검사 537개 중 536개 통과, 실패 0개, Windows 전용 1개는 macOS에서 제외.
- Android 모드 UI 4개 시나리오군 통과: 다른 플랫폼 분리, 전체 격자·아이콘·Esc, 조합/초안·확인창·읽기 이력 보호, Android 넓은/분할 창과 첫 숫자·한글 입력, 터치/데스크톱 선택 및 재실행 후 유지.
- 기존 Android UI 15개 시나리오군 통과. 10만 셀 문서 보기, 연속 Enter·실제 입력창 포커스, 복구·저장 취소/실패, 파일 열기 실패 보호도 재검증했다. Chrome 자동화의 수치는 실제 폰 성능 측정이 아니다.
- Electron 실행/버전 0.7.44와 기존 데스크톱 편집 회귀 검사 통과. 모든 시험은 별도 프로필과 시험 클립보드를 사용했다.
- 초안 확인창을 닫은 뒤 입력란으로 포커스가 복원되어 취소된 편집이 다시 시작되던 Android 결함을 재현·수정하고 같은 시나리오로 확인했다.
- [실제 Android 에뮬레이터 CI](https://github.com/beaur8-prog/office-studio/actions/runs/42452508762)에서 **4개 모두 통과**, 실패 0개, 100.451초. API 35 Pixel 6, tall cutout, 격리 `.qa` 패키지를 사용했다.
- 네이티브 부모/WebView의 창 전체 사용과 세로·가로 전환, 실제 터치·IME 표시 후 Enter의 키보드 유지, 셀 초안 표시·취소, 종료 취소·Activity 종료·문서 복구를 재검증했다.
- 뷰어 격자의 top=0·height=innerHeight, 실제 KEYCODE_ESCAPE의 편집 복귀 및 재입력 시 Activity 미종료, 문서/이력/dirty 불변을 확인했다.
- 첫 실행 CI는 OS 전체화면 안내창의 느린 포커스 반환으로 입력 검사 준비에서 실패했다. 대기 중 안내창을 계속 확인하도록 시험 코드만 보강한 뒤 위 최종 실행에서 같은 네 가지 검사를 통과했다.
- 실제 검증된 렌더러 코드 커밋은 `65cd5a51396eeb560c19e34e6ff4c207e9a02661`, 네이티브/계측 커밋은 `07e1b0207d492baffaabafc64317a1fc68f365e9`다. 이후 결과 기록과 추가 브라우저 검사 커밋은 APK 제품 코드 변경이 아니다.

 물리 제조사 폰·태블릿·DeX 및 다른 한글 입력기 검증은 별도다. 브라우저 자동화의 화면 크기/입력장치 모의 결과를 실기기 검사로 표시하지 않는다.
