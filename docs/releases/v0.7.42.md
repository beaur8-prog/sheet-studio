# 0.7.42 — Android 전체화면의 실제 작업 영역 확장

날짜: 2026-11-08. 개발 버전이며 공개 배포는 별도 요청 시 진행한다. Android에서만 적용한다.

## 재현과 원인

0.7.41 빌드에서 호스트가 위 40px·아래 44px의 시스템줄 여백을 전달한 뒤 웹 Fullscreen API에 진입해도 앱 전체 padding이 남았다. 412×842 창의 상단 메뉴는 y=40에서 시작하고 하단 메뉴는 y=798에서 끝났으며, 격자 높이는 563px였다. 상태줄 숨김과 작업 영역 확장이 연결되지 않은 문제다. 사용자 첨부 화면의 실행 환경은 아직 확인하지 않았으므로 그 화면의 모든 외부 띠가 이 원인이라고 단정하지 않는다.

## 수정

- 앱을 실제 가시 viewport의 위·아래 끝까지 채운다. 앱 전체의 안전 영역 padding을 제거하고 필요한 여백은 조작부에만 적용한다.
- 전체화면에서는 숨긴 시스템줄의 여백을 제거한다. 위 40px+아래 44px를 전달한 같은 조건에서 격자가 **84px 늘어나 647px**가 된다. 상단 메뉴 y=0, 하단 메뉴 끝 y=842를 확인한다.
- 카메라 cutout은 시스템줄과 구분해 유지한다. 가로 회전 시 좌우 cutout이 셀을 덮지 않도록 한다. WebView가 이미 처리한 여백을 다시 적용하지 않는다.
- 전체화면·복원과 실제 화면 크기 변경을 연결한다. 키보드가 브라우저를 위로 민 경우 가시 영역의 위치·크기를 함께 따라가며, pinch zoom 시 문서를 다시 축소 배치하지 않는다.
- 네이티브 호스트 요청은 위 상태줄과 아래 탐색줄을 함께 숨기고 edge-to-edge 창을 사용하도록 보강한다. IME는 유지한다. APK 호스트 연결 계약과 예시는 [구현 기록](../ANDROID-UI-IMPLEMENTATION.md)에 있다.

## 검증

- 프로덕션 빌드 성공. 버전 manifest와 실제 Electron 창 제목 모두 0.7.42.
- 전체 단위 검사 534개: 533개 통과, 실패 0개, Windows 전용 1개는 macOS에서 제외.
- Android Chrome UI 모의 검사 14개 시나리오군 통과. 위아래 84px 회수, 실제 메뉴·격자 위치, 늦게 온 옛 inset 메시지, cutout 유지, 이미 소비한 inset, 누락된 변 초기화를 확인했다.
- 네이티브 호스트의 동기 inset 응답도 초기화 중 놓치지 않도록 검사했다. 상태줄·탐색줄 숨김과 edge-to-edge 요청은 시험용 호스트로 확인했다.
- 키보드가 높이를 300px로 줄이고 가시 viewport 시작을 y=120으로 이동시킨 조건에서 앱과 입력줄이 y=120..420에 놓이며 입력 포커스를 유지했다. 세로/가로 회전, Enter 연속 입력, 한글 조합, 합계/평균과 원본 보호 검사도 통과했다.
- 10만 셀 열기·잘못된 파일 열기 보호, 좁은 Windows/iPad의 Android UI 미적용을 재확인했다. 실제 Electron 실행 검사도 통과했다.

격리된 프로필·복구 저장소·시험용 클립보드를 사용했다. 사용자 문서와 OS 클립보드는 변경하지 않았다.

Chrome 검사는 Android User-Agent·터치·viewport와 호스트 inset 메시지를 모의한다. 실제 Android 폰에서 OS 창·카메라·탐색 방식과 전체화면이 어떻게 연결되는지는 확인하지 않았다. 현재 저장소에 네이티브 APK 호스트가 없으며 해당 구현·기기 검증은 별도다. 웹 콘텐츠 밖에서 브라우저/OS가 제한한 영역을 CSS로 강제로 차지했다고 주장하지 않는다.
