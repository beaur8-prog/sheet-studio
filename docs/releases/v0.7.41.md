# 0.7.41 — Android 작은 화면과 연속 입력

날짜: 2026-11-08. 개발 버전이며 공개 배포는 별도 요청 시 진행한다. Android에서만 새 동작을 적용한다.

## 사용 방법과 변경

1. 일반 문서는 입력 모드로 연다. 셀을 한 번 탭하면 숫자나 글자를 입력할 수 있다. XLSM과 사용자가 전환한 읽기 전용 보기는 선택·열람 동작을 유지한다.
2. 입력 후 **Enter** 또는 **다음 ↓**로 다음 셀에 이동한다. 같은 입력창을 유지해 숫자·문자를 연속 입력한다. **완료**는 입력을 마치고, **취소**는 해당 셀 입력을 취소한다. 한글 조합과 유효성 오류가 남으면 이동하지 않는다.
3. 입력줄의 **123 / 가·ABC**로 숫자·문자 입력 방식을 바꾼다. 입력값이나 포커스를 지우지 않는다.
4. **Σ 합계 · 평균 · 함수**는 편집 도구와 입력줄에 모두 있다. 집계는 계산할 범위와 결과를 넣을 빈 셀을 미리 보여준다. **수식 넣기 → Enter**로 적용한다. 선택한 사각형 전체를 사용하고, 결과 셀의 기존 값과 순환 참조를 보호한다.
5. 가로로 입력할 때 문서 제목·상하단 메뉴를 접고 입력줄 하나를 남긴다. 메뉴는 입력 완료 후 더보기에서 접근한다. 키보드가 켜져 높이가 줄어도 세로 화면을 가로로 잘못 바꾸지 않으며 회전 중 초안을 유지한다.
6. 상단 **전체화면**은 지원 브라우저에서 시스템 전체화면에 진입/복귀한다. Android 네이티브 호스트가 `setFullscreen`을 제공하면 실행 시 상태줄 숨김을 요청한다. 홈 화면 실행용 manifest는 fullscreen 표시 방식을 요청한다.

## 화면 공간

- 기존 Android 가로 대기 화면의 약 216 CSS px 메뉴를 96px로 줄인다.
- 입력 중에는 기존 약 112px 대신 한 줄 48px를 사용한다.
- 915×412 모의 창에서 격자 높이는 대기 316px, 입력 중 364px다.
- 키보드 표시 상황을 모의해 유효 높이를 200px로 줄여도 격자 152px와 입력줄 48px를 유지한다. 터치 버튼은 최소 48 CSS px를 유지한다.

위 수치는 브라우저의 논리적 화면 높이이며 실제 기기의 시스템 표시줄·cutout·키보드 픽셀 수치와 동일하다는 뜻은 아니다.

## 검증

- 프로덕션 빌드 성공. 앱 버전과 빌드 manifest 모두 0.7.41.
- 전체 단위 검사 530개: 529개 통과, 실패 0개, Windows 전용 1개는 macOS에서 제외.
- Android Chrome UI 모의 검사 13개 시나리오군 통과. 단일 탭, 숫자 3칸 Enter 연속 입력에서 동일 입력창·blur 0회, 숫자/문자 전환, 한글 조합, 유효성 오류의 초안 유지, 중복 Enter 방지, 읽기 전용 보호를 확인했다.
- 합계/평균은 A1:B2의 4개 값을 모두 사용하며 결과 10/2.5를 확인했다. 기존 결과 셀 덮어쓰기와 순환 참조는 차단했다. 함수 검색·삽입도 확인했다.
- 가로/세로, 키보드에 의한 높이 축소, 입력 중 회전, 수식 창 입력·닫기 후 셀 입력을 재검사했다. 마지막 경로에서 터치 호환 mousedown이 입력 포커스를 격자로 돌리는 문제를 재현·수정하고 같은 검사로 확인했다.
- 웹 브라우저의 실제 Fullscreen API 진입·복귀 성공. 네이티브 상태줄 요청·확인 응답은 시험용 호스트로 검사했다.
- 10만 셀 문서는 데스크톱 Chrome의 Android 모의 환경에서 845ms에 열렸다. 잘못된 파일 열기는 기존 문서를 유지했다. 실제 휴대폰 성능 측정값은 아니다.
- 실제 Electron 실행 검사와 기존 편집 UI 검사 통과. 좁은 Windows·iPad 창에 Android UI/manifest가 적용되지 않음을 확인했다.

검사는 격리된 프로필·복구 저장소·시험용 클립보드로 진행했다. 사용자 문서와 OS 클립보드는 변경하지 않았다.

실제 Android Gboard·삼성 입력기에서 키보드가 유지되는지와 OS 안테나/시계 줄이 숨겨지는지는 이 환경에서 검증하지 않았다. 웹 API 전체화면 진입/복귀와 네이티브 호출·응답 경로를 구분해 검사한다. 현재 저장소에는 APK 호스트 프로젝트가 없으며 실제 네이티브 상태줄 적용·IME 연결은 패키징 단계에 남는다. [연결 계약과 범위](../ANDROID-UI-IMPLEMENTATION.md)
