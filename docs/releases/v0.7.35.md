# 0.7.35 · 파일 선택창 대기 처리

개발 버전이며 공개 GitHub 릴리스와 리토스 공유본은 갱신하지 않는다.

## 재현과 원인

로컬 Mac의 실제 파일 열기를 실행했으나 선택창이 나타나지 않고, 재요청 시 ‘다른 파일 작업이 끝난 후 다시 시도하세요’가 표시됐다. 앱과 렌더러는 계산 루프를 돌지 않았으며 네이티브 선택창 완료 응답을 기다리고 있었다. macOS 파일 패널 서비스의 프로세스 샘플에서 `NSOSPDefaults`의 마지막/최근 폴더 북마크 복원 → `DownloadCloudDocumentSync` → 대기를 확인했다. 파일 내용의 해석이나 XLSX 수식 계산에 진입하기 전이다.

앱 전용 위치 기록과 공용 파일 패널 최근 폴더 기록을 로컬에 백업했다. 해당 Mac에서 공용 최근 폴더 북마크 목록만 초기화하고 앱 전용 초기 위치를 로컬 경로로 지정해 실제 선택창의 초기화 지연을 해소했다. 문서와 폴더, 자동 복구 문서는 삭제하지 않았다. 이 공용 설정 복구는 해당 Mac의 현장 조치이며 **앱이 다른 컴퓨터의 공용 설정을 자동 삭제하지 않는다.**

## 코드 변경

- Mac에서는 파일 선택창을 만들기 전에 앱 전용 `NSOSPLastRootDirectory`에 현재 문서 폴더의 문자열 경로를 기록한다. 기존 문서 폴더/최근 성공 폴더/문서 폴더의 우선순위는 유지한다. 열기와 저장 모두 적용하며 공용 최근 폴더 설정은 수정하지 않는다.
- 파일 열기 중 선택창을 기다린다는 표시를 보여 주고 중복 열기·편집 입력을 막는다. 취소나 오류가 나면 대기 표시를 해제해 다음 열기를 허용한다.
- OS 파일 요청 IPC가 지속적으로 실패할 때 같은 요청을 무한 재시도하지 않는다. 남은 파일이나 새 요청 알림이 있을 때 다시 처리한다.

## 검증

단위 검사, 격리 프로필의 파일 열기/저장 폴더·파일 연결·복구 시나리오와 실제 Mac 선택창 표시·취소·열기를 검증한다. 자동 UI 검사에서는 파일 선택 결과를 제어하며 실제 OS 선택창 검증과 구분한다. 원시 macOS 설정 백업과 사용자 프로필은 Git에 포함하지 않는다.
