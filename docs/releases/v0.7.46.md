# Sheet Studio 0.7.46 · Android Esc/Back과 계산 표시

이 변경은 개발 수정이다. 리토스 공개 설치본을 자동으로 바꾸거나 공개 APK·릴리스를 게시하지 않았다. Android 패키지는 1.0.5-qa/versionCode 6, 별도 ID `io.officestudio.sheet.qa`로 검증한다.

## 재현과 수정

- 작업 스레드 응답을 180ms 늦춘 Android 검사에서 숫자 입력·Enter·스크롤 도중 화면 전체의 숫자/빈 셀이 ‘계산 중’으로 덮이는 현상을 재현했다. 수정 전 프레임별 임시 문구 셀 수의 합은 3,972였다. 일반 값은 즉시 표시하고 같은 문서의 수식 결과는 재계산 중 직전 표시를 유지하도록 고쳤다. 표시값의 대기 여부는 `aria-busy`로 구분한다.
- 화면용 이전 값은 실제 계산·복사·유효성 검사·저장으로 전달하지 않는다. 원본 파일의 무효화된 계산 캐시와 다른 문서의 결과는 표시용으로도 재사용하지 않는다. 배열/유출 결과와 조건부 서식은 작업 스레드를 유지한다. 처음 계산하는 수식의 대기 시간 자체를 없애는 변경은 아니다.
- 일반 Esc에 더해 키보드/DeX에서 Esc가 Android Back으로 전달되는 경우를 처리한다. 누름에서 뷰어 복원을 요청하고, 화면이 복원된 뒤의 반복·키 뗌이 다시 앱 종료 경로로 넘어가지 않도록 소비한다. 네이티브 응답 대기 중 Esc도 보관해 전환 완료 후 적용한다.
- Sheet 네이티브의 예전 공통 `close` 요청은 Activity를 끝내지 못하게 한다. 문서 종료 확인·복구 저장을 완료한 `closeApp`은 새 `sheetClose` 경로로 정상 종료한다. 다른 앱의 close 경로는 바꾸지 않는다.
- 앱 문서 정보에 Android 설치 버전과 편집 엔진 버전을 함께 표시한다.

## 코드와 적용 범위

[Sheet 전용 Android 호스트 브랜치](https://github.com/beaur8-prog/office-studio/tree/codex/android-sheet-key-up-20261108)는 공개 통합 호스트 `b9031a7`을 기준으로 한다. 기존 Word/Slide 변경은 유지하며 Sheet APK만 검증한다. Android 화면 표시만 새 표시 API를 사용하고 Windows/macOS의 화면은 기존 경로를 유지한다. 정상 수식·출력 파일 계산은 공통 회귀 검사로 확인한다. 공개 설치본에는 렌더러와 호스트를 함께 배포해야 한다.

## 검사

- 추가 표시 단위 검사 4개 통과: 리터럴 타입/오류, 표시값과 실제 값 분리, 이전 작업 응답/다른 문서 차단, 배열과 무효화된 원본 캐시 보호.
- 전체 단위 검사 541개 중 540개 통과, 실패0개, Windows 전용1개는 macOS에서 제외.
- 느린 작업 스레드의 프레임 검사에서 계산 중 덮어쓰기 0개, 기존 수식 결과 지우기 0개. 이는 모의 지연 검사이며 실물 기기의 성능 측정은 아니다.
- Android UI15개군, 전체화면·태블릿 UI8개군, 프레임 검사1개군 통과. 전환 응답을 120ms 늦추고 바로 Esc를 눌러도 종료 요청 없이 화면만 복원하는 경우를 포함한다.
- 실제 Electron 재계산 회귀 검사 통과: RAND/F9와 종속값, 1만 셀 수식 연쇄, 편집·실행 취소/다시 실행·저장·재열기, 날짜·조건부 집계·1904 날짜 기준과 XLSX의 계산 캐시 일치.
- 네이티브 Java/계측 컴파일 통과. 실제 에뮬레이터 결과는 완료 후 추가한다.

실물 제조사 기기·DeX·물리 한글 키보드 검증은 별도다. `KEYCODE_BACK` 매핑은 네이티브 계측에서 누름과 뗌 사이에 웹 뷰어 복원을 기다리는 순서로 검사한다. 사용자 문서·복구 자료·OS 클립보드를 시험에 사용하지 않는다.
