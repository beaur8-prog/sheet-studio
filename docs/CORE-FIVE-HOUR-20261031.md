## 재현과 수정 기록

착수 시 FILTER/SORT/UNIQUE/SEQUENCE와 `A1#` 스필 참조는 미지원이다. 원본 고정 배열을 읽는 기능은 있으나 새 배열 수식 결과를 주변 셀에 동적으로 표시하지 않는다.

### 1차 구현: 동적 배열과 파일 캐시

- FILTER/SORT/UNIQUE/SEQUENCE와 스필 확장·축소, `A1#`, `@` 교차 선택을 연결했다. XLOOKUP은 일치한 행의 여러 열 또는 열의 여러 행을 반환한다. 기존 CSE는 고정 범위를 유지한다.
- 결과 셀 일부 덮어쓰기를 막고 첫 셀 편집·삭제, 복사(원본 포함 시 수식 / 결과만 선택 시 값), 실행 취소·다시 실행, 영역 이동, 합계 표시와 인쇄를 연결했다. 스필 경계와 막힌 이유를 표시한다.
- XLSX의 XLDAPR/동적 배열 메타데이터와 미래 함수 접두사, ANCHORARRAY/SINGLE 표현을 왕복한다. 독립 XlsxWriter 생성 파일과 기존 CSE를 구분하고 원본의 다른 cm/vm 기록·연결 파일을 보존한다.
- 지원하지 않는 수식의 원본 캐시는 표시 근거를 구분한다. 셀 값이 바뀌면 오래된 캐시를 새 계산값처럼 쓰지 않으며 실행 취소가 그 상태도 복원한다. 동적 배열의 오래된 원본 캐시는 파일에 보존하되 이 앱의 저장/재열기에서도 오래되었다는 표식을 유지한다.
- 계산 가능한 가져온 스필의 값 전용 캐시 셀을 정리한다. 스타일·메모·원본 셀 메타데이터는 유지해, 큰 배열을 줄인 뒤 편집 셀 한도가 불필요하게 차 있는 문제를 피한다. XLSM은 원본 보존을 위해 이 정리에서 제외한다.

추가 재현: 잘못된 방향으로 `A1#` 수식을 복사하면 `#REF!#`가 만들어졌다. 참조가 무효화될 때 스필 연산자도 소비해 `#REF!`로 유지하도록 복사·전치·행/열 삭제·시트 삭제를 수정했다. 또 원본이 오래된 미지원 배열을 `SUM(A1#)`로 읽으면 옛 합계가 살아나는 경로를 차단했다.

로컬 검증: 관련 단위 검사, 실제 Electron의 직접 편집·원본 변경·실행 취소/다시 실행·부분/전체 복사·저장/재열기, CSE 회귀, 10,000셀 의존 체인과 F9 회귀를 확인했다. LibreOffice 26.8의 별도 프로필에서 13개 XLSX 사례에 의도적으로 틀린 캐시를 넣고 다시 계산해 배열의 모든 원소가 일치했다. 이는 새 Microsoft Excel 실행 검증을 대신하지 않는다. 100만 결과의 계산·XLSX 저장·재열기 성능 수치와 최종 플랫폼 결과는 마지막 검증 후 기록한다.

한도: 파생 결과 합계 1,000,000개, 한 시트의 활성 배열 정의 10,000개, XLSX 기록 합계 1,000,000개다. 그 이상은 오류를 표시한다. 모든 최신 Excel 배열 함수나 LAMBDA, 복수 검색값과 복수 반환 열을 동시에 조합하는 XLOOKUP 전체를 구현한 것은 아니다. 지원하지 않는 rich-data/사용자 함수는 원본 보존과 캐시 정책을 적용한다.


### 2차 구현: 페이지 설정과 실제 PDF

페이지 레이아웃에 페이지 설정 창을 추가했다. 용지·방향·백분율/페이지 맞춤·시작 페이지 번호·페이지 순서·눈금선, 여백, 인쇄 영역·반복 행/열, 기본/첫/짝수 페이지의 머리글·바닥글을 편집한다. 적용 전 검증은 원본을 변경하지 않으며 한 번의 실행 취소로 되돌릴 수 있다. 잘못된 저장 인쇄 참조도 설정 창에서 보고 수정할 수 있다. XLSM의 원본 설정 변경은 기존 원본 보존 정책에 따라 제한한다.

머리글·바닥글은 왼쪽/가운데/오른쪽 구역, 페이지/전체 페이지/날짜/시간/파일·시트 이름, 글꼴·크기·굵게·기울임·밑줄·색상과 첫/짝수 페이지 구분을 출력한다. 가져온 서식은 해당 텍스트 구역을 바꾸지 않으면 유지한다. 첫 페이지 또는 짝수 페이지의 명시적인 빈 머리글과, 원본에 짝수 머리글이 없는 경우를 구분한다. 원본 경로와 머리글 그림 등 표시할 수 없는 정보는 실제 출력의 제한을 알리고 파일에는 보존한다.

PDF 재현 과정에서 여백에 배치한 바닥글이 추가 페이지를 만드는 문제를 잡았다. 용지 전체 크기 안에 여백·본문·머리글·바닥글을 배치해 실제 PDF 페이지 수를 계산 결과에 맞췄다. 셀 표 뒤의 차트·이미지는 각각 별도 페이지로 출력해 페이지 번호/전체 수에 포함한다. 지정 공간을 넘는 머리글은 잘린 채 인쇄하지 않고 조정을 안내한다. 이는 차트를 시트의 원래 위치 그대로 인쇄하는 기능까지 구현한 것은 아니다.

검증: 인쇄 설정의 적용/취소/실행 취소·다시 실행/저장·재열기, 잘못된 참조·여백의 원자적 거부, 차트 전용 시트의 설정 왕복, 4페이지의 실제 PDF(첫/짝수 머리글·한글·반복 제목·페이지 번호·차트)와 기존 인쇄·페이지 나눔·프린터/머리글 그림 연결 보존 회귀를 통과했다. Poppler 렌더링으로 새 PDF 4페이지와 기존 표·차트·이미지 출력도 시각 확인했다.

근거: [Microsoft 머리글/바닥글 코드](https://learn.microsoft.com/en-us/office/vba/excel/concepts/workbooks-and-worksheets/formatting-and-vba-codes-for-headers-and-footers), [첫 페이지 머리글](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.firstheader), [짝수 페이지 머리글](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.evenheader).

1차 동적 배열 커밋 `8ba775f`는 [Windows·Mac·Ubuntu 핵심 회귀 검사](https://github.com/beaur8-prog/sheet-studio/actions/runs/41096830969)를 모두 통과했다. 후속 인쇄 설정의 플랫폼 검사와 남은 대용량/UI 검증은 계속 진행한다.


### 3차 구현: 대용량 편집과 배열 소비 기능

100만 결과를 선택해 지울 때 파생 셀 100만 개를 만들던 편집 경로를 원본 기록만 처리하도록 바꿨다. 서식·메모와 숨긴 셀, 기존 CSE의 전체 교체 규칙은 유지한다. 부분 스필 선택은 실제 저장 셀이 없어도 거부한다. 실제 원본 셀의 변경 한도 100,000개는 유지한다.

자동 합계는 화면에 계산된 셀만 보고 범위를 자르지 않도록 작업 스레드에서 전체 후보 범위를 확인한다. 배열 결과를 숫자로 인식하고 합계 위치를 비어 있는 다음 행·열에 둔다. `A1#`의 F4 고정 참조와 전체 스필 범위 강조도 연결했다. 필터의 한 행/전체 열/부분 결과 선택과 차트의 첫 행·첫 열 추론이 파생 셀을 빠뜨리지 않게 보강했다.

계산 경계 재현: 1,000셀 범위를 조회하는 XLOOKUP 10,000개 문서에서 앞 수식은 500인데 마지막 수식은 `#NUM!`가 됐다. 배열 후보를 찾는 과정의 누적 한도가 나중 수식의 캐시를 오염시켰다. 단일 값 조회와 이름/표의 크기를 구분해 불필요한 계산을 줄이고, 한도를 개별 계산에 적용했다. 일반 조회 문서에서 마지막 셀만 요청하는 검사는 약 1.7초/오류에서 약 34ms/500으로 바뀌었다. 이는 수식 10,000개 전체를 계산한 시간이 아니다. 가져온 1셀 동적 표식이 있는 조회 수식 10,000개도 별도로 계산해 마지막 값이 500임을 확인했다.

또 `INDIRECT("A1#")`와 이름 범위의 결과를 시작 셀보다 먼저 읽는 경우를 수정했다. INDEX의 생략된 열/행 인수는 [Microsoft의 행·열 전체 반환 규칙](https://support.microsoft.com/en-us/excel/functions/index-function)에 맞추고, 1차원 배열의 단축 선택은 유지했다. 독립 LibreOffice 재계산은 INDEX를 포함한 17개 사례가 일치했다.

실제 앱 대용량 검증(이 Mac의 측정, 다른 PC의 보장 수치가 아님):

| 사례 | 관찰 |
|---|---|
| 원본 1개로 100만 결과 계산·마지막 셀 이동 | 약 0.7초 |
| 100만 결과 전체 지우기 | 약 51ms, 실행 취소 기록 약 3.2KB |
| XLSX 저장 | 약 8.7초, 8.18MB, 화면 타이머 최대 간격 약 26ms |
| XLSX 재열기·원본 압축·마지막 셀 이동 | 약 18.1초, 원본 1개 유지 |
| 프로세스 재시작 | 원본과 100만 결과 복구 |
| 10,000개 가져온 조회 수식 계산·이동 | 약 2.8초, 마지막 값 500 |

배열 원본 셀 하나에서 차트 10종을 실제 삽입하고, 필터 범위·조건·다시 적용·실행 취소/다시 실행·차트 갱신·XLSX 저장/재열기를 통과했다. 재열기 후 원본은 하나이고 차트의 모든 자료가 유지된다. XLSX 기록 한도 초과 시 기존 저장 파일을 덮어쓰지 않는 것도 확인했다.

### 4차 구현: 외부 통합 문서 연결의 원본 보존

외부 파일을 참조하는 XLSX를 열고 저장하면 `externalReferences`와 연결 파트가 사라지고 저장값 42가 `#REF!`로 바뀌는 것을 재현했다. 연결 목록의 순서와 번호, 외부 파일 경로, 원본 정의·캐시·연결 파트 트리를 보존한다. 참조 파일을 열거나 네트워크에서 내려받거나 연결 값을 갱신하지 않는다.

직접 계산할 수 없는 가져온 수식의 저장값은 화면에서 그 근거를 표시한다. 원본의 숫자·불리언·텍스트·실제 오류를 구분하며 차트·필터·선택 합계와 인쇄에 일관되게 연결한다. 셀을 수정하면 저장값을 오래된 것으로 표시하고 계산 결과로 사용하지 않는다. 실행 취소가 유효 상태도 복원한다. 외부 연결 또는 원본 수식 메타데이터가 있는 수식의 캐시는 XLSX에 원본으로 유지하고, 이 앱에서 재열었을 때 오래된 캐시라는 사실도 유지한다. 삭제한 이름의 오래된 값은 되살리지 않고 현재 `#NAME?` 오류를 저장한다.

다른 문서로 외부 참조 수식을 그대로 붙여넣으면 같은 연결 번호가 전혀 다른 파일을 가리킬 수 있어 값 붙여넣기를 안내한다. 같은 문서 안의 복사는 상대 주소를 이동하고 연결 정의는 유지한다. 연결 정의가 없는 새 문서에서 외부 참조를 만드는 작업은 거부한다.

검증: 두 외부 연결과 다섯 가지 캐시 자료형의 JSON·XLSX 3회 왕복, 연결 누락 시 명시적 오류, 편집·실행 취소/다시 실행·저장·재열기, 화면의 저장값 안내와 합계, 문서 간 수식/값 붙여넣기, 문서 내 상대 참조 복사를 확인했다. 합성 OOXML 원본을 사용했고 실제 외부 파일에는 접근하지 않았다. 기준: [OOXML ExternalLink](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.externallink), [ExternalReference](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.externalreference).

전체 플랫폼 회귀에서는 화면을 바꾸며 연속 계산할 때 검사 대기가 일찍 끝나는 경로도 확인했다. 갱신이 다시 요청한 계산까지 끝나고 화면이 렌더링된 뒤 다음 동작으로 넘어가도록 대기 조건을 보강했다. Mac·Ubuntu의 해당 셀 편집/차트 시나리오를 로컬에서 재검사했다. Windows에서 발견한 피벗 필드 편집 실패는 로컬에서도 재현되어 후속 수정 대상으로 다룬다.

### 5차 구현: 피벗의 원본 계산과 배열 연결

전체 검사에서 피벗을 새로 고친 후 필드를 편집하면 “고유한 머리글이 필요합니다”라는 오류가 나며 필드가 사라졌다. 로컬에서도 같은 순서로 재현했다. 원인은 화면 밖 원본의 값을 읽을 때 비동기 계산의 `계산 중…` 문자열을 머리글로 사용한 것이었다.

피벗의 원본 읽기·미리 보기·적용·새로 고침을 작업 스레드의 실제 계산 세션으로 옮겼다. 오래된 미리 보기 응답이 최신 선택을 덮어쓰거나 닫은 창을 다시 채우지 않게 구분하고, 계산 중의 적용을 제한한다. 새로 고침의 오류는 마지막 정상 보고서를 바꾸지 않는다. 배열에서 생성한 머리글과 결과 셀도 빠짐없이 읽고, 수식의 `"#N/A"` 텍스트와 실제 `#N/A`·`#CALC!` 오류를 구분한다. 직접 계산하지 못하는 원본 오류는 옛 캐시로 집계하지 않고 명시적으로 알린다.

검증: 기존 피벗 시나리오 전체(생성·원본 수정·새로 고침 후 즉시 필드 편집·평균·필터·일반 범위 변환·실행 취소·XLSX 왕복)를 다시 통과했다. 추가로 실제 원본 레코드 4개에서 파생된 100,000셀을 집계하고, 화면 밖 원본 수정·집계 방식 연속 변경·창 닫기·한도 오류·계산 오류 후 정상 보고서 유지·집계 방식의 실행 취소/다시 실행·XLSX 재열기를 확인했다. 같은 사례를 운영체제 회귀 검사에도 추가했다.

### 6차 구현: 차트·이미지의 시트 위치 인쇄

앞선 2차 구현의 개별 페이지 출력에 더해, 시트에 놓인 위치대로 차트·이미지를 인쇄하는 방식을 기본으로 추가했다. 인쇄창에서 개체별 페이지 방식도 선택할 수 있다. 차트만 인쇄할 때는 기존처럼 각 차트를 한 페이지에 출력한다.

개체의 범위를 자동 인쇄 영역에 포함하고, 저장 인쇄 영역·선택 영역 밖의 개체는 제외한다. 개체가 페이지 경계를 넘으면 해당 부분만 나눠 출력하며 반복 제목의 공간을 반영한다. 제목을 반복하더라도 차트 자체를 매 페이지 복제하지 않는다. 숨김 행·열과 필터를 제외한 인쇄 좌표, 백분율·페이지 맞춤, 여러 인쇄 영역을 연결했다. 그림은 지원되는 PNG/JPEG/GIF/WebP 미리 보기 대상이며 원래의 시트와 함께 인쇄 여부(`fPrintsWithSheet`)를 유지한다. 지원하지 않는 도형 등은 기존처럼 제외 안내와 원본 파일 보존을 적용한다.

영역 밖 차트는 그래프나 관련 수식을 불필요하게 계산하지 않는다. 개체 분할 2,000개 및 개체 HTML 32,000,000자 한도로 출력을 제한해 큰 문서의 출력이 메모리를 끝없이 늘리지 않게 했다. 셀 20,000개·페이지 500개라는 기존 인쇄 한도도 유지한다. 이 기능은 앱에서 표시하는 개체의 좌표와 미리 보기를 사용하며 모든 Excel 도형 효과·원본 차트 미리 보기의 완전한 재현을 의미하지 않는다.

검증: 인쇄 영역/선택 영역/불연속 영역, 두 축의 수동 페이지 나눔, 반복 제목, 개체 인쇄 제외 표식의 XLSX 반복 왕복, 영역 밖 RAND 자료의 불필요한 계산 방지와 출력 한도 검사를 통과했다. 실제 앱에서 표·차트 2개·그림을 4페이지 PDF로 생성해 페이지별 개체 좌표·잘림·머리글/바닥글·총 페이지 수를 검사하고 **4쪽 모두 렌더링해 육안 확인**했다. 같은 문서를 가로 한 페이지 맞춤 PDF로 다시 출력해 표·개체가 함께 축소되고 영역 밖 차트가 제외되는 것도 확인했다. 기존 개별 페이지 인쇄·페이지 설정·차트 전용 시트·원본 도형 보존 검사를 다시 통과했다.

기준: [Excel 차트 인쇄](https://support.microsoft.com/en-au/excel/print-a-chart), [OOXML ClientData의 인쇄 표식](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.spreadsheet.clientdata), [Excel 인쇄 영역](https://support.microsoft.com/en-us/excel/set-or-clear-a-print-area-on-a-worksheet).

### 7차 보강: 저장값의 근거와 문서 변경

시트 이름·목록·날짜 체계·이름 정의·원본 셀 맵처럼 계산에 영향을 주는 변경도 가져온 미지원 계산값을 무효화하며, 같은 실행 취소 항목이 유효 상태를 복구한다. 활성 시트 이동·글꼴·차트 미리 보기·인쇄용 머리글 변경만으로는 유효한 캐시를 지우지 않는다.

전체 CI에서 `SUM(Revenue)`의 Revenue가 정의되지 않았는데 원래 숫자 캐시 99가 표시되는 회귀를 재현했다. `#NAME?`라는 오류 문자열만으로 미지원 기능 여부를 판단한 것이 원인이었다. 계산 오류에 미지원 함수/외부 연결의 내부 근거를 전파하고, 실제 미정의 이름이나 명시적인 `#NAME?` 오류는 캐시를 표시·그래프·XLSX에서 사용하지 않도록 수정했다. 미래 함수와 그 종속 셀의 유효한 원본 캐시는 계속 구분해 보존한다. 이름 삭제 후 XLSX에는 현재 오류가 실제 오류 종류로 저장된다.

검증: 미정의 이름·그 종속 수식·실제 NAME 오류·미지원 함수와 종속 수식을 한 파일에서 구분했다. 같은 실제 앱의 이름 생성→편집→실행 취소/다시 실행→삭제→저장과 재열기, 외부 연결의 서식 변경·시트 이름 변경·시트 추가·실행 취소, 기존 동적 배열·결과 자료형 검사를 다시 통과했다. 위치 인쇄의 [Windows·Mac·Ubuntu 검사](https://github.com/beaur8-prog/sheet-studio/actions/runs/41109519739)는 모두 통과했다.

### 8차 보강: 배열 결과의 원래 셀 메타데이터

캐시 전용 배열 결과를 희소 원본으로 압축한 뒤 재저장하면 값 메타데이터의 `vm` 번호가 빠지는 것을 재현했다. 결과 셀의 `raw`를 빈 원본으로 바꾸면서, 이전 원문과 비교하던 보존 조건이 항상 달라진 것이 원인이었다.

원본 배열 소유 셀과 원래 자료형/값을 추적해 같은 결과의 메타데이터를 복원한다. 원본 수식을 각 결과 셀에 반복 저장하지 않으며, 배열 공식이나 실제 값이 달라지거나 결과가 없어지면 예전 값의 메타데이터를 붙이지 않는다. 형식만 바꾸거나 다른 셀을 편집하는 경우에는 유지한다. 행·열 이동은 소유 주소와 수식·캐시 서명을 함께 갱신하며 실행 취소로 복원한다. 원본이 오래된 미지원 배열은 기존과 같이 원본 페이로드와 오래된 상태를 보존한다.

검증: 유효한 메타데이터 번호를 가진 합성 `APP_PRIVATE` 확장으로 JSON/XLSX 3회 왕복, 값/서식/공식/전체 삭제/단계별 실행 취소, 가로·세로 구조 이동과 실제 앱의 저장·재열기를 확인했다. 이는 주식·연결 데이터 형식의 계산 기능을 구현하거나 실제 Excel에서 모든 rich-data 확장을 확인했다는 뜻은 아니다. 기존 배열·결과 자료형·외부 연결·구조 변경·인쇄 설정 보존 회귀도 통과했다.

### 9차 보강: 실제 업무 문서의 통합 흐름과 차트 원본 표시

실제 화면에서 매출 표를 만들고 구조화 참조 계산 열을 적용한 뒤, 다른 시트의 `SORT(FILTER(...))` 대시보드·차트·피벗으로 연결했다. 원본 수정, 실행 취소/다시 실행, 명시적인 피벗 새로 고침, 표 자동 확장과 이름 변경, 실제 XLSX 2회 저장/재열기와 재편집을 한 흐름으로 확인했다. 마지막 표·합계·차트를 가로 한 페이지 PDF로 함께 출력했다. 차트와 피벗은 지정한 고정 원본 범위를 사용하며 배열 크기에 맞춰 자동으로 원본 범위를 늘리는 새 기능을 추가한 것은 아니다.

이 흐름에서 저장 후 차트의 계열 값과 그림은 정상인데 설정의 데이터 범위가 내부 기본값 `A1:B2`로 보이는 문제를 재현했다. 가져온 차트는 여러 시트·이름·불연속 범위를 조합할 수 있어 한 사각형으로 표현하지 않고, 원본 계열의 실제 참조를 중복 없이 표시하도록 바꿨다. 셀 참조가 없는 캐시 전용 계열은 그 사실을 안내한다. 변환을 선택할 때만 새 범위 입력이 나오고, 변환을 다시 취소하면 원본 참조를 유지한다. 시트 이름의 따옴표, 이름 참조, 이전 앱 문서의 계열과 원본 유지/변환 토글을 검사했다.

재현 도구는 `tests/ui-dashboard-journey.mjs`이며 실제 사용자 클립보드와 프린터를 사용하지 않는다. 운영체제별 핵심 회귀와 설치 패키지 검사에도 추가했다.

### 10차 보강: 빈 문자열과 실제 빈 셀의 XLSX 자료형

혼합 자료를 더 비교하던 중 명시적인 빈 텍스트(`'`)가 XLSX를 다시 열면 실제 빈 셀로 바뀌는 문제를 재현했다. `ISBLANK`·`ISTEXT`의 결과가 달라지고 SORT 등의 파생 결과는 빈 문자열 대신 0이 됐다. 가져오기에서 빈 문자열을 빈 원본으로 바꾸던 처리와 ExcelJS가 빈 인라인 문자열을 누락하는 경로가 원인이었다. 미지원 수식의 빈 문자열 캐시도 캐시가 아예 없는 경우와 구분되지 않았다.

공유 문자열은 텍스트 원본으로 유지하고, 스트리밍 XML 검사로 빈 인라인/리치 문자열과 명시적인 빈 수식 캐시를 추적한다. 공백·CDATA의 실제 내용은 빈 텍스트로 오인하지 않고, `<v>`가 없는 수식에 빈 캐시를 만들어 넣지 않는다. 빈 셀·스타일 전용 셀은 그대로 유지하며 추가 추적에도 문서 셀 한도를 적용한다. 반복 저장 3회, 실제 앱의 작업 스레드 저장/재열기·실행 취소, 계산 가능한 배열·기존 메타데이터 보존을 확인했다.

별도 고정 시드의 수식 240개(숫자/빈칸 120개, 텍스트·불리언·오류 혼합 120개)는 자체 XLSX 왕복에서 결과 값 4,338개가 모두 유지됐다. LibreOffice 26.8.0.3의 독립 재계산과는 각각 112/120·26/120개 식이 일치했다. 모든 출력 캐시를 -999로 바꿨고 재계산 후 그 값이 남은 사례는 없었다. 숫자 집합의 차이는 UNIQUE 뒤의 빈칸 정렬과 빈 결과의 오류 표현이며, 혼합 집합에는 논리값·빈 문자열·오류의 전파/저장 표현 차이도 있다. 이 수치는 Excel 정답률이 아니며, LibreOffice의 동작을 무조건 Excel의 규칙으로 적용하지 않았다.

재현 명령: LibreOffice를 별도 설치한 환경에서 `SHEET_STUDIO_SOFFICE=/path/to/soffice node tests/libreoffice-array-comparison.mjs`. 성공 종료는 비교 완료를 뜻하므로 `.verification/array-comparison/report.json`의 `differences`도 확인해야 한다. 기본 배열 17개가 독립 재계산과 일치한 검사와 이 경계 진단 집합을 구분한다.

### 11차 보강: 자료형·오류·검색 조건의 배열 처리

Sheet Studio의 저장 경로를 거치지 않은 XlsxWriter 원본에서도 LibreOffice의 배열 논리값/빈 텍스트/오류 표현 차이를 확인했다. 같은 확인 중 앱의 `ISLOGICAL(FILTER(...))`가 첫 값 하나만 반환하는 결함을 재현했다. 정보 함수가 여러 셀 배열을 하나의 값으로 읽다가 잘못된 판정으로 바꾸는 경로였으며, `FILTER(...,ISNUMBER(SEARCH(...)))` 같은 실용적인 검색 조합도 실패했다.

ISNUMBER·ISTEXT·ISNONTEXT·ISLOGICAL·ISBLANK·ISERROR·ISERR·ISNA, ERROR.TYPE·N·T·NOT을 셀별 배열 처리에 연결했다. 숫자/텍스트/논리/오류/실제 빈칸을 구분하고, TYPE의 배열 형식(64)과 ISREF의 참조 확인은 유지한다. 검색 포함 여부·숫자인 행 선택·오류 제외 필터, 결과 확장/축소·읽기 전용 결과·실행 취소/다시 실행·실제 XLSX 재열기를 검사했다. 독립 XlsxWriter의 -999 캐시는 사용하지 않고 원본 수식에서 계산하며 논리값·빈 문자열·개별 오류를 3회 왕복한다.

독립 입력은 `tests/fixtures/xlsxwriter-array-controls.py`로 다시 만들 수 있다. 이는 실제 Excel 실행 자료가 아니며 모든 Excel 함수의 배열 조합을 완성한 것도 아니다. 기준: [Microsoft IS 함수의 자료형 규칙](https://support.microsoft.com/en-us/excel/functions/is-functions), [FILTER의 Boolean 배열 조건](https://support.microsoft.com/en-us/excel/functions/filter-function).
