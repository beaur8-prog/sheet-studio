## 1. 데이터 유효성 규칙 작성 (T02)

0.7.38 검증 패키지에서 데이터 탭에 규칙 작성 명령이 없음을 확인했다. 작성 창을 추가해 목록·정수·소수·날짜·시간·텍스트 길이·사용자 수식을 작성·편집하고, 입력 안내와 중지/경고/정보를 설정한다. 부분 범위 교체·삭제 시 기존 범위를 직사각형으로 나누고 상대 수식 기준점을 옮겨 다른 셀의 의미를 보존한다. 전체 열에 규칙을 설정해도 셀을 모두 생성하지 않는다.

검증: 8개 단위 시나리오, 실제 앱 작성·목록 선택·오류 수정/경고 취소·계속 입력·상대 참조 미리 채움·부분 삭제·실행 취소/다시 실행·행 삽입·XLSX 저장/재열기·작은 화면. 붙여넣기는 Excel 공식 정책에 맞게 입력 경고를 우회하는 기존 동작을 유지하고, **현재 값 검사**로 불일치를 별도 확인한다. 검사창은 읽기 전용이며 조건 불일치/확인 불가, 검사·표시 한도를 명시한다.

아직 규칙 자체를 셀 복사·채우기로 복제하는 기능은 미완료다. 보호 시트·피벗·XLSM 규칙 작성은 차단한다. 가져온 알 수 없는 속성·선택 범위 밖 규칙은 보존한다. [사용법·제한·공식 근거](DATA-VALIDATION.md).

## 2. 날짜/시간 입력의 자료형 (E01/F04/T02)

0.7.38 패키지에서 날짜 서식의 A1에 `2026-11-05`를 입력하면 숫자 날짜 46331이 아니라 문자열이 되는 것을 동일 UI 시나리오에서 재현했다. 날짜·시간 서식 또는 해당 유효성 규칙이 있는 셀의 명확한 ISO 날짜·24시간제 시각을 숫자로 저장하고, 필요한 일반 서식에는 날짜/시간 표시를 붙인다. 일반·텍스트 목적지와 따옴표·수식의 종류는 보존한다. 일반 셀의 날짜처럼 생긴 식별자를 일괄 변환하지 않는다.

검증: 4개 단위 시나리오에서 문서화된 2011-07-05=40729, 1900-02-29 특례, 1462일 차이, DST 날짜·잘못된 날짜/시각, 초·밀리초, 텍스트·값 붙여넣기 보존을 확인했다. 실제 앱은 1900/1904 각각 서식 입력·유효성 입력·오류 재시도·계산 함수·XLSX 재열기를 통과했다. 실제 Excel 입력 지역 설정 비교는 대기다.

## 3. 조건부 서식과 확장 정의 보존 (T03/IO01/F03)

2색·3색 색조와 기본 OOXML 그라데이션 데이터 막대의 작성·편집·화면·인쇄·XLSX 왕복을 연결했다. 숫자만으로 범위 기준을 계산하며 숫자인 수식·스필 결과를 포함한다. 숫자·백분율·백분위수 기준을 지원한다. 기본 막대는 문서화된 10~90% 계산을 사용하고 고급 음수 축·색은 원본 보존으로 구분한다. 단일 값·상수 분포의 실제 Excel 시각 비교는 대기다.

기존 버전에서 두 가지 결함을 추가로 재현했다.

1. 고급 데이터 막대 저장 시 기본 규칙의 `x14:id`는 남고 `x14:dataBar`·음수 색 정의는 없어졌다. 기본 규칙과 확장 정의를 함께 보존하고 범위·수식·시트 이름을 함께 갱신하도록 수정했다. 연관 없는 워크시트 확장 전체를 무작정 보존하지 않고 조건부 서식 확장만 처리한다.
2. `=SEQUENCE(3)`의 A2=2에 일반 비교 규칙을 걸어도 실제 셀 기록이 없는 배열 결과를 빈 셀로 취급해 서식이 빠졌다. 배열 계산 여부를 확인해 값에 맞게 적용한다.

ExcelJS의 기본 막대 내보내기가 빈 `x14:id`를 만들기 때문에 새 기본 막대는 유효한 기본 OOXML 규칙으로 직접 기록한다. 고급 규칙은 별도 구조를 원본에서 보존한다. 사용자 기능과 보존 범위는 [조건부 서식 안내](CONDITIONAL-FORMATTING.md)에 기록했다.

검증: 시각 규칙 단위 시나리오 8개, 원본 확장 유실·배열 서식 실패 기준 로그, 실제 앱의 작성·재계산·취소·실행 취소·인쇄용 공통 스타일·XLSX 재열기·고급 규칙 3회 저장. 고급 정의의 GUID 연결, 음수 색, 삽입으로 이동한 범위, 이름 변경 수식을 검사했다.

## 4. 표와 피벗 원본 연결 (T01/P01)

기준 코드에서 표를 A1:B3→A1:B4로 늘려 새 행 30을 추가해도 피벗 고정 범위의 합계는 30에 머무르는 것을 확인했다. 표 원본을 선택하면 표 ID·사용하는 열 ID를 기록하고 새로 고침 때 현재 범위와 이름을 읽는다. 요약 행은 제외한다. 일반 범위·가져온 고정 범위를 임의로 표에 연결하지 않는다. XLSX에는 `worksheetSource name="Sales"` 같은 실제 표 원본을 기록한다.

표 열 번호가 삭제 후 재사용되지 않도록 다음 번호를 별도로 유지한다. 사용 중인 열/표 삭제·재생성은 자동으로 다른 필드로 바꾸지 않고 오류를 알리며 마지막 결과를 유지한다. 이러한 상태의 XLSX 저장은 차단하고, 사용자가 원본을 다시 고르거나 일반 범위로 바꾸도록 한다. 유효한 XLSX를 다시 열 때는 기존 피벗 외부 변경 검사를 통과한 뒤 표 이름과 열 번호로 새 앱 ID를 연결한다.

검증: 단위 시나리오 6개와 실제 앱에서 표 안 선택→생성, 새 행 추가→합계 30→60, 열 이름 변경, 서식 유지, 고정 범위 전환·실행 취소, 새로 고침 취소 기록, XLSX 이름 원본/재열기, 열 삭제 실패 시 결과 불변, 복구를 확인했다. 기존 피벗 작성·서식 시나리오도 통과했다. 작은 화면에서는 본문만 스크롤하고 적용/취소 버튼은 유지한다. [기능 안내와 제한](PIVOT.md).
