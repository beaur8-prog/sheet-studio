### 1차: 외부에서 변경한 피벗의 덮어쓰기 방지

- 재현: 앱이 만든 XLSX의 네이티브 피벗 집계를 합계→평균으로 바꾸고 결과 D4를 160→40으로 저장한 합성 자료를 열면, 기존 Custom XML의 합계 설정이 다시 적용돼 D4가 160으로 돌아왔다. 실제 Excel 실행 결과가 아니라 네이티브 OOXML 변경으로 재현했다.
- 원인: 가져오기에서 네이티브 정의와 앱 설정의 일치를 확인하지 않고 `applyPivot`을 실행했다.
- 변경: 새 파일에는 네이티브 배치 근거를 함께 기록한다. 기존 파일은 필드·집계·필터·원본을 대조한다. 설정이 다르거나 앱 설정이 없는 기본 피벗은 저장된 결과와 원본 피벗/캐시 연결을 보존하며 임의로 다시 계산하지 않는다. 사용자 지정 숫자 형식 ID와 패키지 관계를 저장 시 재연결한다.
- 편집: 원본 피벗은 안내 막대에 표시하고 Excel에서 새로 고치도록 안내한다. 일반 범위 변환을 명시적으로 선택하면 현재 값을 편집할 수 있고 실행 취소로 원본 개체를 복원한다. 보존 중 행열·시트·표 구성 변경은 제한한다. 외부/OLAP·슬라이서·고급 피벗 서식은 손실 가능한 XLSX 저장을 거부하고 앱 문서 또는 명시적 변환을 안내한다.
- 검증: 피벗 관련 단위 검사와 XLSX 3회 왕복, 앱 JSON 왕복·검증, 실제 Electron의 열기→편집 제한→저장→재로드→변환→편집→실행 취소 통과. 전체 단위 424개 중 423개 통과·Windows 전용 1개 제외. Windows/Mac/Linux 후속 검사는 진행 중이다.


### 2차: 찾기·바꾸기의 조건 일치와 안전한 일괄 변경

- 재현: 기존 찾기는 대소문자를 무시했으나 모두 바꾸기는 대소문자를 구분했다. `ALPHA`, `Alpha Beta`, `alpha`를 찾으면 3개가 표시되지만 모두 바꾸기는 일부만 바뀌었다. 검색 범위와 표시 값/수식 구분, 변경 미리 보기도 없었다.
- 변경: 같은 조건으로 찾기·바꾸기를 수행하고 현재 시트/선택 영역/통합 문서, 대소문자/전체 일치, 표시 값/값·수식 원문, 숨긴 시트 포함을 선택한다. 표시 값은 검색 전용이며 수식 결과를 덮어쓰지 않는다. 검색은 작업 스레드에서 수행하고 결과 목록을 제한해 큰 문서를 다시 정렬·복제하지 않는다.
- 변경 전 미리 보기를 요구한다. 여러 시트의 결과를 복사본에서 보호·배열·유효성·표 머리글/참조·용량 한도까지 검사한 뒤 한 번에 적용한다. 오류가 있으면 모든 시트를 유지하며 창 안에 원인을 표시한다. 한 번의 실행 취소/다시 실행과 원래 파일 폴더 연결을 유지한다.
- 검증: 새 단위 7개와 실제 Electron의 미리 보기→시트 간 결과 이동→일괄 변경→같은 창 재검색→실행 취소/다시 실행→선택/표시 값 검색→보호된 셀 전체 취소→XLSX 저장을 통과했다. 전체 단위 431개 중 430개 통과·Windows 전용 1개 제외. 실제 Excel UI 비교를 새로 수행한 것은 아니다.


### 3차: 알려진 파일 손실의 안내와 원본 보호

- 기준 0.7.37의 실제 입출력 모듈에서 합성 XLSX의 `xl/embeddings/document.bin`이 안내 없이 사라짐을 재현했다. 새 가져오기는 OLE/컨트롤/대화형 댓글/Data Model/슬라이서/다른 Custom XML/잘못된 XLSX의 VBA 등 판별 가능한 항목을 기록한다. 이는 모든 OOXML 기능의 전수 판별이 아니다.
- 도움말과 상태 표시줄의 파일 호환성에서 편집·원본 보존·저장 제한을 확인한다. 위험 항목이 있는 일반 XLSX 저장은 먼저 안내하며, 사용자가 선택한 기능 제외 사본은 원본 경로/동일 파일의 하드링크·심볼릭 링크에 덮어쓰지 않는다. 파일 경로는 앱의 로컬 위치 설정에서만 관리하고 내보낸 문서에 넣지 않는다.
- 앱 문서는 현재 편집 상태와 판별 결과를 저장한다. 보관하지 못한 개체의 원본 바이트까지 보존하는 형식이라고 표시하지 않는다. 복잡한 네이티브 피벗은 기존 제한을 유지하고 명시적 변환을 먼저 안내한다.
- 단위 5개와 실제 Electron의 안내→취소→원본 덮어쓰기 거부→다른 이름의 사본→앱 문서 저장을 통과했다. 원본 전체 SHA-256과 포함된 바이너리가 그대로임을 확인했다.

### 대용량 보강

- 새 바꾸기의 첫 구현에서 문서 전체를 실행 취소에 남길 수 있는 경로를 발견해 변경 셀·메타데이터만 적용하도록 수정했다. 100만 숫자/한글 셀에서 각각 20회 반복해 추가 기록은 약 4.5KB였으며 되돌리기·다시 실행과 증분 복구를 확인했다.
- 전체 셀의 깊은 복제와 배열 생성, 불필요한 격자 재계산을 줄였다. 이 Mac의 같은 합성 숫자 문서에서 처리 시간은 약 2.7초→1.8초, 20ms 화면 타이머의 최대 지연은 약 250ms→20~30ms로 줄었다. 초기 새 구현과 개선 구현의 비교이며, 모든 컴퓨터의 보장 수치나 공개 0.7.29와의 직접 비교가 아니다. 최종 측정의 중앙값·메모리·조건은 종료 시 정리한다.

### 4차: 대화상자와 수식의 문서화된 경계

- 대화상자 공통 처리에서 조합 중 Enter/Esc·229 키가 적용/닫기를 실행하지 않도록 하고, 최초 포커스·Tab 경계·닫힌 뒤 편집 포커스를 보강했다. 합성 composition 이벤트의 실제 Electron 검사와 기존 찾기·셀 서식 흐름을 통과했다. Mac 화면은 잠겨 있어 OS 창 전환 검사는 제외했으며 셀 서식의 나머지 검사와 파일 저장 검사는 통과했다.
- XLOOKUP 첫 인수 생략이 0으로 처리돼 실제 빈 셀보다 숫자 0을 선택하는 사례를 재현했다. [Microsoft 규칙](https://support.microsoft.com/en-us/excel/functions/xlookup-function)에 따른 물리적 빈 셀 검색을 일반/전체 행열 경로에서 보강한다. 실제 Excel의 빈 문자열·오류·이진 검색 전체 조합은 검증하지 않았다.
- LibreOffice 26.8의 캐시를 의도적으로 틀리게 넣은 격리 비교에서 물리적 빈칸/0과 빈 문자열의 차이를 확인했다. 일부 빈 문자열 조합은 엔진 간 차이가 남아 실제 Excel 대조 대기로 유지하며 이를 Excel 정답률에 합산하지 않는다.
- [Excel 찾기/바꾸기](https://support.microsoft.com/en-gb/excel/get-started/find-or-replace-text-and-numbers-on-a-worksheet?nochrome=true), [Range.Replace 조건](https://learn.microsoft.com/en-us/office/vba/api/excel.range.replace), [피벗 구조](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-pivottables)를 참고했다. 지원 범위를 넘어서는 기능의 새 Excel 실행 검증을 했다는 의미는 아니다.

### 5차: 피벗 서식과 필터 행 위치

- 기존 새로 고침은 셀 서식·크기를 모두 새로 만들었다. 항목·머리글별 서식과 크기 유지 옵션을 추가하고, 실제 Electron에서 사용자 지정 숫자 코드·색·열 너비→원본 수정→새로 고침→실행 취소/다시 실행→옵션 해제와 실행 취소→XLSX 저장·재열기를 점검한다.
- 보고서 필터 때문에 XLSX에서 내려간 행 위치를 가져올 때 셀/행 기본 서식과 조건부 규칙 범위도 함께 되돌린다. 3자리 숫자 코드에 생성 기본값 2자리가 다시 섞이던 후속 저장 결함을 왕복 검사에서 발견해 수정했다. 필터 있는 XLSX의 서식·메모·행열 크기·조건부 범위를 3회 왕복하는 단위 검사를 추가했다.
- 같은 앱 피벗의 바깥에 추가한 F10 셀이 가져오기에서 지워지던 사례를 재현했다. 이 경우 원래 배치를 보존하고 F10은 계속 편집하게 한다. 외부 캡션·스타일 변경도 보존한다. 메모를 지울 수 있는 필터 갱신은 전체 취소한다.
- 현재 전체 단위는 **448개 중 447개 통과·Windows 전용 1개 제외**다. 이전 피벗 수정 `1738630`의 [전체 편집 CI](https://github.com/beaur8-prog/sheet-studio/actions/runs/41950633814)는 Mac·Windows·Ubuntu에서 통과했다. 이후 변경은 별도 전체 재검증 대상으로 유지한다.

### 6차: 표의 오른쪽 열 추가와 범위 확장

- 기존 코드는 아래 행 추가만 구현했고 표 관리에서도 열 수 변경을 거부했다. 오른쪽의 기존 표 행에 입력한 연속 열을 포함하고 명시적 오른쪽 범위 확장을 추가했다. 넓은 아래쪽 붙여넣기는 기존 열 폭으로만 행을 확장한다. [Microsoft의 확장 규칙](https://support.microsoft.com/en-us/excel/resize-a-table-by-adding-or-removing-rows-and-columns-in-excel)을 기준으로 구현했으며 머리글 패턴 추론은 포함하지 않는다.
- 새 머리글 이름·열 ID·계산 열·새 열 필터를 기존 모델에 연결한다. 다른 표·병합·배열·보호·요약 행의 기존 자료 충돌을 확인한다. 새 요약 위치에 자료가 있으면 명시적 크기 변경 전체를 거부한다. 표 크기 창의 열 축소는 여전히 행·열 삭제 명령으로 안내한다.
- 관련 단위 17개와 실제 Electron의 중복 머리글 입력→열 추가→실행 취소/다시 실행→새 계산 열→명시적 확장→병합 충돌 유지→새 열 필터→XLSX 저장/재열기→복구를 통과했다. 기존 표 편집 전체 시나리오도 재실행했다. 사용자 클립보드는 쓰지 않았으며 붙여넣기의 자료 계획은 단위·CI에서 별도 검사한다.
