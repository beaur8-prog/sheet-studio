| 출시 판정 | 뷰어와 편집판의 필수 검사 범위가 모호함 | 단계별 필수 시나리오와 실제 기기 검증 조건을 구체화 |

## 1. 권장 방향과 패키징 가능성

**스마트폰에서는 문서를 안전하게 읽는 경험을 먼저 완성하고, 태블릿에서는 같은 문서를 키보드와 터치로 편집할 수 있게 한다.** 파일 해석·수식·저장·표·차트 모델은 공통으로 유지하고 화면 구성과 입력 방법을 나눈다.

1. 외부에서 연 문서는 보기 모드로 시작한다. 편집은 사용자가 **편집**을 눌러 전환한다.
2. 화면 크기와 입력 장치를 별개로 판단한다. 좁은 창에서도 키보드를 쓸 수 있고, 넓은 화면에서도 손가락으로 조작할 수 있어야 한다.
3. 기존 데스크톱 동작을 유지하면서 모바일 화면과 입력 처리를 단계적으로 추가한다.
4. 작은 버튼 확대, 선택·스크롤 분리, 키보드 호출 제어를 첫 구현 대상으로 삼는다.

**안드로이드 패키지는 만들 수 있다.** 다만 현재 Electron 패키지를 APK로 바꾸는 방식은 아니다. Electron 공식 배포 대상은 Windows·macOS·Linux다. 웹 렌더러를 Android WebView 기반 호스트에 넣고, 파일·공유·클립보드·생명주기를 연결하는 방식이 후보이며 Capacitor가 그중 하나다. 현재 수식 엔진과 Worker·저장 경로의 실제 재사용 가능성은 먼저 작은 실행 실험으로 확인한다. 플랫폼 선택은 그 결과로 확정한다. [Electron 플랫폼 지원][electron] · [Capacitor Android][capacitor]

Android 호스트의 최소 실행 실험은 아래 UI 계획의 의존 조건이며, 이 문서가 패키징 구현을 시작했다는 뜻은 아니다. Electron의 파일 창·IPC·업데이트·Windows Excel/VBA 연결은 Android에서 그대로 사용할 수 없다. 최소 Android/WebView 버전과 모바일 문서 한도도 아직 확정하지 않는다.

## 2. 현재 UI에서 확인한 개선 지점

아래는 소스에서 확인한 사실이다. 스마트폰에서 실제 문제가 발생했다는 재현 결과와 구분한다.

| 부분 | 현재 구현 | 모바일에서 필요한 변경 |
|---|---|---|
| 화면 골격 | `styles.css`의 제목 39px·탭 34px·리본 109px·수식 입력 39px·시트 35px·상태 26px. 기본 합계 약 **282 CSS px** | 보기 모드의 상·하단 메뉴로 재구성하고 격자 공간 확보 |
| 도구 버튼 | `.small-btn` 23px 높이, `.icon-btn` 28px, 색 견본 36×36px | 터치용 크기·간격·텍스트 이름 제공 |
| 셀·개체 손잡이 | 채우기 7×7px, 차트 크기 조절 11×11px, 필터 화살표 19×19px | 큰 조작 영역과 메뉴를 통한 대체 명령 제공 |
| 입력 포커스 | `focusGrid()`가 차트 시트 외에는 입력용 `#editor`를 포커스함. 대기 입력창을 투명하게 유지 | 탐색 포커스와 편집 입력창 포커스를 분리. 보기 중 키보드 호출 방지 |
| 셀 선택 | `pointerdown` 직후 선택·드래그 시작. 더블클릭/일부 진입은 마우스 이벤트 사용 | 손가락 스크롤·탭·범위 선택·길게 누르기의 판정 분리 |
| 차트·행열 조절 | 이미 Pointer Events와 일부 취소 처리가 있음. 차트는 `touch-action:none`, 이동 문턱은 3px, 행열은 2px | 기존 처리를 재사용하되 보기 모드 팬·핀치와 충돌하지 않도록 조정 |
| 대화상자 | 일부 차트 창은 `100dvh`·고정 버튼을 지원. 다른 창은 고정 폭/2열 구성, 루트는 `100vh` | 키보드가 열린 유효 높이, 작은 창, 긴 설명·확대 글꼴에 공통 대응 |
| 화면 적응 | 950/850/750/700/600/540/500px 등 개별 CSS 규칙 존재 | 공통 레이아웃 기준을 만들고 기존 개별 규칙의 충돌 정리 |
| 키보드·IME | 방향키·Tab·Enter·단축키·조합 보호가 이미 있음 | Android IME 이벤트 순서와 외부 키보드 연결·해제를 추가 검증 |
| OS 연동 | `window.desktop`과 Electron preload의 파일·클립보드·종료·업데이트 기능 | 공통 호스트 인터페이스와 Android 기능별 지원 여부 분리 |
| 문서 처리 | 가상 격자·해석/계산 Worker·IndexedDB 복구 존재 | Android WebView·메모리·중단/재생성 조건에서 재검증 |
| 시트 이동·변경 기록 | `switchSheet()`가 `book.activeSheetId`를 바꾸고 `changed()` 호출 | 보기의 활성 시트·스크롤을 문서 변경/복구 저장과 분리 |
| 필터·계산 연결 | `applyFilters()`가 숨김 행을 기록하고 계산·차트가 이를 참조 | 임시 보기 조건을 원본 필터/계산 컨텍스트에 섞지 않음 |
| 복구 저장 구조 | `recovery-store.mjs`의 현재/직전 스냅샷과 `startBlank()` 흐름 | 다른 파일 열람이나 빈 문서 시작이 미저장 편집 복구본을 밀어내지 않도록 변경 |

## 3. Excel 모바일에서 참고할 흐름

Microsoft 공식 Android 터치 안내는 한 손가락 스크롤, 두 손가락 확대/축소, 셀 탭 선택, 선택 손잡이로 범위 확장, 더블 탭/수식 입력줄을 통한 편집, 길게 눌러 셀 메뉴 열기를 설명한다. 본 앱에도 이 구분을 도입하되 보기 모드에서는 편집 진입을 별도로 제한한다. [Excel Android 터치 가이드][ms-touch]

공식 리본 안내는 휴대폰의 편집 아이콘을 통한 리본 펼치기와 태블릿의 리본 접기를 설명한다. 작은 화면에서 편집 도구를 필요할 때 여는 구성에 참고한다. [모바일 리본 표시·숨기기][ms-ribbon]

공식 Android 단축키 항목에는 외부 키보드의 방향키·Tab, 저장·복사·붙여넣기·실행 취소·찾기 등이 있다. 태블릿 키보드는 별도 부가 기능이 아니라 기본 입력 경로로 다룬다. 아래 단축키 전체 중 F2·참조 선택 등 확장 동작은 Sheet Studio의 제안이며 모두 Excel Android의 공식 지원 목록이라는 뜻은 아니다. [Excel 단축키의 Android 항목][ms-keys]

**보기 모드 기본 진입, 단계별 출시 범위, 메뉴 배치와 수치는 Sheet Studio의 설계 제안이다.** 현재 Excel Android 화면의 실측 복제나 기능 동등성 판정이 아니다.

## 4. 화면 크기와 입력 방식

Android 공식 창 크기 분류의 600dp·840dp 경계를 출발점으로 삼는다. 기기 이름 대신 **앱에 실제로 주어진 창**을 기준으로 하며 회전·분할 화면·폴더블·창 크기 변경에 반응한다. 높이도 확인하여 가로 휴대폰에 넓은 2열 화면을 무조건 적용하지 않는다. [Android 창 크기 분류][android-window]

| 사용 가능한 창 | 기본 구성 | 편집 도구 |
|---|---|---|
| 좁음: 폭 <600dp | 한 화면의 격자, 하단 주요 명령, 필요할 때 전체 화면 패널 | 글꼴·색·테두리·정렬 등을 단계별 패널로 열기 |
| 중간: 600≤폭<840dp | 격자 + 접는 도구막대. 상세 패널은 필요 시 격자 위로 열기 | 자주 쓰는 명령 한 줄, 나머지는 그룹 메뉴 |
| 넓음: 폭≥840dp | 접을 수 있는 리본과 격자. 공간이 충분할 때만 상세 패널 병렬 배치 | 터치 버튼 크기를 유지한 리본, 키보드 탐색 |
| 넓지만 낮음 | 상단 도구를 한 줄로 줄이고 격자 우선 | 수식·속성은 전체 화면 또는 단일 패널로 전환 |

600/840은 네이티브 **dp** 기준의 설계 참고값이다. 웹 미리 보기의 CSS px와 물리 픽셀·`devicePixelRatio`를 같은 단위로 단정하지 않는다. 최초 호스트 실험에서 WebView의 viewport·네이티브 창/inset·확대 설정을 대조하고 CSS 기준을 확정한다.

- 기본 상태는 `창 크기 × 보기/편집 모드 × 터치/마우스 입력 × IME 상태`의 조합으로 관리한다.
- `pointer:coarse`, `any-pointer`, 실제 Pointer Event를 함께 사용한다. 기기명이나 User-Agent만으로 분기하지 않는다.
- 외부 키보드는 포인터 미디어 쿼리로 감지할 수 없다. 호스트의 연결 정보가 있으면 참고하고, 실제 키 입력과 사용자 설정을 함께 사용한다.
- 키보드 연결, 마우스 클릭, 회전 때문에 보기→편집으로 자동 전환하지 않는다. 입력 장치를 바꾸어도 문서·선택·실행 취소·편집 초안을 유지한다.
- IME가 올라와 공간이 줄어든 상태와 실제 창 크기 변경을 구분한다. 키보드 애니메이션 중 레이아웃이 반복해서 바뀌지 않게 한다.
- 호스트가 상태·탐색·창 제목 표시줄, 화면 잘림 영역, IME의 inset을 전달한다. 웹 레이아웃은 이미 소비한 inset을 중복 반영하지 않는다. 시스템 뒤로/홈 제스처 영역과 선택 손잡이·자동 스크롤이 충돌하면 손잡이의 조작 위치를 안쪽으로 보정하고 주소 입력을 대안으로 둔다. 제스처 탐색과 3버튼 탐색을 모두 검사한다. [Android 화면 가장자리·inset 처리][android-insets]

## 5. 스마트폰의 보기 중심 화면

### 5.1 첫 화면과 문서 열기

파일 요청 없는 새 실행은 기존 정책대로 **빈 통합 문서**를 보여준다. 최근 파일은 열기 패널에서 고르며 이전 파일을 자동으로 다시 열지 않는다. 이미 실행 중인 작업으로 복귀하거나 화면 회전으로 Activity가 재생성된 경우에는 현재 세션을 유지한다. 파일 앱의 ‘연결 프로그램’이나 다른 앱의 공유에서 파일을 받았을 때는 요청한 문서를 보기 모드로 연다. 사용자가 ‘새 문서’를 명시적으로 선택하면 편집을 시작할 수 있다. 미저장 복구본의 확인 경로는 빈 화면에서도 제공한다.

보기 모드의 개념 배치는 다음과 같다. 괄호는 고정 UI 문구가 아닌 역할을 표시한다.

```text
상단: 뒤로 | 문서 이름 · 보기 모드 | 공유 | 더보기
본문: 행·열 머리글 + 스크롤·확대 가능한 격자
선택: 셀 주소·표시 값 요약 → 전체 값/수식 상세 열기
하단: 찾기 | 시트 | 보기 설정 | 편집
```

- 긴 파일명은 한 줄로 줄이고 탭하면 전체 이름·파일 정보를 보여준다. 버전·저장 위치·호환성 상세는 더보기에서 확인한다.
- 큰 제목줄·리본·상태줄을 동시에 유지하지 않는다. 하단의 **시트**를 누르면 시트 목록을 열어 긴 이름·많은 시트를 다룬다.
- **찾기**는 현재 시트/통합 문서, 이전/다음, 결과 위치를 제공한다. **셀 주소로 이동**과 정의된 이름 이동도 검색 패널에 둔다.
- 선택 셀의 긴 텍스트·여러 줄·수식·오류·메모를 읽기 전용 상세 패널에서 확인한다. 보호된 숨김 수식을 이 패널로 노출하지 않는다.
- 보기 설정에는 확대/축소, 선택 영역/현재 표 너비 맞춤, 눈금선·머리글·틀 고정 표시를 둔다. 한도까지 빈 격자를 맞추거나 글자를 읽지 못할 정도로 자동 축소하지 않는다.
- 차트는 탭 후 **크게 보기**로 열어 범례·값·자료 표를 읽는다. 원래 차트의 위치와 크기는 바꾸지 않는다. 보존 전용 개체·저장된 계산값의 표시 근거도 알린다.
- 저장·복구 상태는 한 곳에 간단히 표시한다. 호환성 경고는 사라지는 토스트 하나에만 의존하지 않고 다시 열 수 있게 한다.

### 5.2 보기 모드의 문서 불변 규칙

| 동작 | 보기 모드 정책 |
|---|---|
| 셀·범위 선택, 이동, 확대, 값 복사 | 허용. 입력 키보드를 띄우거나 문서를 수정하지 않음. 찾기/주소 입력은 필요할 때 키보드 사용 |
| 시트 전환·임시 틀 고정 표시·보기 설정 | 세션의 보기 상태로 관리. 원본 문서 설정을 저장하지 않음 |
| 임시 행 표시 | **보기에서 행 좁혀 보기**. 원래 숨김·필터를 존중하고 5.3절의 계산 범위 안내 제공 |
| 정렬·숨김 해제·피벗 새로 고침 | 1차 보기 모드에서는 제공하지 않음. 원본 변경이 필요한 작업은 편집에서 수행 |
| 셀 입력·붙여넣기·잘라내기·삭제·서식·채우기·차트 이동 | 워크시트 변경 경로에서 차단. 찾기 입력창의 타이핑·붙여넣기와 상세 값 복사는 허용 |
| 공유 | 편집 이력이 없는 열람은 열 때 확보한 원본. 편집 후 보기로 돌아온 경우는 5.4절에 따라 편집본 공유 |

`readonly` CSS나 버튼 숨김만으로 구현하지 않는다. 다음 상태를 분리하고 문서 변경 명령의 공통 진입점에 모드/권한 검사를 둔다.

| 상태 | 책임 |
|---|---|
| 편집 가능한 문서 모델 | 셀·서식·개체·원래 필터·저장되는 보기 설정, 변경 기록·dirty |
| 계산·렌더링 캐시 | 표시와 조회에 필요한 파생 결과. 사용자 편집으로 기록하지 않음 |
| 보기 세션 | 활성 시트·선택·시트별 스크롤·확대·임시 틀 고정·임시 행 표시 |
| 파일 식별·원본 스냅샷 | 열린 파일의 ID·URI 권한·원본 바이트 또는 검증 가능한 파일 버전 |
| 미확정 초안 | 셀 입력·IME 조합·패널 미리 보기. 확인 전 문서에 반영하지 않음 |

현재 `switchSheet()`는 `book.activeSheetId`를 변경하고 `changed()`를 호출하며, 변경 기록 시스템은 메타데이터 수정을 dirty로 추적한다. 보기에서는 `sheet()` 등 활성 시트 조회도 세션 상태를 읽도록 바꾼다. `changed()`만 막으면 화면 이동이나 복구 동기화가 어긋날 수 있으므로 호출 경로를 함께 분리한다. [주 화면](../src/main.mjs) · [변경 기록](../src/history.mjs)

Worker의 열기·조회·계산 결과를 보기 모드라는 이유로 전부 거부하지 않는다. 요청 종류, 문서 ID·리비전·모드 전환 세대로 결과를 구분한다. 파생 캐시는 현재 세션에만 적용하고, 편집 적용 결과는 유효한 요청과 편집 권한을 확인한다. 파일 교체나 모드 전환 전의 지연 결과가 새 문서를 덮어쓰지 않게 한다.

불변 검사는 열기 직후 정규화된 문서를 기준으로 **편집 가능한 필드·변경 기록·dirty 상태와 원본 바이트**를 비교한다. 정상적으로 갱신되는 계산 캐시를 포함한 런타임 객체 전체 직렬화와 혼동하지 않는다.

### 5.3 보기에서 행 좁혀 보기와 합계의 의미

초기 뷰어의 필수 기능에서 분리한 **G2b 선택 기능**이다. 기존 필터 함수를 그대로 호출하지 않고 현재 보이는 행에 임시 조건을 겹친다.

- 원래 필터와 수동 숨김 행은 계속 숨긴다. 임시 조건 해제는 원래 표시 상태로 돌아가며 원본의 숨김을 해제하지 않는다.
- `sheet.autoFilter`·표 필터 정의·숨김 행·셀 순서를 변경하지 않는다. `SUBTOTAL` 등 셀 수식, 차트의 데이터 범위/포인트와 보존 피벗 결과도 이 임시 조건으로 재계산하지 않는다.
- **‘보기용 필터 · 합계/차트는 원래 문서 기준’**을 조건이 적용된 동안 표시한다. 선택 요약을 제공한다면 ‘현재 보이는 선택 셀 합계’라고 범위를 명시한다.
- 예: 10·20·30이 모두 보이고 합계가 60인 표에서 30만 표시해도 문서 합계는 60이다. 보이는 선택 셀 요약은 30이며, 조건 해제 후 세 행이 다시 보인다.
- 편집 전환 시 임시 조건은 해제하고 안내한다. 영구 필터에 자동 반영하지 않는다. Excel처럼 합계·차트까지 반응하는 읽기 전용 분석은 별도 파생 계산 컨텍스트와 검사가 준비된 뒤 확장한다.

근거: 현재 [필터 적용](../src/filters.mjs)은 `hiddenRows`를 바꾸고, [공통 필터 행 조회](../src/table-schema.mjs)를 [수식 엔진](../src/engine.mjs)과 [차트 모델](../src/chart-model.mjs)이 함께 사용한다. 따라서 임시 표시와 문서 필터를 분리하지 않으면 단순 열람이 계산 결과까지 바꿀 수 있다.

### 5.4 편집 후 보기 전환·공유

**보기/편집 모드, 저장되지 않은 변경, 원본 쓰기 권한은 별개의 상태다.** 보기로 돌아간다는 이유로 확정한 변경·dirty·실행 취소 기록을 지우거나 원본을 다시 읽지 않는다.

1. 셀 조합/입력이나 패널 초안이 남으면 확인·취소·계속 편집 중 하나로 해결한 뒤 모드를 바꾼다. 유효성 오류를 무시하거나 키보드 닫힘만으로 확정하지 않는다.
2. 저장 전 변경이 있으면 보기 화면에도 **‘저장 전 변경 있음’**을 표시한다. 나가기·추가 파일 열기의 보호는 편집 모드와 같다.
3. 편집한 세션의 공유는 **편집본 공유**를 기본으로 한다. 현재 확정된 문서를 임시 파일로 내보내고 검증한 후 공유하며, 공유 성공은 원본 저장 완료를 뜻하지 않는다. CSV 등 손실 가능한 형식은 기존 호환성 안내를 재사용한다.
4. **변경 전 원본 공유**는 열 때의 원본을 확보한 경우에만 별도 선택지로 제공한다. URI를 다시 읽었다면 버전/해시를 대조한다. 외부에서 바뀐 파일을 열린 시점의 원본이라고 표시하지 않는다. 미편집 열람에서도 같은 원칙을 적용한다.
5. 내보내기·공유 실패/취소는 문서·초안·dirty 상태를 유지한다. 원본 쓰기 권한만 없는 지원 문서는 **사본으로 편집**할 수 있다. 형식상 편집을 지원하지 않는 문서와 구분한다.

## 6. 터치 동작과 작은 메뉴

### 6.1 조작 크기

Android의 터치 대상 권장 최소 **48×48dp**를 메뉴·버튼·손잡이의 설계 기준으로 삼는다. 웹에서는 우선 48 CSS px 토큰을 사용하되 네이티브 dp 대응과 글꼴 확대를 실제 기기에서 확인한다. 겹치는 투명 영역으로 옆 셀이나 다른 명령을 가리지 않는다. [Android 접근성 기본값][android-touch]

- 셀 자체를 모두 48px 높이로 바꾸지는 않는다. 원래 행 높이·열 너비·서식·인쇄 배치는 보존한다.
- 작은 셀은 확대, 셀 상세, 주소 이동, 선택 손잡이를 함께 사용해 조작한다.
- 색 견본은 화면 폭에 맞춰 열 수를 줄이고 큰 선택 영역·색 이름·선택 표시를 제공한다.
- 필터 화살표 19px를 단순 확대해 머리글을 덮지 않는다. 머리글 선택 후 큰 **이 열 필터** 명령을 기본 대안으로 제공한다.
- 아이콘에 접근 가능한 이름과 필요한 텍스트를 붙인다. 터치에서는 hover 설명에 의존하지 않는다.

### 6.2 제스처 우선순위

브라우저가 팬/확대를 시작하면 `pointercancel`로 앱의 이벤트 흐름이 끊길 수 있고, 진행 중 `touch-action`을 바꿔 이미 시작된 제스처를 되찾을 수 없다. 따라서 **네이티브 스크롤과 앱 핀치를 아무 조치 없이 혼합하는 설계는 채택하지 않는다.** [W3C Pointer Events의 제스처 처리 규칙][pointer-events]

G0에서 다음 중 하나를 검증해 선택한다. 초기 검토판은 A를 우선 실험하고, 격자 핀치가 필요하면 B의 비용과 접근성을 함께 확인한다.

| 방식 | 스크롤·확대 처리 | 채택 조건 |
|---|---|---|
| A: 브라우저 중심 | 브라우저가 팬을 처리. 시트 배율은 큰 ± 버튼·너비 맞춤으로 제공. 브라우저 페이지 핀치는 호스트에서 지원·검증된 경우 별도 동작으로 유지 | 브라우저 페이지 확대와 시트 배율을 중복 적용하지 않으며 선택 좌표·고정 영역을 실제 기기에서 검증. 페이지 핀치 미지원 시 시트 확대 버튼 제공 |
| B: 격자 제스처를 앱이 처리 | 한정된 격자 입력 영역에 미리 `touch-action:none`을 설정하고 앱이 팬·핀치를 모두 담당 | 관성 스크롤·경계·자동 스크롤·취소·핀치 중심 유지까지 구현/측정. 메뉴·입력창·시스템 접근성 확대는 별도 경로로 유지 |

핸들처럼 앱이 드래그를 소유하는 작은 영역은 A에서도 사전에 정책을 정한다. 문서 전체와 모든 입력창에 일괄적으로 제스처를 차단하지 않는다. 선택한 방식·호스트/WebView 버전·핀치 지원 범위를 검토 결과에 기록한다.

| 입력 | 보기 모드 | 편집 모드 |
|---|---|---|
| 셀 한 번 탭 | 셀 선택·값 요약 | 셀 선택. 입력은 아직 시작하지 않음 |
| 손가락 한 개로 격자 밀기 | 스크롤 | 스크롤. 셀 위에서 시작해도 범위 선택으로 오인하지 않음 |
| 손가락 두 개 | A는 검증된 페이지 확대, B는 격자 확대. 시트 확대 버튼도 항상 제공 | 같은 확대 정책. 편집 초안은 보존하고 미확정 선택/채우기 조작은 정리 |
| 선택 셀 상세/편집 버튼 | 전체 내용 읽기 | 셀 입력창 열기 |
| 셀 더블 탭 | 상세 보기 | 셀 편집. 앱 더블 탭과 시스템 확대의 충돌을 실제 기기로 확인 |
| 선택 손잡이 끌기 | 범위 선택 | 범위 선택. 선택 손잡이와 채우기 손잡이는 구별 |
| 셀 길게 누르기 | 복사·상세 등 보기 메뉴 | 복사·붙여넣기·셀 서식 등 선택 대상 메뉴 |
| 행·열 머리글 | 행·열 선택 | 선택 후 메뉴에서 크기/삽입/삭제/자동 맞춤 |
| 차트 위 밀기 | 문서 스크롤 | 기본은 스크롤. **개체 배치 편집**을 명시적으로 켠 경우에만 이동 |

앱이 소유하는 터치 상태를 `대기 → 탭 후보 → 스크롤 / 길게 누르기 / 손잡이 드래그 / 핀치`로 구분한다. A에서는 브라우저가 처리하는 스크롤/핀치를 앱이 재현하지 않는다. 이동 허용 거리·길게 누르기 시간은 조정 가능한 값으로 두고 Android 실측으로 확정한다. 마우스의 기존 드래그 선택·우클릭과 터치 동작은 각각 유지한다.

- `pointercancel`, 두 번째 손가락, 창 포커스 상실, 회전 시 진행 중인 제스처를 정리한다. 미확정 차트 이동·행열 조절은 원래 값으로 돌린다.
- 앱이 담당하는 드래그는 안정적인 격자 부모에 포인터를 캡처하고 가상화로 사라지는 셀 DOM에 의존하지 않는다. 포인터 캡처 자체가 브라우저 팬을 막는다고 가정하지 않는다.
- B의 핀치는 중심 아래의 셀 위치를 유지한다. 모든 확대 방식에서 셀 선택·고정 영역·차트 좌표가 일치해야 한다.
- 한 손가락 스크롤 중 두 번째 손가락 추가, 차트 위 제스처, 취소 뒤 재탭을 검사한다. 길게 누른 앱 메뉴와 브라우저 텍스트 선택, 터치 뒤 합성된 마우스 이벤트가 중복 실행되지 않게 한다. 셀 상세의 정상 텍스트 복사는 유지한다.
- 범위 끝까지 이동할 때 자동 스크롤을 지원한다. 큰 범위는 주소 입력으로도 선택할 수 있어야 한다.
- 채우기와 행열 크기 조절은 별도 큰 메뉴로도 수행한다. 채우기 드래그는 스마트폰 1차 출시의 필수 조건에서 제외하고 후속으로 둔다.

## 7. 편집 화면·IME·대화상자

### 7.1 셀 입력

1. **편집 전환**을 눌러도 바로 소프트 키보드를 띄우지 않는다.
2. 터치 탐색에서는 셀 편집 버튼·더블 탭·수식 입력줄 선택 때 입력창을 포커스한다. 외부 키보드의 바로 입력 대기는 7.3절의 별도 포커스 경로를 사용한다.
3. 좁은 화면에서는 편집 중인 주소와 수식/원문 입력창을 키보드 위에 보여준다. 여러 줄 펼치기, **확인·취소**, 필요 시 다음 셀 이동을 제공한다.
4. 확인에 성공하면 같은 셀을 유지한다. ‘다음 셀’ 명령은 아래 셀로 이동하며 키보드의 Enter/Tab은 8절의 규칙을 따른다.
5. 오류·유효성 불일치는 입력창과 설명을 유지하여 수정 후 다시 확인할 수 있게 한다. 작은 토스트만 남기고 입력을 버리지 않는다.

Android IME의 조합·자동 교정·음성 입력·붙여넣기는 키 누름 하나와 대응하지 않을 수 있다. 기존 `beforeinput`·`input`·composition 처리를 유지하고 `keydown`만으로 글자를 재구성하지 않는다. Gboard·삼성 키보드의 한글 첫 글자, 받침 수정, 후보 선택, 조합 중 셀 이동을 실제 기기로 검사한다. 기존 ‘방향키 이동 뒤 첫 한글이 영어로 입력되는 문제’도 필수 회귀에 포함한다.

네이티브 IME inset과 `visualViewport` 등 웹 측 가용 영역을 대조한다. 편집창·확인 버튼·선택 셀이 키보드나 시스템 탐색 영역 아래로 가려지지 않게 하며, 같은 inset을 네이티브와 CSS에서 두 번 빼지 않는다. [Android 입력기 표시 처리][android-ime]

### 7.2 메뉴·패널 공통 규칙

| UI | 좁은 화면 | 태블릿/넓은 화면 |
|---|---|---|
| 셀 문맥 메뉴 | 큰 행의 하단 패널. 자주 쓰는 명령 우선, 더보기로 확장 | 포인터 위치 메뉴 또는 선택 옆 패널. 화면 경계 보정 |
| 셀 서식 | 숫자/글꼴/채우기/테두리/정렬 목록 → 한 항목 편집 → 확인 | 공간에 따라 2열 또는 측면 패널 |
| 글자색·배경색 | 적용 범위·샘플·색 선택·**적용/취소** | 같은 동작, 넓은 색 견본 배치 |
| 테두리 | 전체/바깥/안쪽/없음의 큰 버튼과 개별 선 미리 보기 | 개별 선 설정을 함께 제공 |
| 필터 | 전체 화면 또는 충분히 높은 패널, 값 검색·선택·적용 고정 | 넓은 팝업/측면 패널 |
| 함수 찾기 | 함수 목록 → 상세 설명/인수로 이동 | 기존 목록·상세의 병렬 구성을 재사용 |
| 차트·피벗·입력 규칙 편집 | 후속 고급 편집. 단계별 화면으로 분리 | 기존 미리 보기·필드 편집을 접는 구역으로 재배치 |

- 패널을 열기 전 시트 ID·문서 ID·선택 범위를 기록하고 **적용**까지 유지한다. 메뉴를 터치해도 선택을 잃지 않는다.
- 대상 문서가 바뀌면 이전 패널의 적용을 거부한다. 변경은 한 번의 실행 취소로 묶는다.
- 미리 보기는 원본에 바로 쓰지 않는다. 취소·바깥 터치·뒤로 가기에서도 미확정 변경을 남기지 않는다. 긴 초안의 폐기는 필요할 때만 확인한다.
- 패널 본문만 스크롤하고 확인/취소는 도달 가능한 위치에 둔다. 닫은 뒤 **선택 포커스**로 돌아가며 편집 의도 없이 IME를 다시 띄우지 않는다.
- 시스템 뒤로 가기는 우선 시스템 IME 닫힘을 존중한다. 앱은 이후 열린 메뉴/패널 → 미확정 셀 편집 → 문서 나가기 순서로 처리한다. 키보드가 닫힌 것만으로 입력을 자동 저장·폐기하지 않는다.

### 7.3 탐색 포커스와 외부 키보드의 첫 입력

현재 `focusGrid()`가 투명한 `#editor`를 포커스하는 것은 `beforeinput`·composition으로 첫 글자부터 받는 경로와 연결되어 있다. 이 입력창을 단순히 비편집 요소로 바꾸고 첫 `keydown` 뒤에 다시 포커스하면 한글 첫 조합을 잃을 수 있다. 다음 상태를 나누어 검증한다. [입력 경로](../src/main.mjs)

| 상태 | 포커스·입력 정책 |
|---|---|
| 보기에서 격자 탐색 | 비편집 격자에 탐색 포커스. 워크시트 문자 입력 차단. 찾기/주소 입력창은 정상적으로 입력 가능 |
| 편집에서 터치 탐색 | 셀을 선택만 한 동안은 탐색 포커스. 명시적 입력 명령으로 입력창 활성화 |
| 편집에서 외부 키보드 바로 입력 대기 | 첫 조합 이벤트를 받을 편집 가능 대상을 준비. 호스트의 입력기 제어와 함께 검증하며 글자를 `keydown`으로 재구성하지 않음 |
| 셀 문자 편집·수식 입력 | 실제 입력창에 포커스, 조합·커서·선택 유지. 기존 바로 입력/F2/참조 선택 상태를 구별 |

소프트 키보드의 불필요한 표시를 막는 것과 IME 수신 자체를 끄는 것을 구분한다. 모든 상태에 `inputmode=none`을 지정하거나 blur를 반복하는 방식은 채택하지 않는다. 키보드 연결/분리와 메뉴 복귀 중 조합·초안을 유지한다. 하드웨어 키보드 사용 시 소프트 입력창의 표시도 사용자 설정을 포함해 실제 호스트에서 확인한다. [Android 입력기 표시 처리][android-ime]

G0에서 **방향키 이동 직후 첫 한글이 온전히 들어오는지** 확인한다. 해결 전 검토판에는 명시적 편집 버튼/F2를 임시 경로로 제공할 수 있지만, 이를 외부 키보드 바로 입력 지원 완료로 표시하지 않는다. 바로 입력을 포함한 G4 완료에는 해당 회귀 통과가 필수다.

## 8. 태블릿과 외부 키보드·마우스

태블릿은 보기 모드에서 격자를 넓게 쓰고, 편집 전환 후 접는 리본을 제공한다. 키보드를 연결해도 터치 버튼은 유지한다. 마우스 우클릭·휠·드래그 선택과 손가락 스크롤을 한 세션에서 섞어 쓸 수 있어야 한다. [Android 키보드 탐색][android-keys] · [큰 화면의 입력 호환성][android-input]

| 입력 | 격자 탐색 | 셀 텍스트/수식 편집 | 메뉴·대화상자 |
|---|---|---|---|
| 방향키 | 셀 이동. Shift로 범위 확장 | 바로 입력 모드는 확정 후 셀 이동, F2/더블 탭/수식줄의 문자 편집은 커서 이동. 수식 참조 선택은 별도 모드 | 메뉴 항목/선택 옵션 이동 |
| Enter / Shift+Enter | 보기에서는 Enter로 상세 열기. 편집에서는 아래/위로 이동 | 조합이 끝난 입력을 확인 후 아래/위로 이동 | 선택한 명령 실행 |
| Tab / Shift+Tab | 오른쪽/왼쪽 셀. 보호·숨김·병합 규칙 유지 | 확인 후 다음/이전 셀 | 포커스 순서 이동·모달 안 순환 |
| F2 또는 문자 입력 | 편집 모드에서 셀 편집 시작 | 기존 편집 유지 | 입력 필드의 문자 입력 |
| Esc | 범위/메뉴 등 현재 작업 취소 | 수정 전 값으로 복귀 | 패널 닫기·적용하지 않음 |
| Ctrl+C / Ctrl+F | 값 복사 / 문서 찾기 | 텍스트 복사 / 입력 상태와 검색 명령 구분 | 해당 입력 필드/패널 문맥 유지 |
| Ctrl+V / X / Z / Y | 편집 모드에서만 붙여넣기·잘라내기·실행 취소/다시 실행 | 텍스트 편집 문맥 우선 | 입력 필드 동작 우선 |
| Ctrl+S | 편집본 저장. 초기 Android는 사본 저장 우선, 원본 쓰기는 9절의 검증 조건 충족 시 제공 | 확인 가능한 입력만 확정 후 저장 | 적용되지 않은 패널 초안을 임의 반영하지 않음 |

보기 모드에서는 문자 입력·삭제·붙여넣기가 문서를 바꾸지 않는다. 편집 전환 방법을 안내한다. OS가 소비한 키를 앱이 지원한 것처럼 표시하지 않는다. 단축키 안내에는 실제 Android 기기에서 검증한 항목을 구분한다.

선택 셀에 곧바로 입력한 상태와 F2/더블 탭으로 글자 커서를 편집하는 상태를 구별하는 기존 규칙을 유지한다. F2의 입력/문자 편집 전환, 수식 참조 선택, IME 조합 중 방향키도 각각 검사한다. ‘모바일이므로 방향키는 항상 글자 이동’으로 합치지 않는다.

- 격자에서 도구막대·시트 목록으로 나갈 수 있는 키보드 경로와 다시 돌아오는 경로를 제공한다. 키보드 사용자가 격자에 갇히지 않게 한다.
- 터치로 메뉴를 열었다가 키보드로 값을 고르고 다시 셀을 입력해도 원래 선택 범위를 유지한다.
- 키보드 연결/분리, 트랙패드 사용, 회전·분할 화면에서 문서·초안·스크롤 위치를 보존한다.
- 하드웨어 키보드가 없는데 ‘키보드 연결됨’ 상태를 가정해 IME를 계속 막지 않는다. 사용자가 화면 키보드를 열 수 있는 입력 버튼을 둔다.

### 9.1 파일 권한과 안전한 저장

Android 파일 선택은 Storage Access Framework가 제공하는 문서 URI와 권한을 기준으로 한다. `ACTION_OPEN_DOCUMENT`에서 제공된 지속 가능한 권한과 다른 앱 공유로 받은 임시 권한을 구분한다. 모든 URI에 영구 권한을 얻을 수 있다고 가정하지 않는다. 최근 파일은 유효한 권한을 확인하고 만료·이동·삭제 시 다시 선택하도록 안내한다. `ACTION_CREATE_DOCUMENT`는 기존 파일 덮어쓰기와 다르다. [Android 문서 접근][android-files]

- 원본 스냅샷이 필요한 임시 URI는 접근 가능한 동안 앱 전용 저장소에 확보한다. 큰 파일의 메모리 중복을 피하고 실패 시 복구/원본 공유 가능 여부를 정확히 표시한다.
- **첫 Android 편집판은 사본 저장을 기본으로 한다.** 일반적인 URI 쓰기 권한만으로 원자적 교체·롤백까지 보장된다고 가정하지 않는다. 파일 제공자가 허용하는 쓰기 방식, 실패 시 원본 보호, 백업/복구 전략을 검증한 조합에만 원본 저장을 제공한다.
- 원본을 먼저 비운 뒤 내보내기 성공을 기다리는 흐름은 채택하지 않는다. 앱 전용 임시 파일에 내보내기·형식 검증을 마친 뒤 대상에 쓴다. 대상 제공자의 완료 응답을 확인한 경우만 저장 성공으로 표시하며, 전송 중 실패한 사본은 불완전 파일임을 알리고 가능한 경우 정리한다. 원본 저장 조건이 부족하면 사본으로 유도한다.
- 원본 수정 시간·버전 또는 해시 등 사용 가능한 정보를 대조한다. 외부 변경이나 충돌 여부를 판정할 수 없으면 조용히 덮어쓰지 않고 사본 저장을 제안한다. 모든 제공자에 공통 버전 토큰이 있다고 가정하지 않는다.

확장자는 현재 앱이 실제로 지원하는 형식에 한정한다. 첫 모바일 편집 범위는 XLSX·CSV·TSV·앱 문서의 지원 경로부터 검증한다. XLSM은 초기에는 보기/원본 공유로 제한하고, VBA 실행과 매크로 유지 편집은 PC의 지원 흐름을 안내한다. 편집 불가 문서에서 지원하지 않는 개체를 임의 변환하거나 덮어쓰지 않는다.

원본 쓰기 불가와 앱에서 편집 불가를 구별해 표시한다. 저장 실패·권한 상실·외부 파일 변경이 발생하면 현재 편집본을 보존하고 재시도/사본 저장을 제공한다. 파일 앱에서 들어온 추가 열기 요청도 기존 문서의 저장·복구 보호를 거친다.

### 9.2 문서 복구와 실행 요청

현재 [복구 저장소](../src/recovery-store.mjs)는 현재/직전 스냅샷 중심이고, [문서 Worker](../src/workbook-worker.mjs)의 열기·초기화·flush 경로와 연결되어 있다. 보기로 여러 파일을 여는 동작을 그대로 연결하면 다른 문서의 편집 복구본을 밀어낼 수 있다. **보기 캐시/탐색 상태와 미저장 편집 복구를 분리**한다.

- 복구본은 문서 세션 ID로 식별한다. 저장 또는 명시적 폐기 전의 편집본은 새 문서 열람·빈 문서 초기화로 교체하지 않는다. 보관 개수/용량에 도달하면 저장·사본 내보내기·사용자가 고른 폐기 경로를 제공하고 미저장 자료를 자동 퇴출하지 않는다.
- 회전·일반 앱 전환·Activity 재생성은 기존 세션으로 돌아온다. 새 실행에서 이전 파일 자동 열기는 하지 않되, 완료된 복구본은 사용자가 선택해 되살릴 수 있게 한다.
- 파일 intent는 요청 ID와 처리 세대로 중복 소비를 막는다. 생명주기 복귀마다 같은 파일을 다시 import하지 않는다. 새 파일 요청은 현재 입력·패널·dirty 보호를 통과한 뒤 적용한다.
- 셀 초안과 마지막 확정 문서를 구별해 복구한다. 백그라운드 저장 완료 지점과 실패를 추적하며, 프로세스 강제 종료 순간의 OS 내부 조합 문자열까지 복구된다고 약속하지 않는다.
- WebView 저장 origin과 복구 스키마를 안정적으로 유지한다. 업데이트/스키마 이행 실패 시 기존 복구 자료를 먼저 지우지 않는다. 저장 공간 부족·복구 쓰기 실패를 테스트하고 상태를 사용자에게 알린다.

## 10. 보기 충실도·대용량·접근성

### 10.1 문서 표시와 성능

- 셀 줄바꿈·병합·숫자 형식·조건부 서식·틀 고정·숨김 상태를 기존 공통 엔진으로 표시한다. 화면 재배치 때문에 셀 서식·행 높이·차트 위치를 수정하지 않는다.
- UI는 Android에서 읽기 쉬운 시스템 글꼴을 사용한다. 문서에 지정된 글꼴이 기기에 없을 때의 대체 글꼴·한글 줄바꿈·숫자 너비·차트 레이블 잘림을 검사하고, 대체 표시를 문서의 원래 글꼴 설정에 덮어쓰지 않는다. 대체 사용 여부는 문서 정보에서 확인할 수 있게 한다.
- 미지원 수식의 저장값, 오래된 캐시, 원본 보존 차트·피벗의 제한을 열람 중에도 확인할 수 있게 한다. 보기 모드에서 원본과 다른 계산 결과를 정상 결과처럼 확정하지 않는다.
- **보기 모드도 현재 구조에서는 전체 문서 해석·모델 메모리가 필요하다.** 보기 전용 UI만으로 대용량 비용이 없어지는 것은 아니다.
- 데스크톱의 100만 셀 검증을 Android 지원 보장으로 옮기지 않는다. 최소 목표 기기에서 파일 크기·압축 해제·기록 셀·수식/서식 밀도에 따른 한도를 결정하고, 초과 시 기존 문서를 보존하며 이유를 표시한다.
- 기존 가상 격자·Worker·취소 경로를 재사용한다. 같은 데이터를 호스트·문자열·렌더러에 불필요하게 여러 번 복사하지 않는지 확인한다.
- 큰 파일은 여는 단계·취소·실패를 보여주고 빈 화면에 멈추지 않게 한다. 부분 표시를 후속 도입한다면 ‘전체 문서 아님’을 표시하고 불완전한 모델의 덮어쓰기를 차단한다.
- Android WebView 렌더러 종료 시 새로 열기/명시적 복구 경로를 제공한다. 저장이 끝나기 전 앱이 종료된 변경까지 복구를 보장한다고 표시하지 않는다. [WebView 객체·렌더러 관리][android-webview]

초기 성능 목표는 **제안값**이다. 대표 문서에서 명령 피드백 100ms 이내, 스크롤 프레임 간격 p95 32ms 이내를 목표로 측정하고 최초 기기 실험 후 확정한다. p95는 대기 시간이 아닌 정해진 연속 스크롤 구간에서 측정한다. 문서 해석 시간·최종 화면 적용 멈춤·네이티브 호스트와 WebView 관련 프로세스의 메모리를 별도로 기록한다. 파일 해시·문서 특성·보기/편집 모드·기기 RAM·OS/WebView·반복 횟수·발열 상태를 함께 남긴다. 열린 셀 수만으로 성능을 판정하지 않는다.

### 10.2 접근성

- TalkBack에서 시트명·셀 주소·표시 값·선택 범위·편집 가능 여부를 읽는다. 보호된 숨김 수식은 읽지 않는다.
- 가상 격자의 모든 셀을 Tab 순서에 넣지 않는다. 논리적 활성 셀과 실제 렌더링된 셀을 연결하고 화면 밖 셀로 이동하면 표시와 안내를 함께 갱신한다.
- 버튼·탭·체크박스·메뉴의 이름/선택 상태·포커스 이동과 모달 포커스 복원을 검사한다.
- 시스템 글꼴 100/150/200%, 고대비·화면 확대·가로 화면에서 명령이 잘리지 않게 한다. UI 글꼴 확대를 문서 셀 서식에 저장하지 않는다.
- 색 견본에 이름과 선택 표시, 오류에는 텍스트 설명을 제공한다. 상태 변경은 적절한 빈도로 안내하고 스크롤 중 모든 셀을 반복 낭독하지 않는다.
- TalkBack 사용 중의 제스처 전달을 일반 터치와 같다고 가정하지 않는다. 주소/범위 입력, 확대 버튼, 셀 상세·문맥 메뉴 버튼으로 길게 누르기·드래그·핀치 없이 필수 작업을 수행할 수 있게 한다.

## 12. 구현 순서와 단계별 완료 조건

각 단계의 완료 조건을 출시 판단에 사용한다. G0의 네이티브 실험과 G1의 브라우저 모의 호스트 개발은 병행할 수 있지만, 실제 Android 호스트 검증을 끝내기 전 모바일 지원 완료로 표시하지 않는다. 네이티브 실험용 호스트는 패키징 작업과 연동하는 의존성이다.

| 단계 | 우선순위·산출물 | 완료 조건 |
|---|---|---|
| G0: Android 호스트 적합성 확인 | 선행 실험. 렌더러/Worker·XLSX·URI·IndexedDB·브리지·제스처 방식·IME/viewport | 오프라인 열기·스크롤·복구를 실기기로 확인하고 A/B 제스처 방식을 선정. 외부 키보드 첫 한글의 성공/막힘과 런타임·최소 기기/OS/WebView 후보 기록 |

| G3: 기본 편집 | P1. 편집/보기 전환, 셀/수식 입력, 큰 서식 패널, 사본 저장·편집본 공유·문서별 복구 | 한글 입력·붙여넣기·실행 취소·재열기·권한 실패·모드 전환 뒤 편집본 보존 통과 |
| G4: 태블릿 생산성 | P1. 접는 리본, 외부 키보드·마우스, 창 변경·분할 화면 | 키보드만으로 열기→편집→서식→저장→다시 열기 완료. 터치와 혼용해도 초안·선택 유지 |
| G5: 출시 전 검증 | 필수. TalkBack·큰 글꼴·저메모리·백그라운드/재생성·데스크톱 회귀 | 지원 범위·기기별 한도 확정, 미완료 Android 기능은 실행 불가로 표시, 아래 필수 시나리오 통과 |
| 후속 | P2. 채우기 드래그, 정교한 행열/개체 배치, 차트/피벗/입력 규칙 고급 작성, Android 인쇄/PDF | 각 기능의 터치·키보드·보존·취소 검증 후 노출 |

스마트폰의 첫 검토판은 **G0·G1·G2a + 보기 관련 G5**로 한정할 수 있다. G2b는 독립적으로 추가한다. 편집을 제공하는 Android 버전은 **G3·G4와 편집을 포함한 G5**까지 마친다. 외부 키보드 바로 입력의 G0 문제가 남으면 G4 완료가 아니다. 예상 기간은 G0의 런타임·기기 검증 이후 산정한다.

출시 범위별 필수 검사:

- **핵심 뷰어:** A01~A05, A16~A18, A21, A24~A25, A27~A28. A12~A13은 보기에서 가능한 키보드 탐색·검색·터치 혼용 범위를 검사한다. A24의 보호할 편집 복구본은 격리된 시험 자료로 미리 만든다.
- **G2b 제공 시:** A06·A22를 추가한다. 기능을 빼면 두 항목은 ‘미제공’으로 기록하고 ‘통과’로 집계하지 않는다.
- **편집판:** 위 검사와 A07~A15 전체, A19~A20, A23, A26. 모든 실패 경로에서 현재 문서·초안·복구본을 확인한다. 원본 저장을 제공하지 않는 판은 A26에서 해당 제한이 제대로 동작하는지 검사한다.

추가 출시 조건:

- 기본 글꼴의 360×640 사전 검사에서 키보드·패널을 닫았을 때 실제 가용 높이의 60% 이상을 격자에 할당하는 것을 목표로 한다. 시스템 inset은 제외하고 기록한다.
- 보기 조작 전후 열린 시점 원본 스냅샷의 해시, 문서의 편집 가능한 필드, 변경 기록·dirty를 대조한다. 보기 설정·파생 캐시를 별도로 검사하고 임의의 편집 변경을 캐시로 분류하지 않는다.
- 저장/재열기는 앱 내부 비교에 더해 기존 OOXML 검사를 재사용한다. Android에서 저장한 대표 파일을 데스크톱 Sheet Studio와 가능한 실제 Excel에서 확인하고 실행 환경을 명시한다.
- 기존 Windows·Mac·Linux 편집·파일·복구·업데이트 회귀를 유지한다. Android UI 때문에 데스크톱의 한글 입력·방향키·메뉴 선택 보존을 퇴행시키지 않는다.
- 필수 시나리오의 미완료 항목과 지원하지 않는 기능은 문서·화면에 명시한다. 모바일 한도·최소 OS·지원 기기는 측정 후 확정한다.

## 14. 첫 구현 묶음

계획에 따라 작업을 시작할 때는 아래 순서로 진행한다.

1. **G0 실행 실험**으로 제스처 소유권·외부 키보드 IME·URI·Worker/복구 경로를 먼저 확인한다. 병행해 모의 호스트에서 상태 모델을 설계한다.
2. **문서/보기/캐시/초안·명령 권한**을 분리하고 시트 이동·dirty·복구·지연 결과 회귀를 검사한다.
3. **스마트폰 보기 화면**, 공통 48 크기 터치 토큰·inset, 검증된 스크롤/확대·선택·셀 상세·시트 이동·찾기를 연결한다.
4. **파일 열기·열린 시점 원본 공유**와 복구본 보호를 완성한다. 임시 행 표시는 G2b에서 별도로 추가한다.
5. **셀 입력·서식 패널·태블릿 키보드·사본 저장**을 연결하고 편집 후 보기/공유·실패 복구까지 검사한다.
6. **단계별 실제 Android 기기 검사**로 런타임·IME·복구·성능 한계를 확정하고 그 결과를 별도 패키징 작업의 지원 범위에 반영한다.

문서 작성·재검토만으로 기능 구현·Android 검증·APK/AAB 제작·공개 배포가 완료된 것으로 보지 않는다. 최초 작성·재검토는 계획서에 한정했으며, 이후 구현은 별도 [구현·검증 기록](ANDROID-UI-IMPLEMENTATION.md)에 정리한다.
