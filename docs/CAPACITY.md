# 대용량 문서 안내 — 0.7.31 개발

0.7.31 개발 버전은 **모든 시트를 합쳐 기록된 셀 1,000,000개**까지 지원합니다. 아래 기능별 범위에는 이번 개선을 포함합니다. 공개 배포본 0.7.28과 다운로드 가능한 운영체제는 [README](../README.md)에서 구분합니다.

값·수식·서식 등이 저장된 셀을 셉니다. 서식만 있는 셀과 편집 후 기록이 남은 빈 셀도 포함합니다. 화면에 보이는 빈 격자의 개수나 마지막 행 번호를 뜻하지 않습니다. 예를 들어 10,000행 × 100열 또는 1,000,000행 × 1열입니다. 여러 시트로 나눠도 문서 전체 한도는 같습니다.

## 저장과 실행 취소

- 자동 복구는 IndexedDB의 셀 묶음에 저장합니다. 일반적인 단일 셀 수정은 해당 묶음과 문서 정보를 갱신합니다. 파일 가져오기·시트 복제·정렬처럼 셀 배치 전체가 바뀌는 작업은 해당 시트를 다시 저장합니다.
- 이전 localStorage 자동 복구 자료는 새 저장소에 정상 저장한 뒤 이전 항목을 지웁니다. 옮기기 실패 시 기존 자료를 유지합니다.
- 상단에 **자동 복구 저장 중…**이 표시되면 저장이 진행 중입니다. 데스크톱 앱은 정상 종료·새로 고침 전에 저장을 마칩니다. 저장 실패 시 창을 유지하므로 파일로 저장하고 종료하세요. 강제 종료·전원 차단 직전의 미완료 변경까지 보장하지는 않습니다.
- 실행 취소는 바뀐 속성·셀만 보관합니다. 최대 60단계이며 추정 데이터 예산은 128 MiB입니다. 이전 기록부터 정리하고, 한 작업 자체가 예산을 넘으면 기록을 비우고 화면에 알립니다. 큰 정렬·시트 교체 전에는 파일을 저장하세요.
- 자동 복구는 파일 백업을 대신하지 않습니다. 중요한 문서는 XLSX 또는 앱 문서 파일로도 저장하세요.

## 기능별 범위

| 기능 | 범위 |
| --- | --- |
| 문서의 기록된 셀 | 전체 시트 합계 1,000,000개 |
| 셀의 원문 텍스트 총량 | 전체 시트 합계 100,000,000자. 긴 텍스트의 대량 채우기도 검사 |
| 일반 수식 범위·배열 | 최대 1,000,000셀. 전체 행/열은 지원하는 집계·조회에서 희소 계산. 밀집 배열은 별도 한도 유지 |
| 동적 배열 파생 결과 | 문서 합계 1,000,000개, 활성 배열 정의는 시트당 10,000개 |
| XLSX의 원본+파생 셀 기록 | 합계 1,000,000개. 넘으면 기존 저장 파일을 바꾸지 않고 거부 |
| 자동 필터 | 데이터 행 최대 1,000,000개. 문서 셀 한도도 함께 적용 |
| 일반 정렬·필터 정렬 | 한 번에 최대 1,000,000셀 |
| 선택 편집·붙여넣기·채우기·Studio 표 교환 | 한 번에 최대 100,000셀 |
| 피벗 원본·결과 | 각각 최대 100,000셀. 원본과 결과를 합친 문서 한도도 적용 |
| 조건부 서식 | 규칙 범위당 최대 100,000셀 |
| 중복 제거 | 사용 영역 최대 100,000셀 |
| 인쇄 | 원래 영역 합계 20,000셀, 반복 제목 포함 100,000셀, 500페이지. 개체 조각 2,000개/개체 HTML 32,000,000자. 시트 위치·개체별 페이지 지원 |
| 표 계산 열·일반 범위 변환 | 한 번에 최대 100,000셀 |
| 여러 행·열 삽입/삭제 | 한 번에 10,000개. 기록 셀이 시트 끝에서 밀려나면 적용 전 거부 |
| 열기·저장 파일 | 최대 100 MB. JSON 문자열은 최대 100,000,000자 |
| XLSX 압축 해제 크기 | 전체 ZIP 항목 합계 최대 512 MB. 셀 모델을 만들기 전에 검사 |
| Windows Excel/VBA 연결 | 기존 15 MB 파일·200,000셀 변경 계획 제한 유지 |

긴 원문을 반복해서 붙여넣거나 자동 채우기/아래로·오른쪽 채우기 할 때는 셀 복제 전에 원문 총량을 확인합니다. 덮어쓸 원문과 잘라내기에서 비워질 원문은 먼저 제외하므로, 최종 용량이 같은 이동/덮어쓰기를 잘못 거부하지 않습니다. 한도에 가까운 99,975,168자 문서와 정상 10만 셀 채우기의 재검사 내역은 [작업 기록](EXCEL-IMPROVEMENTS.md)에 있습니다. 이 한도는 모든 메모리 사용량의 상한을 의미하지 않습니다.

문서 한도를 넘는 편집은 그 작업 전체를 취소합니다. 일부 셀만 변경한 상태로 남기지 않습니다. 파일 가져오기 실패도 작업 중인 문서를 교체하지 않습니다.

## 속도와 호환성

파일 읽기·쓰기, 일반 수식·동적 배열·피벗 계산, 화면의 조건부 서식 계산, 필터·정렬은 작업 스레드에서 처리합니다. 화면에는 보이는 격자만 그립니다. 파일을 처음 넘겨받거나 큰 시트를 교체할 때는 잠시 지연될 수 있습니다. 긴 텍스트·개별 서식·많은 수식은 같은 셀 수의 단순 숫자보다 메모리와 시간이 더 필요합니다. 100만 셀 지원이 모든 컴퓨터에서 같은 속도나 Excel 전체 기능의 동등성을 뜻하지는 않습니다.

0.7.29의 세 OS CI에서 합성 숫자 문서 두 종류를 검사했으며 XLSX 재열기는 약 22~56초가 걸렸습니다. 로컬 Mac의 최종 패키지는 가로형 약 10.2초, 세로형 약 21.0초였습니다. 첫 데이터 전달 중 수초 지연이 남을 수 있습니다. [최종 플랫폼 검사](https://github.com/beaur8-prog/sheet-studio/actions/runs/41045469858)와 [측정 조건·제한](../VALIDATION.md)을 참조하세요.

보조 XLSX 처리는 셀 전체를 다시 DOM으로 만들지 않고 워크시트 메타데이터를 읽습니다. 내보내기에서도 셀 XML을 유지하면서 필터·차트·조건부 서식 정보를 갱신하고 같은 서식 객체를 재사용합니다.

검증은 단순 숫자 100만 셀의 JSON 왕복, 큰 범위 합계, 실제 CSV/XLSX 열기·저장, 한도 초과 취소, 편집·실행 취소, 필터 및 프로세스 재시작 복구를 포함합니다. 플랫폼별 결과는 [검증 기록](../VALIDATION.md)에 남깁니다. 실제 Windows Excel/VBA와 Office 프로그램의 왕복 검증을 새로 수행했다는 의미는 아닙니다.

## 0.7.31 개발 보강

여러 행/열 변경은 복제한 문서의 작업 스레드에서 한 번의 이동과 참조 갱신으로 처리합니다. 일반 수식·표·필터·이름/차트·배열·입력 제한·숨김 크기·틀 고정을 함께 변경하고 저장 위치를 유지합니다. 브라우저 물리 높이를 넘는 시트는 논리 좌표와 스크롤 막대 범위를 분리해 180%에서도 1,048,576번째 행에 접근합니다.

10,000행×100열과 1,000,000행×1열은 메모리 특성이 다릅니다. 세로형 100만 셀의 큰 문서 교체는 128MiB 실행 취소 예산을 넘어 기록을 정리할 수 있으며 실제 안내를 확인했습니다. 이후 단일 셀 변경의 실행 취소/다시 실행은 별도로 유지합니다. 최종 성능 측정과 플랫폼 검사는 [작업 기록](EXCEL-IMPROVEMENTS.md)·[검증 기록](../VALIDATION.md)에 남깁니다.

## 0.7.31 동적 배열 측정

이 Mac의 격리 앱에서 원본 수식 1개의 100만 결과 계산·끝 이동은 약 0.7초, 전체 지우기는 약 51ms였고 실행 취소 기록은 약 3.2KB였습니다. XLSX 저장은 약 8.7초, 재열기·원본 압축·끝 이동은 약 18.1초였습니다. 피벗은 원본 레코드 4개로 파생된 100,000셀의 집계·화면 표시에 약 1초가 걸렸습니다. 하드웨어와 문서에 따라 달라지는 측정값이며, 모든 PC의 보장 성능은 아닙니다. [조건과 검증 기록](CORE-FIVE-HOUR-20261031.md)을 참조하세요.
