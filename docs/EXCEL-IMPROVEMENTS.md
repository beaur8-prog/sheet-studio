# Excel 호환성 개선 작업 — 2026-10-30

작업 시작: 2026-10-30 10:28 KST. 목표 작업 시간: 10시간.

기준 커밋은 `0d3a05b` (0.7.28)이다. 실제 Microsoft Excel을 새로 실행한 검증과 독립 엔진/OOXML 검사를 구분해서 기록한다. 공개 릴리즈와 리토스 공유본은 별도의 배포 요청 전까지 갱신하지 않는다.

## 우선순위와 완료 기준

1. 차트 데이터와 표시: 오류가 난 수식의 이전 캐시, 숨김/필터 행, 혼합 누적, 거품 크기, 원형 색/레이블, 날짜·숫자 표시를 수정한다. 입력→화면→XLSX 왕복의 의미가 일치하는 회귀 사례를 추가한다.
2. 계산 신뢰성: 재계산 명령, 긴 셀 의존관계, 날짜/빈칸 조건 집계, AVERAGEIF 범위 확장, 표시 형식을 보강한다. 기존 계산 검증과 새로운 경계 사례를 함께 확인한다.
3. 문서 보존: Excel 표, 이름 정의, 유효성·보호·고급 서식, 배열 수식, 1904 날짜 체계, 차트 전용 시트와 참조를 안전하게 보존한다. 편집하지 않은 기능이 저장 과정에서 사라지지 않게 한다.
4. 선택 영역과 작업 흐름: 정렬 영역 추론, 표 내부 단일 셀에서 차트 삽입, 차트 인쇄와 자주 쓰는 차트 편집 옵션을 보강한다.
5. 남은 시간에는 기본 표 모델/참조, 진단과 편집 기능 확장을 진행한다. 완성되지 않은 Excel 기능을 완료로 표시하지 않는다.

## 검증 기록

- 시작 전 감사: 표/수식 관련 기존 검사 59개, 차트 관련 기존 검사 28개 통과. 새로 재현한 사례는 기존 검사에서 누락되어 있었다.
- 개발은 iCloud 읽기 지연을 피하기 위해 별도 로컬 체크아웃에서 진행한다. 사용자 문서와 앱 프로필은 검증용으로 변경하지 않는다.

### 1차: 차트 정확성

- 필터·수동 숨김과 행/열 방향을 함께 반영하고, 숨김 포함 옵션을 XLSX·Windows Excel 저장 계획에 연결했다.
- 현재 계산 오류를 오래된 숫자 캐시로 바꾸지 않는다. 가져온 계산값에는 원래 수식을 기록하고, 지원하지 않는 수식의 저장값을 표시할 때 안내한다.
- 누적 혼합 차트의 누적 기준을 유형·축별로 분리했고 거품 크기는 같은 차트에서 공통 기준을 사용한다.
- 원형 조각/범례 색, 백분율 레이블의 XLSX 설정, 단일 계열 꺾은선 범례, 방사형 음수 구분을 보강했다.
- 날짜·백분율 표시와 날짜 간격을 화면 및 XLSX 날짜축에 연결했다. 가까운 날짜 눈금의 겹침도 확인하고 수정했다.
- 차트의 이름 정의 참조를 직접 셀 범위로 바꾸지 않고 유지한다.
- 검증: 전체 단위 검사 193개 중 192개 통과, Windows 전용 1개 건너뜀. 새 차트 회귀 사례 10개와 기존 18개 조합을 포함한다. 실제 Mac Electron에서 삽입→편집→필터→실행 취소/다시 실행→저장/재열기 및 날짜 간격·범례·레이블을 확인했다.
- 현재 차트 전용 시트, 전체 XLSX 원본 보존과 상세 축/레이블 편집은 다음 작업으로 남아 있다. 실제 Windows Excel 실행은 수행하지 않았다.

### 2차: 재계산과 수식 의존관계

- 날짜 문자열 조건을 날짜 번호로 해석하고, AVERAGEIFS의 빈 조건 셀/논리값 및 AVERAGEIF의 평균 범위 확장을 보강했다.
- 지금 계산과 F9는 표시 캐시와 작업 스레드의 계산 세션을 실제로 갱신한다. 늦게 도착한 이전 계산 결과는 새 결과를 덮지 않는다.
- 일반 XLSX/CSV 저장은 작업 스레드에서 화면과 같은 계산 세션을 사용한다. RAND 등의 화면 값과 저장 캐시가 달라지지 않는다.
- 긴 셀 참조는 재귀 호출 대신 의존 셀의 계산을 순서대로 재개한다. IF/IFERROR 등의 지연 평가와 RAND 호출 횟수를 유지하며, 큰 범위와 SUBTOTAL도 중간 진행 위치를 재사용한다.
- 검증: 전체 검사 198개 중 197개 통과, Windows 전용 1개 건너뜀. 실제 Mac Electron에서 재계산 버튼/F9, 난수와 종속 수식의 저장 캐시 일치, 10,000개 연결 셀의 탐색·수정·실행 취소/다시 실행·저장/재열기, 날짜/빈칸 조건식 직접 입력을 확인했다.

### 3차: 1904 날짜 체계

- 날짜 셀을 1900 기준으로 일괄 변환하지 않고 문서의 1904 날짜 체계와 원래 날짜 번호를 유지한다. 수식 속 날짜 번호 상수도 같은 의미를 갖는다.
- DATE/YEAR/DATEVALUE/TEXT/요일/근무일/월말 함수, 조건 집계, 셀·차트 표시, 날짜 필터와 네이티브 저장 계획이 문서의 날짜 체계를 사용한다.
- XLSX의 통합 문서와 차트 날짜 체계를 함께 저장한다. 날짜가 있는 셀의 일반/값 붙여넣기는 서로 다른 날짜 체계 사이에서 날짜 번호를 조정한다.
- 검증: 전체 검사 202개 중 201개 통과, Windows 전용 1개 건너뜀. 1904 문서의 3회 XLSX 왕복, 날짜 상수 포함 수식, 날짜 필터, 차트, 클립보드 날짜 표시/변환을 확인했다. 실제 Mac Electron에서도 1904 XLSX 열기→날짜 표시→수식 편집→날짜 필터→저장/재열기를 통과했다.

### 4차: 정렬 범위와 차트 삽입

- 단일 셀 정렬은 주변의 이어진 데이터 영역만 사용한다. 서로 떨어진 표가 함께 이동하던 문제를 수정했다. 역순으로 저장된 큰 셀 목록도 반복 전체 검색 없이 처리한다.
- 숫자로 시작하는 데이터의 첫 행을 머리글로 제외하지 않는다. 머리글 여부가 불분명하거나 일부 열만 선택한 경우 범위·머리글 확인창을 제공해 행의 다른 열과 분리되는 정렬을 예방한다.
- 표 안의 단일 셀에서 빠른 차트와 모든 차트를 삽입하면 해당 데이터 영역을 제안한다. 명시적으로 선택한 여러 셀의 범위는 유지한다.
- 검증: 독립된 표, 첫 숫자 행, 부분 열 선택, 수식 이동, 10,000행 역순 입력, 빈 셀·전체 열을 단위 검사했다. 실제 Mac Electron에서 정렬→실행 취소/다시 실행→XLSX 저장·재열기 및 두 차트 삽입 경로를 확인했다.

### 5차: XLSX에서 기존 정보 보존

- 기본 서식 모델이 다루지 않는 회전·들여쓰기·축소 맞춤, 취소선, 그라데이션·대각선 테두리, 셀 잠금 설정을 원래 서식과 함께 보관한다. 글꼴·숫자 표시 등을 수정하면 변경한 속성만 덮어쓴다.
- 셀 안의 여러 글꼴과 하이퍼링크 주소·도움말을 보존한다. 링크 표시 문구를 수정해도 주소가 남고, 전체 셀의 글꼴 변경은 서식 있는 문자열에도 적용한다.
- 배열 수식의 범위·유형과 가져온 미래 함수 접두어를 유지한다. 차트가 없는 문서의 이름 정의와 테마도 저장한다.
- 입력 제한은 범위 XML을 보관해 전체 열의 목록 규칙을 100만 개의 객체로 펼치지 않는다. 시트 보호의 암호 해시·권한을 유지한다.
- 지원하지 않는 색조·아이콘 조건부 서식은 저장을 차단하거나 없애지 않고, 원래 우선순위와 차등 서식을 보존한다. 화면 미리 보기와 편집의 한계는 규칙 관리창에 알린다.
- 검증: 전체 검사 210개 중 209개 통과, Windows 전용 1개 건너뜀. 고급 서식·링크·보호·배열·이름 정의와 미지원 조건부 서식을 3회 왕복했다. 실제 Mac Electron에서 열기→글꼴/링크 문구 수정→XLSX 저장·재열기를 확인했다. 입력 제한과 보호의 편집 동작, 구조 변경 시 관련 범위 갱신은 후속 작업으로 계속 점검한다.

### 6차: 보호·입력 제한·배열 결과 편집

- 시트 보호의 잠긴 셀과 편집 허용 셀을 구분하고, 잠긴 셀이 섞인 붙여넣기·채우기·정렬은 일부만 변경하지 않고 중단한다. 허용되지 않은 서식·크기·구조·차트 변경도 차단한다. 행·열 기본 잠금과 암호 정보는 새로 입력한 셀 및 XLSX 왕복에도 유지한다. 숨김 수식은 수식 입력줄과 수식 표시·복사에서 노출하지 않는다.
- 목록 입력 제한에 선택 버튼과 키보드 탐색을 제공한다. 직접 입력에는 정수·소수·목록·문자 길이·사용자 수식의 중지/경고 규칙을 적용하고, 여러 입력 후보를 원본 수정 없이 확인한다. 아직 계산할 수 없는 입력 제한 수식은 명시적으로 안내한다.
- 배열 결과 일부의 입력·붙여넣기·정렬·행·열 삽입/삭제를 방지한다. 기존 배열 계산 전체와 동적 배열 엔진을 완성한 것은 아니며, 수식의 유형과 범위를 보존하는 단계다.
- 행·열 변경, 시트 이름 변경 시 보존된 입력 제한·조건부 서식·배열 범위와 수식도 갱신한다. 최대 행 끝까지 걸친 범위의 삽입 시 끝점을 잘못 #REF!로 바꾸던 문제도 수정했다.
- 검증: 단위 검사 215개 중 214개 통과, Windows 전용 1개 건너뜀. 실제 Mac Electron에서 목록 선택, 거부된 입력 수정, 사용자 조건식, 경고 입력 유지, 배열 일부 수정 차단, 보호된 범위의 원자적 붙여넣기, 잠금 해제 셀·열 입력, 수식 숨김, 암호를 유지한 저장·재열기를 확인했다. 기존 재계산·차트·정렬 UI 시나리오도 재확인한다.
- 기준: [Microsoft 시트 보호 안내](https://support.microsoft.com/en-us/excel/protect-a-worksheet), [OOXML 시트 보호 속성](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.sheetprotection?view=openxml-3.0.1). 실제 Windows Excel을 실행한 검증은 수행하지 않았다.

### 7차: 정의된 이름

- 범위·상수·별칭·OFFSET 기반 이름을 수식 계산에 연결했다. 시트별 이름이 통합 문서 이름보다 우선하며, 다른 시트의 로컬 이름도 명시적으로 참조할 수 있다. ROW/ROWS 같은 참조 정보 함수는 이름의 실제 셀을 읽지 않아 불필요한 순환 참조를 만들지 않는다.
- 수식 탭에 이름 관리자를 추가해 만들기·편집·삭제·범위 이동을 지원한다. 이름 상자로도 참조 범위에 이동할 수 있다. 새 이름은 선택한 시트의 절대 참조를 사용한다.
- 이름 정의의 원래 속성·설명과 로컬 범위를 XLSX에 유지한다. 정의를 바꾸면 차트 범위도 다시 확인하며, 삭제된 이름을 오래된 계산 캐시로 정상 값처럼 저장하지 않는다.
- 정의 기준 위치가 보관되지 않은 가져온 상대 참조 이름은 원본을 보존하고 계산 지원 한계를 안내한다. XLSM 이름 정의 편집은 네이티브 저장 계획이 지원할 때까지 막아 조용히 변경을 누락하지 않는다.
- 검증: 이름 계산·스코프·순환·동적 범위, XLSX 3회 왕복과 원래 속성, 이름 변경에 따른 차트 갱신·캐시 무효화를 확인했다. 실제 Mac Electron에서 이름 만들기→수식 계산→정의 편집→실행 취소/다시 실행→이름 상자 이동→저장·재열기→삭제 시나리오를 통과했다.

### 8차: Excel 표 개체와 구조화 참조

- XLSX의 표 이름·범위·열 정의·계산 열·요약 행·스타일·필터를 읽고 실제 표 개체로 다시 저장한다. 색만 남고 표 정의가 사라지던 문제를 수정했다. 표의 조회 연결 파일과 통합 문서 데이터 연결도 함께 보존한다.
- `Sales[Amount]`, `[@Qty]`, 열 구간, #Headers/#Data/#Totals/#All, 이스케이프된 열 이름과 이름을 통한 표 참조를 계산한다. 참조 정보 함수와 INDIRECT에서도 같은 구조화 참조를 사용한다.
- 필터가 있는 표에서 라이브러리의 기존 표 필터 파서에 들어가 파일 열기가 실패할 수 있는 경로를 분리하고, 범위·필터를 직접 복원한다. 표 필터는 SUBTOTAL·행 표시·차트 가시성에 반영된다. 수동 숨김과 필터 숨김도 구분해 왕복한다.
- 표 안의 빠른 정렬과 단일 셀 차트 삽입은 요약 행을 데이터에 포함하지 않는다. 사용자 지정 표 스타일·차등 서식 ID를 보존하며 반복 저장해도 같은 서식과 연결 경로가 계속 늘어나지 않는다.
- 검증: 전체 검사 226개 중 225개 통과, Windows 전용 1개 건너뜀. 표 3회 왕복, 사용자 스타일 4회 왕복, 연결 파일 3회 왕복과 경로 안정성을 확인했다. 실제 Mac Electron에서 표 XLSX 열기→입력·계산·요약→실행 취소/다시 실행→저장·재열기→요약 행을 유지하는 정렬→차트 범위 제안과 필터가 있는 표의 재열기를 확인했다. 표 만들기·관리 UI와 행·열 변경 연동은 이어서 구현한다.
- 구조화 참조 기준: [Microsoft Excel 표 참조 안내](https://support.microsoft.com/en-us/excel/using-structured-references-with-excel-tables). 표 생성 검증 파일은 ExcelJS와 OOXML로 만들었으며, 설치된 Microsoft Excel을 실행한 검증과 구분한다.

### 9차: 표 만들기와 관리

- 삽입·홈의 표 명령과 Ctrl/Command+T에서 실제 Excel 표를 만든다. 표 이름·범위·스타일·요약 행을 관리하고, 선택한 열의 전체 데이터 행에 수식을 적용할 수 있다. 표 안에서는 관리 막대를 보여 준다.
- 새 스타일은 사용자 지정 Excel 표 스타일로 함께 저장한다. 직접 지정한 셀 서식이 표 기본 서식보다 우선하며, 표의 색도 색 필터와 다른 앱에 복사하는 표시 서식에 반영된다. 원래 Excel 기본 스타일은 원래 이름을 보존하고 간소화해 미리 본다.
- 표 이름이나 머리글을 바꾸면 관련 셀 수식·계산 열 정의·이름 정의·차트·조건부 서식과 보존된 입력 제한 참조를 함께 갱신한다. 중복 열 이름과 숫자·날짜·논리값 머리글도 정리한다. 표를 줄여 밖으로 나온 현재 행 수식은 일반 셀 참조로 바꿔 결과를 유지한다.
- 표별 필터 버튼·값/색 필터·지우기·재적용을 연결했다. 표 스타일이나 계산 열 변경 후의 필터는 새 표시·값을 기준으로 다시 계산한다. XLSM과 외부 조회 표에서 아직 저장 계획이 다루지 못하는 구성 편집은 막아 변경 누락을 예방한다.
- 기본 90px 열 너비와 25px 행 높이를 쓰는 새 문서도 XLSX 저장·재열기에서 같은 크기를 유지한다. 표의 기본 글꼴 서식을 불필요한 셀 직접 서식으로 덮지 않도록 내보내기도 조정했다.
- 검증: 표 만들기/중복/충돌, 이름·머리글 변경과 실행 취소, 계산 열·요약·범위 변경, 새 스타일 4회 왕복 및 색 필터 재계산을 확인했다. 실제 Mac Electron에서 만들기→계산 열→이름/머리글 수정→실행 취소/다시 실행→요약 행→값/색 필터→저장·재열기→범위 축소를 통과했다. 기존 일반 범위의 필터 UI도 재확인했다.

### 10차: 표의 구조 변경·자동 확장·일반 범위 변환

- 표 안의 행·열 삽입/삭제가 범위·열 ID/이름·필터·계산 열 정의·요약 행에 함께 반영된다. 새 데이터 행은 계산 열과 직접 서식을 이어받되 기존 값·메모를 복제하지 않는다. 삭제한 열을 참조하는 수식은 명시적인 #REF!로 바꾸고, 머리글 일부 삭제는 막는다. 표 전체 삭제는 외부 참조도 갱신한다.
- 바로 아래 이어진 행에 입력/붙여넣기하면 표를 세로로 확장하고 계산 열을 채운다. 빈 열에 처음 입력한 수식은 입력 위치에 맞춰 전체 데이터 행에 채운다. 기존 열 값과 개별 수식 예외는 자동으로 덮어쓰지 않는다. 요약 행·병합·다른 표·배열과 겹치거나 현재 구성 편집이 지원되지 않는 경우에는 자동 확장하지 않는다.
- 표 관리의 일반 범위 변환은 표의 표시 서식과 필터 숨김을 유지한다. 현재 행 참조는 일반 상대 참조로, 표 전체/열 참조는 시트를 명시한 절대 참조로 바꾸며 다른 시트·이름 정의·차트·보존된 기능 수식도 함께 갱신한다. 변환 계획은 원본을 수정하지 않고 만든다. 서식을 유지하는 변환은 현재 한 번에 100,000셀까지 지원한다.
- 검증: 전체 검사 241개 중 240개 통과, Windows 전용 1개 건너뜀. 실제 Mac Electron에서 행·열 삽입→새 행 계산→열 삭제 오류/머리글 보호→실행 취소/다시 실행→일반 범위 변환→저장·재열기를 통과했다. 직접 수식 입력의 계산 열 자동 채움과 행 확장·실행 취소도 확인했다. 실제 Microsoft Excel 실행 검증은 수행하지 않았다.

### 11차: 차트 전용 시트·이미지·도형·사용자 색상표

- 차트 전용 시트를 누락하지 않고 원래 시트 순서·종류·활성 탭·로컬 이름 범위와 함께 가져온다. 셀 편집을 막는 차트 화면을 제공하고, 지원하는 차트의 제목·표시 설정과 기하 정보를 XLSX의 실제 차트 시트에 저장한다. 원래 인쇄/머리글 정보와 기타 연결 파일도 보존한다.
- 시트의 hidden/veryHidden 상태를 저장하며 일반 숨김 시트는 탭의 오른쪽 클릭 메뉴에서 표시/숨김을 변경할 수 있다. 마지막 표시 시트는 숨기거나 삭제할 수 없다. veryHidden과 XLSM 시트 숨김 구성은 Excel에서 변경하도록 안내한다.
- 차트가 아닌 그림·도형의 앵커, 미디어, 외부 하이퍼링크 및 관련 파일을 보관한다. 기본 PNG/JPEG/GIF/WebP는 화면에 표시하고, 자르기·회전·효과가 있는 그림과 도형은 미리 보기 지원 한계를 상태 막대에 알리고 원본을 유지한다. 이미지 위에 셀 눈금선이 겹치던 표시도 수정했다. 일반 시트의 그림/차트 좌표에 행·열 머리글 여백을 일관되게 적용한다.
- 일반 시트의 그리기 원본은 ExcelJS의 제한된 그림 파서에 넘기지 않고 별도로 복원한다. 관계 속성의 접두어가 r 이외인 경우도 처리하며 반복 저장 시 파일 경로가 중첩되거나 개체 ID가 중복되지 않게 한다.
- 사용자 지정 indexedColors 색상표를 함께 유지해 셀 글자·배경·테두리와 표 차등 서식의 색상이 달라지지 않도록 했다.
- XLSM 네이티브 계획은 차트 전용 시트를 Worksheet로 잘못 다루지 않고 원본 파일에 유지한다. 현재 지원하지 않는 차트 시트 구성 변경은 오류로 알린다. 실제 Windows Excel 실행 검증은 수행하지 않았다.
- 검증: 전체 검사 246개 중 245개 통과, Windows 전용 1개 건너뜀. 차트 전용 시트·로컬 이름·인쇄 정보 3회 왕복, 이미지·도형·하이퍼링크·차트 병합 4회 왕복과 경로/개체 ID, 사용자 색상표 3회 왕복을 확인했다. 실제 Mac Electron에서 차트 전용 화면→설정 변경→숨김 시트 표시·값 수정·다시 숨김→저장·재열기와 그림 미리 보기·편집·재열기를 통과했다. 기존 10개 차트 유형/18개 조합 UI 시나리오도 다시 통과했다.

### 12차: 전체 행·열 참조와 큰 범위 집계

- A:A·$B:$D·1:1 및 시트 한정 참조를 해석한다. 복사/채우기·행열 삽입/삭제·전치와 이름 정의의 절대 참조 변환에 반영하고, 수식 편집 중 범위 표시와 F4 고정 전환도 연결했다.
- SUM/AVERAGE/MIN/MAX/COUNT/COUNTA, COUNTBLANK, 단일·복수 조건 집계, VLOOKUP/XLOOKUP/MATCH/XMATCH와 SUBTOTAL은 전체 행·열이나 큰 희소 범위에서 기록된 셀을 읽는다. 빈 셀 개수가 필요한 계산은 실제 전체 범위를 기준으로 센다. 일반 집계 결과는 계산 세션에서 공유하여 같은 전체 열 합계의 반복 계산을 줄인다.
- INDEX는 거대한 전체 열을 먼저 읽지 않고 선택한 셀/범위를 참조한다. 다중 영역 참조형 INDEX, INDIRECT/OFFSET 기반 참조 정보와 ROWS/COLUMNS/ISREF/SHEET도 보강했다. 선택하지 않은 XLOOKUP 대체 식을 평가하지 않는다. SUBTOTAL은 숨김 행과 중첩 합계를 읽기 전에 제외해 불필요한 순환/계산을 방지한다.
- SUMPRODUCT 등 실제 배열 전체가 필요한 계산은 기존 1,000,000셀 한도를 유지한다. 전체 열에 대한 모든 배열 연산을 무제한 지원한다는 의미는 아니다.
- 검증: 전체 검사 253개 중 252개 통과, Windows 전용 1개 건너뜀. 100만 기록 셀에서 전체 열 합계 100개, 실제 마지막 행 조회, 빈 셀·조건·오류·숨김·긴 계산 의존관계를 확인했다. 실제 Mac Electron에서 입력→F4/범위 표시→마지막 행 수정→실행 취소/다시 실행→열 삽입→XLSX 저장·재열기를 통과했다. 기존 수식 편집 UI의 주소 오류 안내도 함께 수정하고 재검증했다.
- 기준: [Microsoft의 전체 열 참조·배열 계산 성능 설명](https://learn.microsoft.com/en-us/office/vba/excel/concepts/excel-performance/excel-tips-for-optimizing-performance-obstructions). 실제 Windows Excel 실행 검증은 수행하지 않았다.

### 13차: 가져온 배열 수식의 실제 재계산

- 저장된 배열 수식의 결과 셀을 예전 캐시 그대로 읽지 않고 원래 수식에서 다시 계산한다. 단일 값/축의 반복, 범위를 벗어난 결과의 #N/A, 빈 참조의 0, ROW/COLUMN 및 배열 조건 IF·IFERROR·IFNA를 보강했다. 조건에 선택되지 않은 오류 값은 다른 결과에 전파하지 않는다.
- 원본에 결과 셀이 생략된 배열도 계산·전체 열 집계·CSV/XLSX 저장에 포함한다. XLSX에는 현재 결과 캐시를 쓰고 원래 배열 유형·범위를 유지한다. 결과를 포함한 기록 셀 한도는 1,000,000개이며 시트당 배열 정의는 최대 10,000개다. 잘못된 시작 위치나 겹친 배열 정의는 거부한다.
- 배열의 일부를 값으로 덮어쓰거나 앵커만 일반 값으로 바꾸는 작업을 막는다. 배열 전체를 지우면 오래된 정의도 제거하여 나중에 수식을 입력했을 때 이전 배열이 다시 나타나지 않는다. 전체 배열 복사는 새 위치의 정의와 현재 결과를 유지하고, 일부 결과를 복사할 때는 현재 값으로 복사한다. 수정한 수식을 복사할 때 옛 수식 원문이 저장되던 문제도 수정했다.
- 값 붙여넣기는 배열 정의를 남기지 않는다. 배열 수식 전치는 현재 값으로 전치할 수 있으며, 배열 자체의 자동 채우기는 복사·붙여넣기를 안내한다. 배열 결과의 서식만 붙여넣는 것은 허용한다. XLSM의 배열 구성 변경은 네이티브 저장 계획이 지원할 때까지 Excel에서 진행하도록 막되 일반 입력값 변경에 따른 결과는 앱에서 다시 계산한다.
- 검증: 전체 검사 258개 중 257개 통과, Windows 전용 1개 건너뜀. 실제 Mac Electron에서 오래된 결과가 든 XLSX 열기→원본값 수정→실행 취소/다시 실행→배열 앵커 IF 수정→일부/전체 복사→전체 삭제와 복구→저장·재열기를 통과했다. 입력 제한·보호·배열 편집 거부 시나리오도 다시 확인했다. 이 단계는 기존 범위가 지정된 배열의 계산이며, 새 동적 배열의 자동 스필 전체를 구현한 것은 아니다.
- 기준: [Microsoft 배열 수식 안내](https://support.microsoft.com/en-us/excel/guidelines-and-examples-of-array-formulas), [배열 크기와 #N/A 설명](https://support.microsoft.com/en-us/excel/how-to-correct-a-n-a-error). 실제 Windows Excel 실행 검증은 수행하지 않았다.

### 14차: 글자와 계산 오류의 구분·배열 화면 표시

- `="#N/A"`처럼 수식이 반환한 글자와 `=NA()`의 계산 오류를 계산 세션·작업 스레드·복사/값 붙여넣기·CSV/XLSX 저장까지 구분한다. 지원하지 않는 수식의 가져온 글자 캐시도 오류로 바꾸지 않는다. 차트가 글자 결과를 예전 숫자 캐시로 대신 표시하던 경로도 수정했다.
- 배열 결과 셀의 원래 값이 글자·숫자이거나 셀이 생략되어 있어도 화면은 현재 계산값을 사용한다. 수식 입력줄은 배열 시작 셀의 수식과 범위를 보여 주고, 결과 셀에서는 직접 편집을 막는다. 수식 숨김과 보호 설정도 적용한다.
- 검증: 전체 검사 262개 중 261개 통과, Windows 전용 1개 건너뜀. 글자/오류 결과와 미지원 수식 캐시를 각각 XLSX 3회 왕복했다. 실제 Mac Electron에서 원본값 수정 후 배열 결과의 화면 글자, 결과 셀의 수식 입력줄, 일부/전체 배열 복사, 값 붙여넣기, 저장 캐시의 실제 자료형과 재열기를 확인했다. 기존 차트 표시·편집·필터·실행 취소·저장 시나리오도 통과했다.

### 15차: 숫자 표시 형식과 TEXT

- 숫자 형식 코드를 공통 해석해 앞자리 0, 양수/음수/0/글자 구간, 조건, 음수 괄호, 인용·이스케이프 문자, 선택 소수 자릿수와 정렬 공백, 천 단위 축약, 지수·분수·백분율 표기를 보강했다. 셀 화면과 TEXT 함수가 같은 처리를 사용하며 숫자로 된 글자 입력도 TEXT에서 변환한다.
- 시간의 소수 초, 경과 시간의 반올림, 날짜/시간 경계, 월의 한 글자와 오전/오후 대소문자를 보강했다. 형식 코드의 색은 화면·복사·색 필터에 반영하며 조건부 서식이 우선한다. 셀이 생략된 배열 결과도 필터에서 빈칸으로 오인하지 않는다.
- 셀 서식창에 사용자 지정 코드·입력 검증·실제 값 미리 보기를 추가했다. 숫자 값 자체는 유지한다. 소수 자릿수 변경이 사용자 코드의 문자/음수 구간을 없애지 않도록 저장 경로도 맞췄다. 반복 문자 채움의 정확한 열 너비 배치와 지역별 달력/로캘 전체는 아직 구현하지 않았다.
- 검증: Microsoft의 형식 예제 및 추가 경계 사례, 값과 코드의 XLSX 3회 왕복을 확인했다. 실제 Mac Electron에서 코드 입력→미리 보기→적용→취소/잘못된 코드 거부→실행 취소/다시 실행→TEXT 계산→저장·재열기를 통과했다. 기존 셀 서식과 테두리 UI도 통과했다. 당시 macOS가 잠겨 있어 네이티브 창 전환의 포커스 검사는 건너뛰었다.
- 기준: [Microsoft 사용자 지정 표시 형식 안내](https://support.microsoft.com/en-us/excel/review-guidelines-for-customizing-a-number-format). 실제 Windows Excel 실행 검증은 수행하지 않았다.

### 16차: 차트·셀·이미지 인쇄

- 인쇄에서 빠지던 차트와 차트 전용 시트를 실제 SVG로 출력한다. 인쇄 대상을 현재 시트·선택 영역·차트만 중 선택하고, 방향·눈금선·차트/이미지 포함 여부를 정할 수 있다. 차트와 이미지는 셀 뒤에 이어서 배치한다.
- 필터·수동 숨김, 병합 셀, 행·열 크기, 표/직접/조건부 서식, 표시 형식과 현재 배열 결과를 반영한다. 인쇄 문서는 작업 스레드에서 화면과 같은 계산 세션으로 만들며 RAND 등도 화면 값과 일치한다. 기존 XLSM 저장 캐시를 사용하는 값과 미리 보기 불가 개체의 제외 여부를 문서에 표시한다.
- 셀 인쇄는 한 번에 20,000개까지 지원한다. 큰 문서는 선택 영역 또는 차트만 인쇄하도록 안내하며 원본은 변경하지 않는다. 원래 화면 좌표대로 차트를 셀 위에 겹치는 Excel 인쇄 배치를 그대로 구현한 것은 아니다.
- 검증: 전체 검사 272개 중 271개 통과, Windows 전용 1개 건너뜀. 실제 Mac Electron에서 옵션→작업 스레드 계산→인쇄 문서, PDF 생성, 차트·범례·이미지 크기의 시각 검사, 선택 영역, 차트 전용 시트, 큰 범위 거부를 확인했다. 검증에서는 프린터 대화상자만 가로채어 사용자 프린터 설정과 실제 인쇄 작업에 영향을 주지 않았다.

### 17차: 여러 행·열 변경과 대용량 검증

- 10,000개 행·열 변경 때 전체 셀과 수식을 10,000회 반복 순회하던 작업을 작업 스레드의 한 번 이동·참조 갱신으로 바꿨다. 전체 변경을 복제본에서 검증한 뒤 적용하고 실행 취소/다시 실행, 저장 위치의 문서 ID와 복구 저장을 유지한다.
- 연속 삽입/삭제가 일반·전체 행열 참조, 표 범위·열 ID/머리글·계산 열·요약·필터, 이름/차트/피벗 참조, 입력 제한·조건부 서식·배열·숨김 크기·잠금 기본값·틀 고정에 함께 반영된다. OFFSET 등 차트 참조 수식의 내부 좌표도 갱신한다. XLSM 비교 기준은 한 번 변환하되 기존 Windows 저장 계획의 개별 작업 형식을 유지한다.
- 마지막 행·열의 기록 셀이 밀려나 사라질 삽입은 변경 전 거부한다. 가져온 배열과 표가 시트 끝을 넘어가는 경우도 막는다. 표에 새로 생길 계산·서식 셀을 포함한 1,000,000셀 한도를 적용한다.
- 검증: 전체 검사 278개 중 277개 통과, Windows 전용 1개 건너뜀. 실제 Mac Electron의 100,001셀 문서에 10,000행 삽입은 약 0.63초, 응답 간격 최대 262ms였다. 1,000,000셀 문서의 100행 삽입은 약 4.84초, 최대 간격 837ms였고 실행 취소/다시 실행도 유지됐다. 이어 65회 입력, 정렬·필터, 프로세스 재시작 복구, XLSX 저장·재열기를 통과했다. XLSX 저장 약 3.63초, 재열기 약 8.89초였으며 이 수치는 현재 Mac·검증 데이터에서의 측정이다. 표 구조 변경·배열 보호·전체 열 수식의 기존 UI도 다시 통과했다.

### 18차: 확대 상태의 마지막 행·눈금선 표시

- 180% 확대 후 마지막 행으로 이동해도 약 745,640행 부근에서 화면이 멈추는 문제를 실제 앱에서 재현했다. 브라우저의 물리 높이가 33,554,432px에서 제한되어 1,048,576행의 전체 높이를 표현하지 못했다.
- 스크롤 막대의 물리 범위와 시트의 실제 좌표를 분리하고 화면에 그리는 셀·테두리·차트를 뷰포트 좌표로 배치한다. 마지막 행까지 원래 셀 크기를 유지하며 큰 좌표에서 얇은 눈금선 일부가 사라지는 현상도 해결했다. 휠 이동은 실제 화면 픽셀 간격을 유지한다.
- 선택·입력창·수식 참조·복사 테두리·포인터 선택·자동 스크롤·틀 고정·행 높이·차트 이동/크기 조절을 같은 좌표에 연결했다. 보이는 행 번호의 자릿수에 맞춰 머리글 폭을 늘려 7자리 행 번호가 잘리지 않는다.
- 검증: 전체 검사 280개 중 279개 통과, Windows 전용 1개 건너뜀. 실제 Mac Electron에서 50/180%의 마지막 행 표시·입력·실행 취소·키보드/포인터 선택·휠·틀 고정과 차트 위치를 확인하고 시각 검사했다. 기존 워크시트·수식 편집·행/열 크기·차트 조작·테두리 픽셀 폭·이미지/차트 전용 시트 UI도 통과했다.
- 세로 100만 셀의 별도 시나리오도 입력·정렬·필터·재시작·XLSX 저장/재열기를 통과했다(저장 약 10.24초, 재열기 약 20.31초). 이 배치의 100행 변경은 기존 128 MiB 실행 취소 예산을 넘어 안내 후 기록을 비웠고, 이후 65회 단일 셀 편집은 작은 변경 기록 60개로 유지됐다. 가로·세로 배치와 문자열/서식 양에 따라 큰 변경의 복구 비용이 달라진다.

### 19차: 기본 서식과 행·열 서식

- Normal 기본 서식과 비어 있는 행·열 전체의 원래 서식을 별도 모델로 보관한다. 새 셀의 글꼴·색·숫자 표시·맞춤·테두리와 잠금에 반영하며, 셀에서 명시적으로 기본 서식으로 되돌린 경우는 행·열 서식과 구분한다. 기존 셀의 직접 서식은 우선한다.
- 글자색 한 속성만 바꿔도 원래 기본 글꼴 크기·기울임 등을 유지한다. 화면·도구 모음·색 필터·차트 표시 형식·자동 크기·표 변환·인쇄에 같은 상속 규칙을 적용했다. 자동 글꼴색과 직접 지정한 검정을 색 필터에서 구분한다.
- 행·열의 고급 회전·축소 맞춤·대각선 테두리·보호 정보도 XLSX에 유지한다. 기본 글꼴 기준의 열 너비 환산을 가져오기/저장/차트에서 일치시켰다. 서식만 있는 행을 보존하되 수십만 빈 셀을 만들지 않는다. 행·열 구조 변경도 서식 기본값을 이동한다.
- 검증: 전체 검사 284개 중 283개 통과, Windows 전용 1개 건너뜀. 사용자 Normal 글꼴, 서식만 있는 행·열, 기본 서식으로 되돌린 셀, 잠금, 새 입력과 고급 속성을 JSON 및 XLSX 3회 왕복했다. 보조 시트나 이름이 최종 파일과 문서 속성에 남지 않는다. 실제 Mac Electron에서 빈 셀 표시→입력/서식 토글→실행 취소→글자색만 변경→저장·재열기를 통과했고 기존 표·입력 제한·고급 서식·표시 형식·PDF 인쇄 UI도 통과했다. 실제 Windows Excel 실행 검증은 수행하지 않았다.
- 기준: [OOXML 열 기본 서식과 Normal 글꼴 기준 너비](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.column?view=openxml-3.0.1), [기본 Normal 셀 스타일](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.cellstyle?view=openxml-3.0.1).

### 20차: 인쇄 원본 정보와 문서 속성

- 일반 시트의 용지 설정·여백·머리글/바닥글·수동 페이지 나눔·오류 무시 범위와 시트 속성을 보존한다. 연결된 프린터 설정 바이너리와 머리글 VML 이미지/미디어도 관계 ID·파일 경로·콘텐츠 유형을 맞춰 XLSX에 다시 쓴다. 반복 저장 시 경로가 중첩되거나 파일 수가 늘지 않는다.
- 페이지 레이아웃의 방향은 현재 시트의 문서 설정으로 저장하며 실행 취소/다시 실행할 수 있다. 차트 전용 시트도 지원하고 인쇄창의 기본 방향은 파일 설정을 따른다. XLSM의 파일 설정 변경은 기존 네이티브 저장 계획이 지원하지 않아 Excel을 안내하되 이번 출력의 방향은 인쇄창에서 고를 수 있다.
- 수동 페이지 나눔과 오류 무시 범위가 여러 행·열 삽입/삭제에 따라 갱신된다. 원래 작성자·최초 작성일·제목·설명·회사 등의 문서 속성을 유지하고, 마지막 수정 정보만 현재 저장으로 갱신한다.
- 검증: 전체 검사 287개 중 286개 통과, Windows 전용 1개 건너뜀. 프린터 설정·머리글 이미지·원래 속성을 포함한 XLSX 3회 왕복, 연결 경로/파일 수, 차트 시트 방향과 범위 이동을 확인했다. 실제 Mac Electron에서 방향 변경→실행 취소/다시 실행→인쇄창 기본값→셀 수정→저장·재열기를 통과했고 차트·이미지와 PDF 인쇄 UI도 다시 통과했다.
- 원본 Excel 인쇄 설정을 파일에 보존하는 것과 앱의 PDF 출력을 구분한다. 앱은 현재 A4·셀/개체를 이어서 배치하는 인쇄를 제공하며, Excel의 모든 프린터 옵션이나 머리글 이미지 배치를 그대로 렌더링하지는 않는다. 실제 Windows Excel 실행 검증은 수행하지 않았다.

### 21차: 텍스트 입력과 문서 간 복사 서식

- 텍스트 형식의 입력은 숫자·지수·백분율·논리값·오류 모양 문자열과 미완성 수식을 텍스트로 유지한다. 기존 숫자에 텍스트 표시 형식만 적용하거나 숫자를 값으로 붙여넣는 경우에는 원래 값의 종류를 바꾸지 않는다. 텍스트 수식에는 자동 괄호 완성과 참조 선택을 적용하지 않는다.
- 외부 일반 텍스트를 붙여넣을 때 대상 셀의 글꼴·색·표시 형식·메모·상세 서식을 유지한다. 텍스트 형식은 행·열 기본값도 반영한다.
- 내부 복사 스냅샷에 Normal·표·행·열에서 보이는 서식을 담고, 원래 Excel 상세 서식 정의를 독립적으로 보관한다. 다른 통합 문서를 연 뒤 붙여넣어도 이전 문서의 서식 번호를 새 문서에서 잘못 사용하지 않는다. 붙여넣기 검증 후에만 대상 서식 목록을 늘리고 기존 정의를 재사용한다. 값/수식만 붙여넣기와 시트 보호는 대상 서식을 유지한다.
- 검증: 전체 검사 291개 중 290개 통과, Windows 전용 1개 건너뜀. 실제 Mac Electron에서 텍스트 입력·외부 붙여넣기·실행 취소/다시 실행·숫자 값 붙여넣기·문서 간 복사·저장/재열기를 확인했다. 대각선 테두리·글자 회전·축소·잠금 등 상세 서식은 XLSX 모델로 확인했다. 기존 표·배열 및 오류/문자열 구분·시트 보호 UI도 통과했다. 조건부 서식 규칙 자체와 표 정의를 복사하여 만드는 기능은 별도 범위다.

### 22차: LET 지역 이름 수식

- LET에 최대 126개 이름/값과 최종 계산을 지정할 수 있다. 앞서 지정한 값, 중첩 범위에서의 같은 이름, 한글 이름, 가져온 `_xlpm.` 이름을 계산한다. 이름이 참조 셀이나 통합 문서의 정의된 이름 안으로 새지 않는다.
- 같은 계산을 재사용하며, 아직 계산되지 않은 참조 때문에 작업을 이어서 수행해도 RAND 같은 중간값을 다시 뽑지 않는다. 필요한 분기만 계산한다. 범위 메타데이터를 유지해 SUM·INDEX·ROW·ISREF 및 전체 열의 희소 집계에 사용할 수 있다. 기존 저장 배열의 결과에도 사용할 수 있으나 새 동적 스필 엔진을 추가한 것은 아니다.
- XLSX는 `_xlfn.LET`와 현재 값의 종류를 가진 캐시를 저장한다. 공식 LET 설명과 XlsxWriter의 미래 함수 저장 설명을 기준으로 구현했고, 실제 Windows Excel 실행을 대체한 검증으로 표시하지 않는다.
- 검증: 전체 검사 297개 중 296개 통과, Windows 전용 1개 건너뜀. 지역 범위·참조/배열·난수 재사용·형식 오류·126개 순차 계산·세 번의 XLSX 저장/재열기를 검사했다. 실제 Mac Electron에서 입력→종속 셀 변경→실행 취소/다시 실행→F9→상대 참조 복사→저장/재열기와 기존 재계산·이름 관리자 UI를 통과했다.
- 참고: [Microsoft LET](https://support.microsoft.com/en-us/excel/functions/let-function), [XlsxWriter 수식 저장](https://xlsxwriter.readthedocs.io/working_with_formulas.html).

### 23차: 셀 변경에 따르는 차트·이미지 위치

- 행·열을 바꾸어도 데이터 참조만 바뀌고 차트·이미지 위치는 그대로였던 문제를 고쳤다. 셀 기준 두 모서리, 한 모서리와 고정 크기, 절대 위치를 구분하여 이동·크기 조절을 반영한다. 두 모서리 형식의 `editAs=oneCell/absolute`도 같은 의미로 처리한다.
- 여러 행/열 삽입·삭제, 행 높이·열 너비 드래그, 자동 맞춤, 수동 숨김/해제에 연결했다. 삭제된 시작 지점은 남은 경계로 이동하고, 시트 끝의 큰 좌표는 희소 크기 목록으로 계산한다. 차트 전용 시트는 셀 위치 변경 대상에서 제외한다.
- 차트 설정에 셀 변경 시 배치를 추가했다. 새 차트는 셀과 함께 이동·크기 조절을 사용하며 이전 앱 문서의 절대 위치 동작과 가져온 Excel 배치를 유지한다. 차트를 직접 옮기거나 크기를 바꿔 저장해도 원래 위치 동작을 잃지 않는다. XLSM의 배치 설정 편집은 Windows 저장 경로가 지원하기 전까지 잠근다.
- 검증: 전체 검사 302개 중 301개 통과, Windows 전용 1개 건너뜀. 세 배치 방식, 삽입·삭제·숨김·백만 번째 행 좌표와 세 번의 XLSX 왕복을 확인했다. 실제 Mac Electron에서 차트/이미지 이동·부분 크기 변경·열 너비 드래그·배치 변경·실행 취소/다시 실행·차트 직접 이동 후 저장/재열기를 통과했다. 기존 차트 조작·행/열 크기·차트 전용 시트/이미지 UI도 통과했다.

### 24차: 값 축의 범위·눈금·로그·표시 형식

- 차트 설정에서 주 값 축, 분산/거품형의 가로 값 축, 보조 값 축의 최소/최대값·주 눈금 간격·표시 형식·로그 밑·값 순서·주 눈금선을 편집한다. 빈칸은 자동이며 자동 재설정 버튼을 제공한다. 백분율 축은 Excel 파일과 같이 1=100%로 입력한다. 불가능한 범위·간격·로그 밑·표시 코드는 적용 전에 안내한다.
- 자동 축은 읽기 쉬운 간격을 사용한다. 보조축의 독립 범위와 눈금을 그리며, 데이터는 그래프 영역에서 잘라 원래 데이터가 축/제목 영역을 침범하지 않게 한다. 로그 축의 0 이하 값은 제외하고 해당 경우를 표시한다. 작은 일반 숫자가 0으로만 보이던 눈금 표시도 보강했다.
- 가져온 값 축 설정을 미리 보기에 반영하고, 원래 교차점·소눈금·확장 XML은 유지하면서 바꾼 속성만 저장한다. 새 차트에도 실제 OOXML 축 설정을 기록한다. XLSM 연결 저장에서 아직 지원하지 않는 축/배치 편집은 UI와 저장 계획 양쪽에서 막는다.
- 검증: 전체 검사 308개 중 307개 통과, Windows 전용 1개 건너뜀. 선형·음수·작은 수·백분율·로그·반전·보조축·잘못된 설정과 세 번의 XLSX 저장/재열기를 확인했다. 실제 Mac Electron의 입력 오류 안내·적용·실행 취소/다시 실행·자동 재설정·유형 변경·재열기를 통과하고 축 글자와 그래프 영역을 시각 검사했다. 10유형/18조합, 기존 데이터/범례 배치와 PDF 인쇄 UI도 통과했다.
- 범주/날짜 축의 모든 간격·교차점·표시 단위, 추세선·오차 막대·개별 레이블 편집까지 구현한 것은 아니다. 참고: [Microsoft 값 축 설정](https://support.microsoft.com/en-gb/office/change-the-scale-of-the-vertical-value-axis-in-a-chart).

### 25차: 데이터 구간 이동과 선택 범위 입력

- Ctrl/⌘+방향키가 시트 다른 곳의 마지막 셀로 이동하던 동작을 현재 행/열의 연속 데이터 끝·다음 데이터·시트 경계로 바꿨다. 서식만 있는 빈칸은 건너뛰고, 빈 문자열을 반환하는 수식과 저장 배열 결과는 기록된 데이터로 취급한다. 숨김 대상은 이동에서 건너뛴다. 긴 이동은 작업 스레드에서 수행한다.
- 여러 셀을 선택한 뒤 Tab은 행 방향, Enter는 열 방향으로 범위 안을 순회한다. Shift로 거꾸로 이동하며 끝에서 처음으로 돌아온다. 편집 후에도 선택 영역을 유지하고 일반 방향키나 새 클릭은 범위 순회를 끝낸다. 숨김 행/열과 병합된 셀의 나머지 부분을 건너뛴다.
- 검증: 전체 검사 312개 중 311개 통과, Windows 전용 1개 건너뜀. 빈 구간·다른 위치의 데이터·수식 빈 문자열·배열·숨김·역방향과 백만 행 병합 범위 건너뛰기를 확인했다. 실제 Mac Electron에서 구간/시트 끝 이동·Shift 확장·4셀 연속 입력·Tab/Enter/역방향·활성 셀과 범위 표시·전체 범위 복사·저장/재열기를 통과했다. 기존 수식 편집/참조 선택/IME 보호·마지막 행 확대·저장 배열 UI도 통과했다.

### 26차: 상속된 셀 서식 초기화와 상세 서식 복사

- 열 전체에서 상속한 빨간 글자/숫자 표시가 서식 지우기 뒤에도 남는 문제를 실제 앱에서 재현했다. 기록이 없는 빈 셀까지 Normal 재설정 표식을 저장하여 행·열 서식을 덮어쓰고, 값·수식·메모·링크를 유지한다. 문자별 서식만 제거할 때는 텍스트도 유지한다.
- 메뉴를 **직접 서식 초기화**로 명확하게 표시했다. 조건부 서식과 표의 테마는 별도 기능으로 유지하며 조건부 서식이 있으면 관리 위치를 안내한다. Excel의 조건부 규칙까지 제거하는 Clear Formats 전체 동작을 구현했다고 표시하지 않는다.
- 서식 복사와 서식만 붙여넣기에 원본 상세 서식·상속 서식·잠금 정보를 연결하고 대상의 오래된 문자별 글꼴이 다시 나타나지 않게 했다. 서식 복사는 선택한 가시 셀에만 적용하여 숨김 행 때문에 선택 범위 밖까지 칠하지 않는다. Esc로 취소할 수 있다. XLSM의 전체 초기화/상세 서식 복사는 연결 저장이 지원하기 전까지 안내한다.
- 검증: 전체 검사 315개 중 314개 통과, Windows 전용 1개 건너뜀. Normal 재설정·빈 셀·원문/메모/링크·문자별 서식·배열 정의·잠금·대각선/회전 형식의 파일 모델을 검사했다. 실제 Mac Electron에서 문제 재현→수정→동일 동작 재검사, 초기화·실행 취소/다시 실행·서식 복사/취소·숨김 셀과 범위 밖 보호·저장/재열기를 통과했다. 문서 간 클립보드와 Normal/행/열 서식 UI도 다시 통과했다.

### 27차: 최신 Excel 오류값 종류 보존

- 엔진과 파일/클립보드에서 사용하던 오류 목록을 공통 정의로 맞췄다. 기존 7종 외에 GETTING_DATA·SPILL·CALC·FIELD·BLOCKED·UNKNOWN·CONNECT·BUSY·PYTHON 오류와 같은 글자의 텍스트를 구분한다. 수식의 오류 상수와 IFERROR도 이 종류를 인식한다.
- 가져온 실제 오류 셀과 지원하지 않는 수식의 오류 캐시가 저장 때 일반 문자열로 바뀌지 않는다. 명시적인 텍스트는 계속 텍스트로 저장하며, 값 붙여넣기와 CSV의 문자열 구분에도 같은 정의를 적용한다. 스필·연결·Python 계산 기능 자체를 추가한 것은 아니다.
- 검증: 전체 검사 316개 중 315개 통과, Windows 전용 1개 건너뜀. 16종 각각의 실제 오류·문자열·오류/문자열 캐시와 IFERROR 상수를 세 번 XLSX 왕복했다. 실제 Mac Electron에서 CALC/SPILL과 같은 글자의 텍스트를 계산하고 저장/재열기하여 구분을 확인했다.
- 참고: [Microsoft SPILL](https://support.microsoft.com/en-us/excel/how-to-correct-a-spill-error), [CALC](https://support.microsoft.com/en-us/excel/how-to-correct-a-calc-error), [Python 관련 오류](https://support.microsoft.com/en-us/excel/python/troubleshoot-python-in-excel-errors).

### 28차: 문서 간 테마·팔레트 색 복사

- 다른 테마의 문서에 붙이면 화면에서는 맞지만 XLSX 저장 후 색이 바뀔 수 있는 경로를 발견해 재현했다. 이전 테마/인덱스 번호를 대상 문서에서도 그대로 해석한 것이 원인이었다.
- 복사 스냅샷의 글꼴·테두리·그라데이션 등 상세 색과 문자별 글자색을 원본 테마·팔레트·명암 기준의 RGB로 고정한다. 원본 문서의 정의는 바꾸지 않는다. 같은 문서에서 원래대로 둔 셀의 테마 관계는 유지한다.
- 검증: 전체 검사 317개 중 316개 통과, Windows 전용 1개 건너뜀. 실제 Mac Electron에서 서로 다른 문서로 복사→화면 색→저장→재열기를 확인하고, 명암 글자색·사용자 인덱스 대각선·그라데이션·문자별 색의 XLSX 모델을 검사했다. 상세 서식 복사/취소·숨김 범위 보호 UI도 다시 통과했다.

### 29차: 정렬할 때 행 기본 서식 보존

- 행의 기본 글꼴·색·숫자 표시가 다른 범위에서 정렬하면, 값이 목적지 행의 서식을 받아 저장/재열기 전후 결과가 달라지는 문제를 재현했다. 실제 이전 Mac 패키지도 숫자 5를 정렬한 뒤 500.0%로 표시했다.
- 서로 다른 행 서식을 건너 이동하는 셀에만 원래 Normal/열/행 서식을 기록한다. 빈 셀과 직접 서식, 회전·대각선·잠금 정보도 유지한다. 서식 정의는 재사용하고 표의 줄무늬는 목적지 행에서 계속 계산한다. 일반 대용량 정렬에는 셀별 서식 정보를 추가하지 않는다.
- 작업 스레드의 새 서식 정의를 셀 목록과 같은 변경 기록에 적용한다. 실행 취소/다시 실행과 준비된 계산 문서가 같은 인덱스를 사용한다. 네이티브 저장이 이 서식 이동을 지원하지 않는 XLSM의 행 기본 서식 정렬은 Excel/XLSX 사본 안내와 함께 변경 전에 중단한다.
- 검증: 전체 검사 322개 중 321개 통과, Windows 전용 1개 건너뜀. 저장 전후 정렬 일치, 숨김 행 고정, 빈칸·Normal·고급 서식·표 줄무늬, 1만 행의 정의 재사용과 XLSM 원자적 거부를 검사했다. 실제 Mac Electron에서 같은 문제 시나리오를 재검사하여 정상 숫자/백분율·글꼴·색상, 실행 취소/다시 실행과 XLSX 회전 서식·저장/재열기를 통과했다. 기존 영역 정렬과 표 관리 UI도 함께 확인했다.

### 30차: 표 수식의 표준 저장 표기

- 독립 LibreOffice 재계산에서 표 안의 `[@Qty]*[@Price]`가 #N/A가 되는 것을 확인했다. 같은 수식을 Microsoft의 명시적인 `Sales[[#This Row],[Qty]]` 표기로 저장하면 6·20과 요약/집계 26이 일치했다.
- XLSX의 셀 수식과 계산 열 정의를 함께 정규화한다. 현재 표의 암시적 참조에 표 이름을 넣고, 현재 행의 @ 표기를 #This Row로 저장한다. 문자열·외부 링크·알 수 없는 열은 바꾸지 않으며 이스케이프된 열 이름과 열 구간, 미래 함수 접두어를 유지한다. 화면에서 입력하는 짧은 표기는 계속 지원한다.
- 검증: 문자열/특수문자/구간/명시·암시 참조, LET 접두어와 원래 매개변수, 세 번의 XLSX 왕복을 추가 검사했다. 전체 325개 중 324개 통과, Windows 전용 1개 제외. 실제 Mac Electron의 표 편집/정렬/계산·행열 구조 변경/일반 범위 변환·저장/재열기를 확인했다.
- 참고: [Microsoft 구조화 참조 규격](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/bcd72180-31a3-423b-8f83-d224b2286da3), [구조화 참조 사용](https://support.microsoft.com/en-us/excel/using-structured-references-with-excel-tables).

### 31차: XML 불리언 날짜 체계와 독립 파일 검사

- LibreOffice가 저장한 유효한 `date1904="true"`를 ExcelJS 4.4가 false로 읽어 날짜 체계가 사라지는 문제를 찾았다. 실제 이전 Mac 패키지도 해당 파일의 날짜 체계를 인식하지 못했다. 라이브러리가 날짜 번호를 Date 객체로 바꾸기 전에 검사용 ZIP 복사본에서 true를 1로 정규화한다. 원본 입력 ZIP은 바꾸지 않는다.
- true/1/false/0의 두 날짜 체계를 날짜 상수·날짜 수식 결과·일반 숫자 수식·저장/재열기에서 확인했다. 전체 326개 중 325개 통과, Windows 전용 1개 제외. 실제 Mac Electron에서 true 문서 열기→날짜·수식·날짜 필터→저장/재열기를 통과했다.
- 설치된 LibreOffice 26.8.0.3의 별도 프로필에서 항상 재계산을 설정하고, 생성 파일의 숫자 캐시 하나를 일부러 -999로 바꾼 뒤 열기/재계산/저장을 검사했다. 표/구조화 참조/LET·전체 열 조건 집계, 1904 날짜, 이름/기존 배열, 상속 서식 정렬, 18개 차트 조합 등 5문서를 확인했다. 23개 값 중 22개가 일치했고 18개 차트를 다시 읽었다. 캐시를 그대로 재사용하는 검사는 통과로 세지 않는다.
- 중첩 LET 한 식은 앱 결과 5와 LibreOffice #NAME?가 달랐다. 명시적인 매개변수 접두어와 서로 다른 내부 이름으로도 차이를 확인했다. 독립 프로그램과의 미해결 호환성 차이로 기록하며 실제 Microsoft Excel/VBA 검증을 한 것으로 해석하지 않는다. 이 한 식을 제외한 표 계산·배열 결과·날짜·차트 보존은 독립 왕복을 통과했다.
- 재현 명령은 `npm run test:interop:libreoffice`이며, LibreOffice를 별도 설치한 환경에서만 실행한다. 사용자의 프로그램 프로필이나 문서를 사용하지 않는다. [LibreOffice 재계산 설정](https://books.libreoffice.org/en/CG262/CG26216-SettingUpCustomizing.html), [설정 값 정의](https://github.com/LibreOffice/core/blob/master/officecfg/registry/schema/org/openoffice/Office/Calc.xcs)를 참고했다.

### 32차: XLSM 서식 이동과 원본 상태 검증

- 상세 서식을 복사한 화면과 Windows XLSM 저장 계획이 달라질 수 있는 경로를 재현했다. 대각선·회전/축소·특수 채우기·취소선·잠금, 문자별 서식·링크 이동을 현재 저장 경로가 표현하지 못하면 편집 단계에서 안내한다. 붙여넣기는 임시 서식 인덱스를 목적지 정의에 매핑한 뒤 검사하며 아직 문서에 반영하지 않는다. 정렬·채우기에도 연결하고 저장 계획에서 다시 확인한다.
- 값/수식만 붙여넣기와 지원하는 글꼴/색상 복사는 유지한다. 기존 상세 서식을 바꾸지 않는 경우도 허용한다. 일부 고급 이동을 임의로 단순화해 저장하는 대신 Excel/XLSX 사본을 안내한다.
- 행·열 기본 서식이 있는 XLSM의 원본 스냅샷을 검증할 때 공통 서식 목록이 빠져 열기/복구가 실패하는 문제도 재현했다. 원본과 현재 문서가 사용하는 공통 정의로 검증하고 원본 바이너리·범위·참조를 유지한다.
- 검증: 전체 331개 중 330개 통과, Windows 전용 1개 제외. 미지원 상세 서식·링크의 차단, 적용 전 문서 불변, 기본 서식/값 복사의 저장 계획, XLSM 원본의 JSON 복구를 확인했다. 실제 Mac Electron에서 행/열 서식이 있는 원본 상태를 열고 상세 붙여넣기 거부→값만 붙여넣기→실행 취소를 통과했다. 원본 보관·저장 계획·UI 검사이며 실제 Microsoft Excel/VBA 실행은 아니다.

### 33차: 문서 교체 시 이전 설정창 정리

- 기존 편집 시나리오 전체를 재검사하다가 정렬 확인창이 열린 상태에서 다른 파일을 열면 이전 창이 남아 새 시트 탭을 가리는 문제를 발견했다. 서식창 등에서 남은 이전 문서의 적용 버튼도 새 문서에 연결될 수 있는 상태였다.
- 새 문서를 성공적으로 읽은 시점에 이전 문서의 일반 설정창과 팝업을 닫는다. 파일을 읽지 못한 경우에는 현재 문서의 창을 유지한다.
- 검증: 실제 Mac Electron에서 셀 서식창이 열린 상태로 파일 교체→이전 창 없음→새 문서의 다른 시트 선택을 확인했다. 기존 영역 정렬/차트 삽입·저장·실행 취소 시나리오와 함께 통과했다. 전체 플랫폼 회귀도 같은 검사를 포함해 다시 실행한다.

### 34차: 긴 텍스트 복제 전 용량 확인과 대량 채우기

- 셀 복제본을 모두 만든 뒤 원문 총량을 검사해, 결국 거부될 긴 문자열 붙여넣기/채우기에서도 먼저 큰 메모리를 쓸 수 있는 경로를 발견했다. 원문을 만들고 복제하기 전에 문서의 기존 문자 수, 덮어쓸 셀과 잘라내기 원본에서 비워질 양을 계산한다. 빈 셀 건너뛰기·겹치는 이동·값/수식·날짜 변환 후의 실제 원문 길이를 반영하며 실행 취소의 문서 전체 검사도 유지한다.
- 아래로/오른쪽 채우기에서 첫 가시 원본 위치를 셀마다 다시 배열로 만들던 탐색을 한 번으로 줄였다. 대상과 문자 예산을 먼저 준비해 범위가 커져도 같은 탐색을 반복하지 않는다.
- 검증: 전체 337개 중 336개 통과, Windows 전용 1개 제외. 덮어쓰기 순서에 따른 잘못된 거부, 겹치는 잘라내기, 건너뛴 빈칸, 값/수식/서식 전용, UTF-16 문자 길이와 가시 자동 채우기를 확인했다.
- 실제 Mac Electron에서 99,975,168자의 합성 문서(공유 문자열 XLSX 23,832바이트)를 열고 10만 셀 붙여넣기/아래 채우기/모서리 채우기를 원자적으로 거부했다. 필요한 원문을 줄인 뒤의 정상 붙여넣기와 실행 취소/다시 실행을 통과했다. 로컬 거부 응답은 94ms, 별도의 정상 10만 셀 채우기/실행 취소/다시 실행 중 채우기는 420ms였다. 환경에 따른 보장 수치나 모든 메모리 사용량의 상한을 뜻하지 않는다.
