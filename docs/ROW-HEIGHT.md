# 표와 행 높이 보존 — 0.7.18 개발판

2026-10-21. Slide Studio의 `72409b8`(PPTX 표 행 높이 보존)과 비교했습니다. Slide는 72pt 외곽 프레임 안에 네 개의 32pt 행이 있는 표를 가져오면서 행들을 18pt로 줄여 한글이 잘렸습니다. Sheet는 PPTX를 읽거나 표 외곽 프레임에 행 높이를 맞추는 경로가 없으므로 그 코드의 직접적인 복제 문제는 없습니다.

Sheet에서는 다음 행 높이 손실을 확인하고 수정했습니다.

- **XLSX 기본 높이:** `sheetFormatPr`의 기본 행 높이를 가져오지 않아, 32pt 높이의 문서도 개별 높이가 없는 행은 앱 기본 25px로 보였습니다. 기본 높이를 px로 변환해 가져오고 XLSX 저장·재열기에 보존합니다. 명시적 높이와 숨김 행의 원래 높이도 함께 유지합니다.
- **외부 표 붙여넣기:** HTML에서 읽은 행 높이가 셀 붙여넣기 자료로 넘어가지 않았습니다. 행 높이를 함께 전달하고, 원본 높이를 대상 행의 최소 높이로 반영합니다. 이미 더 큰 대상 행은 줄이지 않습니다. 표의 외곽 `height`가 작아도 명시적인 행 높이를 축소하지 않습니다.
- **다른 앱으로 복사:** 개별 행 높이가 없는 XLSX 표를 복사할 때, 문서 기본 높이 대신 25px를 기록하던 경로를 수정했습니다. 화면에서 사용 중인 기본 행 높이를 HTML에도 기록합니다.

붙여넣기 높이는 숨김 행을 건너뛴 실제 대상 행과 반복 선택 범위에 맞춥니다. 셀·병합·높이를 한 번에 실행 취소하며 화면 배치와 자동 복구도 함께 갱신합니다. 일반 텍스트, 값·수식·서식만 붙여넣기, 전치와 연산 붙여넣기는 행 높이를 바꾸지 않습니다. 공유 HTML 형식과 Slide 저장소의 코드는 변경하지 않았습니다.

## 검증

- `tests/row-height.test.mjs`: 기본 높이, 명시 높이, 불균등 행, 숨김/해제에 필요한 원래 높이, 병합과 작은 사용 범위 메타데이터, 빈 높이 전용 행, XLSX 왕복, 숨김 행 대상 매핑·반복, 더 큰 대상 높이, 잘못된 높이와 붙여넣기 모드 보호를 확인합니다. 같은 네 검사는 수정 전 소스에서 1개 통과·3개 실패, 수정 후 네 개 모두 통과했습니다.
- `tests/ui-studio-clipboard.mjs`: 실제 Electron과 OS 클립보드에서 72pt 표 외곽·32pt 행 네 개, 불균등 행, 세로 병합, 더 큰 대상 행을 확인합니다. 행·병합 셀의 실제 화면 높이와 한글 범위의 세로 넘침, 실행 취소·다시 실행·자동 복구 후 재열기·XLSX 저장/재열기, XLSX 기본 행 높이로 표시·복사와 숨김 해제를 검사합니다. 사용자 프로필과 분리하며 클립보드는 종료 시 복원합니다.
- [Windows·Ubuntu·Mac 회귀 CI](https://github.com/beaur8-prog/sheet-studio/actions/runs/39550630788)가 모두 통과했습니다. Windows 단위 검사 176개, Mac·Linux 각각 175개 통과 및 Windows 전용 1개 제외이며 각 플랫폼의 화면 검사 23개 모음을 실행했습니다. Mac arm64 앱 패키지에서도 표 교환·행 높이·행열 크기·워크시트·자동 복구와 데스크톱 연결 등 5개 검사를 통과했습니다.

일반 XLSX의 명시적 행 높이는 수정 전에도 외곽이나 사용 범위에 맞춰 축소되지 않았습니다. 해당 사례는 회귀 검사에서 유지합니다. 실제 Microsoft Excel·PowerPoint의 실행이나 파일 왕복을 검증했다는 의미는 아닙니다. 고정 높이보다 큰 글자나 미지원 서식의 모든 잘림을 자동 보정하는 기능은 아닙니다.

이 수정은 개발 소스에만 반영하며 공개 0.7.17 다운로드와 리토스 공유본에는 아직 포함되지 않습니다.
