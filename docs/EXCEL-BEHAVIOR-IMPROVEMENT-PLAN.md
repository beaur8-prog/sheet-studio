# Excel 동작 비교 기반 사용성·기능 개선 계획

작성일: 2026-11-05

대상: Sheet Studio **0.7.37**, 기준 커밋 **`bbfd2905f6e538ab8e43525293fbbce0838b9f58`**

상태: **첫 4시간 완료 · 두 번째 4시간 완료 · 전체 계획 진행 중** — [첫 기록](EXCEL-FOUR-HOUR-20261105.md), [두 번째 기록](EXCEL-NEXT-FOUR-HOUR-20261105.md). 아래는 전체 계획이며 한 작업 묶음에서 전부 완료한다는 뜻은 아니다.

## 1. 목표와 우선순위

목표는 일반 사용자가 Excel에서 하던 **입력 → 표 정리 → 계산 → 차트·보고서 작성 → 저장 → 다시 열기**를 Sheet Studio에서도 예상대로 끝내도록 하는 것이다. 기능 개수보다 계산 결과의 신뢰성, 원본 보존, 반복 작업의 편의성을 우선한다.

가장 먼저 진행할 세 가지는 다음과 같다.

1. **계산·저장 신뢰성:** 계산값과 파일 캐시의 차이, 미지원 개체, 피벗 설정의 충돌을 사용자가 알 수 있게 하고 조용한 손실을 막는다.
2. **기본 편집의 일관성:** 선택·입력 모드·한글 조합·복사 범위·실행 취소가 메뉴와 단축키에서 같은 결과를 내게 한다.
3. **표를 중심으로 한 업무 흐름:** 행·열 추가, 계산 열, 필터, 차트, 피벗 새로 고침을 연결해 자료가 늘어나도 보고서를 쉽게 유지한다.

기존 [핵심 계획](CORE-IMPROVEMENT-PLAN.md)과 [0.7.31 추가 개선](CORE-FIVE-HOUR-20261031.md)의 후속 계획이다. 이미 구현된 동적 배열, 색 필터, 셀 서식, 차트 10종, 페이지 설정을 새 기능으로 다시 세지 않는다. 이번 문서 작성은 앱 수정이나 배포를 의미하지 않는다.

## 2. 비교 기준과 근거의 구분

- **주 비교 대상:** Windows 데스크톱 Excel for Microsoft 365의 정식 채널. 실제 비교 때 버전·빌드·언어·지역·계산 모드·설정·확대율을 기록한다.
- **보조 비교 대상:** Mac 데스크톱 Excel. 단축키, 파일 선택창, 한글 입력은 Windows와 따로 비교한다. 웹 Excel의 동작을 데스크톱의 정답으로 사용하지 않는다.
- **계획 작성 때 확인한 것:** 당시 저장소의 소스·테스트·검증 기록과 Microsoft 공식 설명. 함수 목록은 실제 모듈을 읽어 **384개 이름, 별칭 30개 포함**을 확인했다.
- **계획 작성 때 하지 않은 것:** 실제 Microsoft Excel 실행, 새 사용자 시나리오 실행, 새 성능 측정. 이후 두 번의 개선 작업에서 실행한 앱·반복·파일 검사는 각각의 결과 문서에 기록하며 실제 Excel 비교와 구분한다.
- 실제 Excel 실행 환경은 현재 확보되어 있지 않다. 기존 측정 자료와 공식 규칙으로 진행 가능한 항목부터 구현하고, 버전·설정에 따라 달라지거나 근거가 충돌하는 항목은 **실제 Excel 대조 대기**로 남긴다.

문서의 **확인된 차이**는 코드 또는 현재 기능 안내로 확인한 범위 차이다. **확인 과제**는 테스트해야 할 후보이며 새로 재현한 결함이라는 뜻이 아니다. **제품 제안**은 Excel의 동작을 참고해 Sheet Studio에 도입하려는 개선이다.

## 3. 현재 상태와 개선 방향

아래 표는 계획 작성 당시 0.7.37 기준이다. 0.7.38의 구현·검사·남은 범위는 [첫 4시간 결과](EXCEL-FOUR-HOUR-20261105.md)의 21개 시나리오 표에 따로 기록했다. 0.7.39의 입력 규칙·날짜 입력·시각 규칙·표 연결 피벗·계열별 차트·파일 해석 취소와 보존 결함 수정은 [두 번째 4시간 결과](EXCEL-NEXT-FOUR-HOUR-20261105.md)에 기록했다. 규칙 복사/채우기, 최종 모델 적용 지연, 원본 차트의 부분 편집·날짜 축, 외부 피벗 역변환, 고급 시각 규칙과 실제 Excel·접근성 대조는 남아 있다.

## 4. 구현 작업 묶음

### P0-A. 계산 결과와 파일 보존을 신뢰할 수 있게 만들기

**사용자 결과:** 저장 후 값·수식·개체가 왜 바뀌었는지 추측할 필요가 없고, 계산하지 못하는 내용을 정확히 안다.

1. 문서를 열 때 기능 목록을 수집해 `계산·편집 가능 / 원본 보존만 가능 / 손실 가능 / 판정 불가`로 나눈다. 이 목록은 실제 지원 파트 탐지 범위에 한정한다.
2. 저장 전에 변경된 기능과 출력 형식을 함께 검사한다. 일반 파일은 기존 흐름을 유지하고 손실 가능 항목만 구체적으로 안내한다. 결과를 안전하게 만들 수 없는 원본 덮어쓰기는 거부하고 사본 저장·취소를 제공한다.
3. 계산 지원, 유효한 원본 캐시, 변경으로 오래된 캐시를 화면·상태·차트·인쇄에서 일관되게 구분한다. 이 구분은 이미 일부 구현되어 있으므로 표시와 경계 사례를 보강한다.
4. [기존 35차 비교](EXCEL-IMPROVEMENTS.md)의 SUMIF/SUMIFS/AVERAGEIFS 빈칸·논리값·오류 차이를 작은 재현 자료로 분리한다. LibreOffice 결과만으로 Excel 기대값을 바꾸지 않는다.
5. Excel에서 바꾼 피벗 정의와 앱의 저장 설정이 다른 경우, 오래된 앱 설정으로 바로 재구성하지 않도록 탐지한다. 역변환이 불가능하면 저장된 결과를 유지하고 제한을 알린다.
6. 384개 함수 카탈로그와 README의 380개 표기 차이를 정리할 수 있도록 문서·도움말의 개수와 지원 상태를 하나의 목록에서 생성한다. 이름 개수와 검증된 인수 조합 수는 별도로 기록한다.

**주 변경 위치:** `io.mjs`, `xlsx-preservation*.mjs`, `external-xlsx.mjs`, `engine.mjs`, `function-runtime.mjs`, `array-*.mjs`, `pivot-xlsx.mjs`, `calculation-display.mjs`.

**완료 기준:** 선택한 지원 기능의 XLSX 3회 왕복에서 값의 종류·수식·참조·개체 관계가 유지된다. 보존 대상으로 선언한 미지원 파트도 유지되며, 저장 실패 시 기존 파일과 열린 문서는 불변이다. 대조 불가능한 항목은 통과 수에서 제외한다.

### P0-B. 선택·입력·복사를 하나의 일관된 편집 흐름으로 정리하기

**사용자 결과:** 셀을 선택하고 메뉴를 누르면 원래 대상에 적용되며, 한글 입력과 키보드 이동이 끊기지 않는다.

1. `선택 / 직접 입력 / F2 커서 편집 / 수식 참조 지정 / 한글 조합 / 대화상자 / 파일 작업` 상태에서 각 키·포인터 동작을 표로 고정한다. [Excel 단축키][ms-shortcuts]를 기준으로 OS 차이를 남긴다.
2. 리본·우클릭·단축키가 동일한 명령과 대상 범위를 사용하도록 정리한다. 메뉴를 여는 동안 대상은 유지하고, 다른 문서로 전환하면 이전 메뉴의 적용을 차단한다.
3. 서식 창에는 적용 범위와 혼합값을 표시한다. Esc/취소는 원본을 바꾸지 않고, 적용은 한 번의 실행 취소로 돌아간다. 색상 적용/취소 버튼은 기존 구현을 유지한다.
4. 필터와 수동 숨김이 있는 복사를 별도 시나리오로 대조한다. 필요하면 `전체 셀 / 보이는 셀` 선택과 붙여넣기 대상 안내를 추가한다. 기존 숨김 셀 보호 정책 변경은 실제 Excel 관찰 및 사용자 영향 검토 뒤 결정한다.
5. 빠른 이동 후 첫 한글, 조합 중 Enter/Esc/방향키, 마우스 이동 직후 입력을 Windows/Mac의 실제 IME에서 확인한다. 합성 composition 이벤트 검사와 실제 IME 검사를 따로 기록한다.
6. 큰 작업이 실행 취소 예산을 넘으면 변경 전에 복구 범위를 알린다. 단일 작업의 실패·취소는 부분 반영 없이 끝나게 한다.

**주 변경 위치:** `main.mjs`, `cell-navigation.mjs`, `cell-paste.mjs`, `cell-clipboard.mjs`, `cell-format-ui.mjs`, `history.mjs`, `workbook-tasks.mjs`.

**완료 기준:** 직접 입력과 F2 편집의 방향키 의미가 섞이지 않는다. 같은 명령의 리본/우클릭/단축키 결과가 같고 선택·포커스·실행 취소가 유지된다. IME 실측 미실시 플랫폼은 명시한다.

### P1-A. 표와 데이터 입력 기능 완성도 높이기

**사용자 결과:** 매출·재고 표에 새 항목과 계산 열을 추가할 때 범위를 계속 수동으로 고치지 않는다.

- 표 바로 오른쪽 입력에 따른 열 확장과 명시적 범위 변경을 추가한다. 아래쪽에 더 넓은 자료를 붙이는 경우 등은 [Excel의 확장 규칙][ms-table]과 구분해 처리한다.
- 요약 행이 있는 표의 마지막 데이터 행에서 새 행 추가, Tab 이동, 계산식/필터/스타일 상속을 검증한다. 다른 표·병합·배열과 충돌하면 전체를 취소한다.
- 계산 열의 예외값을 보존하고 `이 셀만 변경 / 열 전체에 적용`을 이해할 수 있게 한다. 표 이름·열 이름 변경과 열 삭제는 수식·이름·차트 참조에 함께 반영한다.
- 데이터 유효성 작성 창을 추가한다. 1차는 목록·정수·소수·날짜, 2차는 시간·텍스트 길이·사용자 수식이다. 입력 안내와 오류의 중지/경고/정보 차이를 포함한다.
- 색조·데이터 막대는 규칙 모델 → 화면 → 인쇄 → XLSX 입출력 순서로 연결한다. 아이콘 집합은 P2로 분리한다.

**주 변경 위치:** `table-data-edits.mjs`, `table-ui.mjs`, `table-structure.mjs`, `table-references.mjs`, `cell-constraints.mjs`, `worksheet-ui.mjs`, `conditional.mjs`.

**완료 기준:** 표 확장·규칙 변경을 실행 취소하고 저장/재열어도 범위·열 ID·계산식·필터·스타일이 일치한다. 유효성 검사는 직접 입력과 붙여넣기를 구분해 대조하며, Excel보다 엄격한 정책은 제품 차이로 표시한다.

### P1-B. 차트 삽입 결과를 예측 가능하게 만들기

**사용자 결과:** 선택한 데이터에서 어느 열이 제목이고 어떤 값이 그래프로 나오는지 삽입 전에 확인한다.

1. 삽입 창에 `항목 이름 / 계열 이름 / 값`의 작은 표와 실제 차트 미리 보기를 추가한다. 숫자인 첫 행·열을 자동 누락하지 않는 기존 동작은 유지한다.
2. 단일 계열 막대형은 항목명을 가로축에 두고 같은 색과 범례 생략을 유지한다. 사용자가 선택한 다중 계열의 색·범례는 유지한다.
3. 계열 추가·삭제·순서·이름·X/Y 범위를 편집할 수 있게 한다. 가져온 원본 차트의 지원 가능한 참조만 부분 변경하고, 고급 설정을 잃는 변환은 명시적으로 구분한다.
4. 빈 셀을 간격/0/선 연결로 처리하는 옵션을 유형별로 추가한다. `#N/A` 옵션은 Excel 버전별 제공 여부와 결과를 대조한 뒤 지원한다. 현재 공식 설명도 채널 제약을 명시한다. [빈 셀·숨김 데이터][ms-chart-empty]
5. 날짜 축 간격, 긴 한글 범주, 범례 줄바꿈, 음수·0·오류, 축 범위와 보조축을 확인한다. 화면·PDF·XLSX에서 같은 계열을 사용하게 한다.

**주 변경 위치:** `chart-ui.mjs`, `chart-model.mjs`, `chart-schema.mjs`, `chart-render.mjs`, `chart-axis*.mjs`, `chart-xlsx.mjs`.

**완료 기준:** 가로/세로 한 줄의 4개 값은 해당 유형에 맞는 4개 항목으로 반영된다. 18개 기존 조합의 계열·항목·참조·숨김 정책이 왕복 후 유지된다. 원형의 여러 계열, 0값, 불완전한 거품형 자료는 누락처럼 보이지 않도록 설명한다.

### P1-C. 피벗과 반복 보고서 작업 개선하기

**사용자 결과:** 원본에 새 자료를 넣고 새로 고침해도 보고서의 서식과 의도가 유지된다.

- P0-A의 외부 변경 충돌 탐지 이후, 먼저 일반 범위 기반 Excel 피벗의 필드·배치·필터 역변환을 지원한다. OLAP/Data Model 등은 분리한다.
- 셀 주소 대신 표의 안정된 ID·열 ID로 원본을 연결하는 방식을 추가해 표 확장을 추적한다. 가져온 고정 범위를 임의로 자동 확대하지 않는다.
- 새로 고침 시 숫자 형식·열 너비·사용자 서식을 유지하는 옵션을 제공한다. [Excel 서식 유지 옵션][ms-pivot-format]을 기준으로 확인한다.
- 날짜의 연/분기/월 그룹, 전체 대비 비율 표시를 다음 순서로 추가한다. 슬라이서·계산 필드·드릴다운은 별도 단계로 둔다.
- 찾기·바꾸기에 범위·값/수식 선택과 결과 목록을 추가한다. 바꾸기 직전에는 대상과 변경 수를 검증한다.

**완료 기준:** 원본 추가 → 새로 고침 → 실행 취소/다시 실행 → XLSX 재열기에서 합계와 설정·서식이 일치한다. Excel에서 편집한 파일을 열 때 과거 앱 설정으로 덮어쓰지 않는다.

### P1-D. 대용량·인쇄·접근성 개선하기

- 긴 열기·저장·재계산·정렬·피벗 작업은 실제 단계와 처리량을 알린다. 추정할 수 없는 시간에 가짜 백분율을 표시하지 않는다.
- 취소 가능한 작업은 작업 스레드의 취소 요청과 결과 세대 확인을 연결한다. 저장의 파일 교체 구간처럼 취소가 불가능한 짧은 단계는 별도로 표시한다. 취소 후 기존 문서·파일을 유지한다.
- 한도를 무조건 올리지 않는다. 숫자·긴 한글·개별 서식·수식·스필이 섞인 문서를 측정하고, 큰 편집은 사전 계산 후 한 번에 반영한다.
- 인쇄 미리 보기와 최종 PDF가 같은 페이지 계산을 쓰도록 하고 배율·반복 제목·개체 잘림을 미리 확인한다. 현재 20,000셀 인쇄 제한 완화는 페이지 단위 생성의 메모리 검증 뒤 결정한다.
- 키보드만으로 열기·입력·서식·필터·차트·저장을 완료하는지 검사한다. 화면 읽기 프로그램의 활성 셀·좌표·값·오류 안내, 대화상자 포커스 복귀, 고대비를 확인한다.

## 6. 검증 방법과 증거 관리

### 기대값의 신뢰 수준

| 수준 | 근거 | 사용 방법 |
|---|---|---|
| A | 같은 원본을 실제 Excel에서 조작·계산·재저장한 결과 | 해당 Excel 빌드와 설정의 직접 비교 결과 |
| B | Microsoft 공식 문서 및 저장소의 기존 Excel 측정 자료 | 문서화된 규칙·과거 빌드의 회귀. 현재 빌드 실측과 구분 |
| C | OOXML 검사·독립 생성기·LibreOffice 비교·자체 계산 | 파일 구조·자체 일관성·불일치 후보 발견. Excel 동등성의 증명으로 사용하지 않음 |

기존 `tests/fixtures/excel-functions.json`, `excel-function-edges.json`, `excel-filters.json` 등을 출처·측정 버전과 함께 재사용한다. 문서와 실측이 다르면 최소 재현 자료를 유지하고 환경 차이를 확인한다.

각 사례에는 `ID, 입력 파일 SHA-256, Sheet 커밋/버전, Excel 빌드·설정, 조작 순서, 기대값 출처, 실제값, 차이 유형, 재현 전/후 결과, 증거 경로`를 남긴다. 상태는 `미실시 / 통과 / 실패 / 근거 확보 대기 / 의도된 차이` 중 하나로 기록한다. 전체 호환성 백분율 대신 **명시한 사례 중 통과 수와 미실시 수**를 보고한다.

XLSX는 ZIP 전체 바이트가 아니라 값의 종류·수식·정의·참조·관계와 지원 개체를 비교한다. XML 순서·계산 캐시 갱신 등 의미가 같은 차이는 허용한다. 수정하지 않은 불투명 바이너리와 보존 계약 파트에는 별도의 해시/내용 검사를 적용한다. 실제 Excel에서는 복구 경고 없이 열리는지도 확인한다.

### 자동 검사와 실제 앱 검사

- 논리: `npm test`, 기능별 실패 재현 테스트. 임계값·오류·원자적 취소를 검사하고 구현을 그대로 따라 쓰는 테스트는 피한다.
- 편집: `ui-cell-editing`, `ui-entry-navigation`, `ui-ime-entry`, `ui-colors`, `ui-cell-format`, `ui-user-journeys`를 확장한다.
- 파일/계산: `ui-result-types`, `ui-recalculation`, `ui-dynamic-arrays`, `ui-array-races`, `ui-xlsx-preservation`, `ui-file-dialogs`, `ui-recovery`를 사용한다.
- 표/보고서: `ui-excel-tables`, `ui-table-structure`, `ui-cell-constraints`, `ui-excel-charts`, `ui-chart-parity`, `ui-pivot`, `ui-pivot-arrays`, `ui-print-settings`, `ui-print-objects`를 확장한다.
- 대용량: `ui-capacity`, `ui-large-spills`에 숫자만 있는 문서 외 혼합 자료와 취소·반복 작업 측정을 추가한다.
- Windows/Mac/Linux의 패키지 검사는 앱 동작 검증이다. Windows CI가 통과했다고 Microsoft Excel이 실행된 것으로 표시하지 않는다. 실제 IME·화면 읽기·네이티브 파일창은 별도 확인한다.

사용자 프로필·열린 파일·클립보드를 시험에 쓰지 않는다. 합성 문서와 격리 프로필을 사용하고, 클립보드는 자동 검사에서 격리/모의 처리한다. 실제 OS 교환은 별도 시험 환경에서 확인한다. 재현용 작은 자료와 요약만 Git에 남기고 대용량 생성물·중복 빌드는 정리한다.

### 성능 목표

아래 수치는 **새로 측정할 목표이며 현재 달성 수치가 아니다.** 같은 장비·전원 설정에서 워밍업 뒤 최소 5회 측정하고 중앙값·최댓값, 입력 이벤트 지연은 충분한 표본의 p95를 기록한다.

- 보통 문서의 선택·키 입력·메뉴 반응: p95 100ms 이내를 목표로 한다.
- 큰 문서의 단일 셀 편집·선택: p95 200ms 이내를 목표로 한다. 긴 전체 재계산은 분리한다.
- 긴 작업의 시작 상태 표시: 250ms 이내, 취소 요청 확인: 500ms 이내를 목표로 한다. 실제 종료·자원 반환 시간도 별도로 측정한다.
- 100만 셀 열기·저장 시간과 최대 RSS: 현행 기준값부터 재측정한다. 같은 자료에서 20% 이상 악화하면 원인을 설명하고 개선 또는 허용 근거를 남긴다.
- 20회 열기·편집·저장·닫기 반복에서 메모리가 지속 증가하는지 확인한다. 복구 자료와 원본 파일은 오류·취소 후에도 손상되지 않아야 한다.

## 7. 실행 순서와 단계별 산출물

시간은 현재 정보로 잡은 작업량 추정이다. 실제 Excel 접근 대기와 복잡한 미지원 개체 전체 구현은 포함하지 않는다. 일정 약속이나 자동 작업 시작 요청으로 해석하지 않는다.

| 단계 | 범위 | 예상 작업량 | 단계 종료 산출물 |
|---|---|---:|---|
| 0 | 비교 자료·상태표·성능 기준선, 기존 테스트 연결 | 4–8시간 | 21개 시나리오의 준비 상태·기대값 출처·미검증 목록 |
| 1 | P0-A: 계산 경계 사례, 보존 진단, 피벗 충돌 방어 | 16–28시간 | 작은 재현 파일, 실패→수정 결과, 저장 보호와 지원 상태 표시 |
| 2 | P0-B: 편집·선택·복사·실행 취소 | 12–20시간 | 상태별 명령표, 관련 UI 회귀, 실제 IME 검증 또는 대기 명시 |
| 3 | P1-A: 표 확장·유효성 작성·색조/데이터 막대 | 20–32시간 | 표 업무 시나리오와 규칙 편집·왕복 검사 |
| 4 | P1-B: 차트 자료 미리 보기·계열 편집·빈값 정책 | 16–28시간 | 18개 기존 조합 회귀, 새 설정과 XLSX/PDF 비교 |
| 5 | P1-C: 기본 피벗 역변환·원본/서식 유지·찾기 | 24–40시간 | 외부 수정 보존, 반복 보고서 시나리오 |
| 6 | P1-D 및 통합 검수: 성능·인쇄·접근성 | 16–28시간 | 성능 보고서, 패키지 검사, 미해결 제한 목록 |

첫 개발 묶음은 **0–2단계, 약 32–56시간**이다. 전체 0–6단계는 **약 108–184시간**의 초기 추정이며, 0단계의 재현 결과에 따라 다시 산정한다. 심각한 결함이 나오면 새 기능 범위를 줄여 먼저 해결한다. 성능·보존·접근성의 기본 원칙은 마지막 단계까지 미루지 않고 각 기능 개발에 적용한다.

1단계의 보존 정책을 먼저 정해야 가져온 차트와 피벗을 안전하게 편집할 수 있다. 표 확장은 계산 열·필터·참조 갱신을 함께 끝내고 차트·피벗 원본 추적으로 이어간다. 한 작업 묶음마다 재현 → 수정 → 같은 사례 재검증 → 관련 회귀 → Git 반영 순서로 진행한다.

## 8. 공통 완료 조건과 후순위

- [ ] 새 결함은 수정 전 실패와 수정 후 동일 시나리오의 통과 기록이 있다.
- [ ] 적용/취소·실행 취소/다시 실행·저장/재열기가 연결된다. 실패·취소가 문서 일부만 바꾸지 않는다.
- [ ] 계산 가능·캐시 표시·원본 보존·미지원이 화면과 문서에서 같은 뜻이다.
- [ ] 지원한다고 선언한 파일은 관련 개체·관계·종류를 유지하며, Excel 검증 여부를 구분한다.
- [ ] 기존 파일 열기/폴더 기억, 빈 문서 시작, 명시적 복구, 업데이트 저장·종료 보호가 유지된다.
- [ ] 변경 범위에 맞는 단위·실제 앱·플랫폼 검사를 통과하고 남은 제한을 기록한다.
- [ ] 버그 수정과 기능 추가 단위로 커밋·푸시한다. 공개 배포와 리토스 갱신은 별도의 **“배포해줘”** 요청 때 진행하고 기존 공유 링크를 유지한다.

**후순위:** LAMBDA/MAP/REDUCE 전체, Power Query·외부 데이터 새로 고침, Data Model/OLAP, 슬라이서, 공동 편집, 독립 VBA 실행기, 고급 ChartEx/3D 효과, 전체 Excel UI 복제. 수요와 재현 파일을 확보한 뒤 별도 계획으로 다룬다. 기존 XLSM의 Excel 연결 경로를 독립 VBA 지원처럼 표시하지 않는다.

전체 TypeScript 전환은 이 계획의 선행 조건이 아니다. 변경하는 계산 결과·작업 스레드 메시지·표/차트 모델의 계약부터 JSDoc 또는 타입 검사로 명확히 하고, `main.mjs`의 관련 책임을 필요할 때 분리한다. 큰 구조 변경과 동작 변경을 한 번에 섞지 않는다.
