# 사용자 시나리오 검수 — 0.7.20 개발판

검수일: 2026-10-23. 공개 배포 버전은 0.7.17이며 이 변경은 개발판에 반영합니다.

## 발견하고 수정한 문제

| 재현 순서 | 수정 전 | 원인과 수정 |
| --- | --- | --- |
| A1을 잘라내기 → 새 문서/다른 파일 열기 → 다른 셀에 붙여넣기 | 새 문서의 A1까지 삭제되거나 같은 위치 붙여넣기가 무시됨 | 기본 시트 ID가 문서마다 반복되는데 클립보드는 시트 ID만 비교함. 문서 식별자를 함께 기록하고 문서가 바뀌면 잘라내기를 일반 복사로 전환 |
| A1=`keep`, A2=`move` → A2 잘라내기 → 1행 삽입 → B1 붙여넣기 | 옮겨진 A2의 `keep`가 삭제됨 | 이전 주소를 계속 삭제 대상으로 사용함. 원본 셀 집합 교체 또는 원본 범위 수정 시 이동을 취소하고 복사본 유지. 원본에 새로 입력한 값도 보존 |
| 저장 작업이 끝나기 전에 OS 메뉴 실행 취소/붙여넣기 | 내보내는 데이터와 화면 상태가 달라짐 | 화면 가림막만 있고 네이티브 메뉴·paste 이벤트 경로는 열려 있었음. 작업 중 명령·단축키·붙여넣기를 차단하고 완료 후 정상 편집 재개 |

같은 문서의 다른 시트로 잘라내기/붙여넣기는 계속 실제 이동으로 동작합니다. 문서를 바꾸거나 원본이 바뀐 뒤에는 복사 시점의 내용을 붙이고, 현재 원본 셀은 삭제하지 않습니다. 클립보드가 큰 원본 문서를 계속 메모리에 붙잡지 않도록 셀 집합은 약한 참조로 비교합니다.

## 실제 화면을 사용하는 새 회귀 시나리오

`tests/ui-user-journeys.mjs`는 별도 사용자 프로필에서 Electron 앱을 실행합니다. 메뉴·키보드·시트 탭·이름 상자로 조작하며, 데이터 모델을 직접 고쳐 성공을 만드는 방식은 사용하지 않습니다. 파일 선택 창의 응답만 자동 지정하며 실제 내보내기·디스크 쓰기·열기 경로를 거칩니다.

1. 한글 품목·숫자·수식을 붙여넣어 정산표 작성.
2. 머리글 굵게, 테두리, 병합, 상대 참조 복사, 셀 삭제를 각각 실행 취소/다시 실행하고 문서 전체 비교.
3. 두 번째 시트에 다른 시트 참조 수식 작성.
4. 수식 입력을 끝내기 전에 저장해 마지막 입력 확정 여부 확인.
5. 앱 종료/재시작 후 값·수식·서식·병합 확인.
6. 실제 XLSX 파일과 앱 문서 파일을 다시 열어 수식 결과 12,900 및 보존 항목 확인.
7. 실행 취소 후 새 편집을 하면 이전 다시 실행 분기가 사라지는지 확인.
8. 새 문서·파일 열기·행 삽입·원본 수정 후 잘라내기와 정상 시트 간 이동 재검증.
9. 저장 중 네이티브 메뉴·단축키·붙여넣기·직접 입력을 시도하고 문서가 그대로인지 확인.
10. 저장 완료 후 편집/실행 취소가 다시 동작하는지 확인.

## 대용량 및 기존 기능 검사

기존 UI 회귀 검사는 직접 편집/F2/Enter/Tab/방향키, 한글 조합, 숫자 자동 채우기, 함수, 행·열 크기, 숨김·틀 고정, 조건부 서식, 숫자·색 필터, 피벗, 시트 수명주기, 차트, 셀 서식, 외부 표 교환, 파일 폴더와 자동 복구를 포함합니다.

`tests/ui-capacity.mjs`는 100열×10,000행과 1열×1,000,000행 문서를 각각 검사합니다. 100만 셀 CSV 입력, 전체 범위 합계, 한도 초과 편집 거부, 65회 편집과 실행 취소 기록 제한, 증분 복구, 정렬·필터, 앱 재시작, XLSX 저장/재열기를 확인합니다. 측정 시간에는 현재 기기 성능과 당시 부하가 영향을 줍니다.

### Mac 실측 결과

- 단위 검사: 176개 중 175개 통과, Windows 전용 1개 제외.
- 소스 실행 UI 검사: 기존 25개 실행(100만 셀 두 배치 포함)과 새 사용자 시나리오 1개, 합계 26개 모두 통과. 새 시나리오 안의 18개 검증 항목 모두 통과.
- 0.7.20 Mac arm64 패키지: 사용자 시나리오, 표 클립보드, 파일 폴더, 자동 복구, 100만 셀 두 배치 등 6개 실행 모두 통과.
- 서명 무결성 검사와 패키지 안의 런타임 소스·빌드 결과 11개 파일의 일치를 확인. 설치한 앱도 같은 ASAR SHA-256(`c8e14ec99e68e6253b4c94c7e2818474105482c485d8d30b7b7b07cebbc5d026`)인지 확인.
- 기존 앱·사용자 프로필 백업 후 로컬 앱을 업데이트하고 기존 문서 복구 화면 확인. 테스트용 프로필과 패키징 작업 폴더 제거.

### 운영체제별 자동 검사

수정 커밋 `9345fd8`과 검사 보완 커밋 `ee14880`에 대해 [macOS·Windows·Ubuntu 전체 회귀 검사](https://github.com/beaur8-prog/sheet-studio/actions/runs/39805310761)가 최종 성공했습니다.

| 실행 환경 | 단위 검사 | Electron UI 검사 |
| --- | --- | --- |
| Windows | 176 통과, 제외 없음 | 25개 실행 모두 통과 |
| macOS | 175 통과, Windows 전용 1개 제외 | 25개 실행 모두 통과 |

세 환경 모두 새 사용자 시나리오의 18개 항목과 100만 셀 두 배치의 XLSX 왕복·프로세스 재시작을 완료했습니다. 운영체제별 CI는 소스에서 실행하는 Electron 앱 검사이며, 설치 패키지 자체 검사는 위의 Mac arm64 결과입니다. Windows CI의 세로형 100만 셀 XLSX 재열기는 약 27.1초였습니다.

[첫 실행](https://github.com/beaur8-prog/sheet-studio/actions/runs/39803421885)에서는 새 사용자 시나리오가 세 운영체제에서 통과했지만 기존 틀 고정 좌표 검사가 Windows·macOS에서 실패했습니다. 해당 검사는 화면 갱신을 기다리지 않고 이전 절대 좌표를 비교했습니다. 작업·렌더링 완료를 기다리고 실제 고정 열의 오른쪽 경계와 비교하도록 보완했습니다. 최종 실행에서 세 환경 모두 고정 열 오른쪽 경계와 이동한 셀 왼쪽 좌표가 각각 170px로 일치했고 나머지 검사까지 통과했습니다.

## 검증 범위

이 검수의 XLSX 왕복은 Sheet Studio가 저장한 실제 파일을 다시 읽는 검사입니다. Microsoft Excel이나 Windows VBA의 실제 실행 검증은 포함하지 않습니다. 자동화된 한글 조합 검사는 실제 사용자의 입력기별 수동 검수를 완전히 대체하지 않습니다.
