# 분석 범위

Sheet Studio는 기존 Excel의 화면 구조와 핵심 작업 흐름을 참고한 독립 구현입니다. Microsoft Excel 원본 소스의 복원 또는 전체 기능의 동등성을 주장하지 않습니다.

## 정적 분석

대상은 설치된 Excel 16.0.19127.20860, x64 PE였습니다. 대상 SHA-256은 `f911ab2f68aca736aae96c437468f09a5884af2d95f6a4b0d97214973285d448`입니다.

- REA MCP로 PE 리소스 1,228개, icon group 27개, UIFILE 15개를 확인했습니다.
- PE import 목록에는 일반 import 536개와 delay import 7,378개가 있었습니다. Office 공통 UI 및 차트 등 외부 네이티브 모듈에 대한 의존성이 확인됐습니다.
- Windows 네이티브 TYPELIB API로 COM 타입 1,036개를 열거했습니다. 계산, 셀 범위, 시트, 저장 및 내보내기 인터페이스 선언을 확인했습니다. 메타데이터 선언은 함수 구현과 구분했습니다.
- REA의 Ghidra 전체 자동 분석은 도구 호출 제한 시간을 초과했습니다. 기존 Ghidra로 범위를 좁혀 `GetDMCLRRuntime`과 `MdCallBack12`의 기계어 및 의사코드를 확인했습니다. 전체 수식 계산 엔진이나 파일 저장 엔진을 복구하지 않았습니다.

원본 실행 파일은 수정하지 않았습니다. 대상의 실행 파일, 추출 리소스, 디컴파일 결과, 상세 원시 증거는 이 공개 저장소에 포함하지 않습니다.

## 화면 관찰

실행 중인 한국어 Excel 창의 스크린샷과 접근성 트리에서 리본, 이름 상자, 수식 입력줄, 워크시트 격자, 시트 탭 및 상태 표시줄 구조를 확인했습니다. 기본 화면은 검은색/회색 도구 모음과 흰색 격자를 사용했습니다.

기존 사용자 통합 문서는 편집하지 않았으며, 앱 예제에는 별도로 만든 가상 데이터를 사용했습니다. Microsoft 아이콘이나 추출 UI 리소스를 복사하지 않고 별도 아이콘과 화면 코드를 작성했습니다.

## 검증 해석

앱의 계산 엔진·파일 왕복·UI 테스트는 구현한 동작의 검증입니다. 원본 Excel과 모든 함수·부동소수점 경계 조건·저장 형식을 전수 비교한 결과는 아닙니다. 구현 범위와 미지원 기능은 README와 IO-NOTES.md에 설명합니다.

## 0.7.0 추가 비교

REA MCP `inspect_pe_resources`로 동일 Excel 실행 파일(위 SHA-256)의 2,473개 엔트리와 1,228개 리소스를 재확인했습니다. 증거 ID: `ev_45c7f5230e6fc8d5902bbe169ddb6e7da029f5361da6a0274b5243887cc843fa`. 기존 네이티브 TYPELIB 분석 자료도 참조했습니다. 이번 리소스 검사는 정적 식별이며 기능 알고리즘 분석은 아닙니다.

Windows 접근성 트리에서 `ConditionalFormattingMenu`, `FormatCellsMenu`, `PasteMenu_Dropdown`, `ViewFreezePanesGallery`와 틀 고정·첫 행 고정·첫 열 고정 메뉴를 확인했습니다. 사용자 문서의 값을 수정하지 않고 메뉴만 관찰한 뒤 홈 탭으로 복귀했습니다. 기능 동작은 별도 합성 데이터와 새 Excel COM 인스턴스에서 비교했습니다. 실제 파일 비교를 통해 조건부 채우기 색, 중지 우선순위, 빈 숨김 행, 네이티브 수식 규칙 기록을 보완했습니다. 상세 항목은 [워크시트 안내](WORKSHEET.md)를 참조하세요.
